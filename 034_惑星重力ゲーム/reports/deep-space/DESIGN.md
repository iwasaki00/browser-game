# v1.8.0 — DEEP SPACE 仕様

## 導入と領域

開始時の対象プロジェクトはv1.7.0で、HOMEWARD EXPERIENCE・テスト・レポートが存在した。対象ディレクトリの未コミット差分はなかった。公開・push・デプロイは行わない。

既存のSector09（3750×5000）を拡大せず、そのクリア後に独立した `homeward-deep` を解放する。旧01〜09の座標・目的地・到達条件・チェックポイントは維持する。遠方領域は **12000×10000**、面積はSector09の6.4倍。出発位置は **(600,9000)**、帰還中継点は **(10500,1000)**、到達半径120。旧領域での成功は地球帰還の完結を意味しない。

惑星は3個、重力異常1個、固定残骸群1組、構造物1個に留め、空白領域を残す。新領域の飛行時間上限180秒、予測上限120秒。予測の表示間引き・時間上限は既存のまま。未予測区間は「この先は未予測」と表示する。固定刻み1/120秒、1〜100倍、連続衝突・危険領域判定を維持。画面外でも力・判定を省略しない。

カメラは新領域だけ最小倍率0.025、最大3。375px幅の全体表示は約0.03倍。旧領域は最小0.1に復帰する。FIXED/FOLLOW/OVERVIEW/CINEMATIC、パン・ピンチ、ミニマップを再利用する。

## 探索対象

全対象の到達半径は100。検出・調査はロケットの実物理ステップ線分と円の交差で判定する。調査条件は近距離通過。対象自体へ衝突させる必要はない。検出後は目的地に選び、寄港・再発射も可能。

状態はUNKNOWN→DETECTED→INVESTIGATED。入口の星図に載るDS01だけは初期DETECTED、他はUNKNOWN。未検出地点は一覧・名称・座標を出さない。DETECTEDは「未解析の反応 DSxx」、調査後に正式名称と情報を表示する。危険な天体・引力中心・残骸本体は隠さない。

DS02の引力中心は(5000,6000)、作用範囲1400、強さ120。**既存unknown encounterの重力式をそのまま使用**する。中心は既存の接触失敗判定を持つ。調査点を中心から約361離す。残骸本体は(6300,2600)、3個、速度0。調査点とは200離す。構造物は既存station描画・非衝突挙動を利用。

通信は既存の1枚の通知に集約。閉じても情報は消えず、目的地・航海日誌から確認できる。検出・調査・情報解放で自動停止やワープを行わない。マップを開いている間は従来どおりゲームが一時停止する。

## 航路方針と操作

- DIRECT RETURN：帰還中継点を目標にする。
- SAFE VOYAGE：検出済みなら空白域側のDS03を候補とし、なければ帰還中継点を選ぶ。危険の位置をマップで確認するための計画補助で、安全の保証・自動回避はしない。
- DEEP EXPLORATION：検出済みの未調査対象から現在地に近い地点を候補にする。該当がなければ帰還中継点。

いつでも別の方針・目的地を選べる。現在位置・目標座標・距離・寄港地・調査状態をマップに表示。航行中は目標のgoalだけを置換し、現在位置・速度・経過時間を変更しない。発射前の目的地切替は既存Sector09と同じく新たな出発設定を用意するが、発射自体はプレイヤーが行う。

新領域のANGLEスライダーは0.01°刻み、±ボタンは0.1°。旧領域の±1°操作は変更しない。DS01調査後に、解読した参考航路を表示する。自動入力・自動発射はせず、惑星を動かしたら予測で再確認する。

寄港は既存物理エンジンの選択目標への到達結果だけで確定する。次の発射は寄港地点の外側の安全な位置から始める。既存の寄港・再発射と同じ独立した次の航行であり、飛行途中の強制移動はしない。LIVE GRAVITYで移動した惑星座標も寄港時に保持し、安全な出航点を再計算する。

## 物語

探査機・構造物・残骸は、消失した調査船と関係するかもしれない古い観測網を示す。救難信号は同じ識別列の一部、時間観測点は72時間の矛盾を記録する。現実の日付から72時間を計算せず、既存の設定を継続する。

DS02・DS03・DS06の情報がそろうと `final-voyage-chart` を一度だけ取得し、次の帰還航路候補を整理する。未来の本船・時間移動・調査船の所在を確定しない。旧CLUE-01〜09や既存の物語選択を変更しない。v1.9.0でこの観測網と帰還航路を結び付ける。

## 保存と段階保存

localStorageキー `orbit-maker.homeward.v1` とversion=1を維持し、任意項目 `deep` を追加する。旧データにない場合は安全な初期値を使い、読み込みだけでは保存を書き換えない。

`deep` は selected / checkpoint / visited / targets / rewards / choices / records / planets / elapsed / completed を持つ。対象ごとに状態・初回検出日時・調査完了日時・獲得情報・発見/調査航行IDを保持する。方針履歴は直近100件。情報報酬は集合として重複を防ぎ、初回の記録参照を再訪で置き換えない。旧voyage・frontier・echoes・CLUE・CLASSIC用キーには干渉しない。

重要記録は既存の別DB `orbit-maker-homeward-archive` version1 / flightsストアを使用する。通常ギャラリーとは別で、整理の対象にならない。既存のimmutableな `sector:` / `dock:` / `discovery:` / `story:` キーを維持する。

新しい `partial:<flightId>` キーだけを単調に更新する。HOMEWARD航行の開始、発見後、約30航行秒ごと、終了に保存。1フレーム中の多数の発見は集約し、1本の非同期書き込みキューで直列化する。同じ航行の待機中スナップショットは最新へ置換。最終版を古い途中版で上書きしない。最終版には通常記録と同じ物語・目的地情報を含める。

途中版は `partial:true, result:'partial', reason:'in-flight'`、記録形式自体はv1のまま。記録点は最大4096、既存の曲率を考慮した間引きを再利用。再生では物理計算をやり直さず、PARTIAL / 飛行途中と表示する。画像出力もFAILと誤表示しない。

段階保存は最大30航行分。上限・容量不足で既存記録を削除せず、新しい段階保存を拒否して通知する。各保存操作は最大3回、失敗間隔50ms・100msで再試行し、その後は航行を続ける。新しい段階保存の成功を確認してから日誌へ参照を登録する。保存先が利用できなくてもゲームは続けられる。

再読み込みは最後の寄港地点から再開する。途中記録は鑑賞用の安全な段階保存であり、位置・速度・未処理の入力を含む完全な飛行再開データではない。サイトデータ消去・端末のストレージ消去から記録を保護することはできない。
