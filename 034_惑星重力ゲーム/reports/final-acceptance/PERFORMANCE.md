# PC Chrome 性能検証 — v2.0.0-rc.1

## 条件

Windows 10.0.26300、Core i7-1355U、RAM約16GB、headless Chrome 156.0.8078.76。モバイル相当375×667・DPR3、必要箇所でCDPセーフエリア59/34px。PC版CINEMATICは1366×768。独立ブラウザコンテキストで試験し、各性能試験を直列実行した。PCの他アプリやOS全体の負荷までは固定していない。

FPSはrAFの回数／実時間。CPU欄はChrome rendererのTaskDuration／実時間であり、PC全体のCPU・GPU使用率ではない。ヒープは強制GC後のJavaScriptヒープで、プロセス全メモリやGPUメモリではない。仮想時計で短縮した進行試験の値は性能測定に使わない。

## 3分間SCAN反復と前回比較

同じ375×667・DPR3・DEEP発射前状態で6回×30秒。各回でサーチ・対象切替・カメラ移動／復元・SCAN開閉を行う。メニューで一時停止してGC・DOM採取を行い、その時間をFPS区間から除外する。結果は [endurance.json](endurance.json)。前回原データは [v1.9.4](../space-scanner/endurance.json)。

|DOMノード|1628→1631、2回目以降横ばい|1628→1631、2回目以降横ばい|
|イベントリスナー|171→169、その後横ばい|171→169、その後横ばい|

操作・発射ボタン・例外・メモリ増加上限の判定はPASS。これは前回より高速、または同等のFPSという意味ではない。今回のFPSは前回を下回ったため、性能の観察事項として残す。renderer TaskDuration比率は約95.5〜97.1%だった。UI操作は完了し、ゲーム実行時JavaScriptの変更はないが、PCの負荷が固定されていないため原因を断定しない。

今回の10秒SCAN ON区間では前回の52.83FPSより低い47.61FPSだった。数値の差を隠さず残す。ゲーム実行時のJavaScriptを変更していないため、この単一測定から候補版のコード変更による回帰や改善とは断定しない。100倍・SCAN併用は負荷の高い条件として実機受入で重点確認する。

## 限界

- 2〜3分の各試験で上限を超える持続的増加を検出しないことと、長時間のメモリリーク不存在は同義ではない。
- モバイル相当CINEMATICは60秒の再スタート時にGC後ヒープが約15.59MiBまで一時増加し、70秒で約7.84MiBへ戻った。終点差だけをもって全区間一定とは扱わない。
- 100倍の短区間では描画FPSが低下する。現行の物理処理予算・繰越処理を維持し、見た目のFPS向上のための物理省略は行わない。
- iPhoneのFPS・発熱・音声・OS共有・10〜15分の操作感は未確認。PC結果を実機性能として扱わない。
