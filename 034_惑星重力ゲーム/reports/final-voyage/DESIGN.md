# v1.9.0 — FINAL VOYAGE 仕様

## 構造と既存機能の保護

v1.8.0の未コミット実装を基盤に、DEEP SPACEの帰還中継点への到達後、`homeward-final` を宇宙マップから解放する。旧Sector01〜09とDEEP SPACEは変更しない。最終宙域は独立した進行・寄港状態を持ち、DEEP SPACEの12000×10000ワールド、惑星3個、引力異常、残骸群、構造物の配置を再利用する。入口は(10500,1200)。

新しい判断・通信・結末は物理処理の外側で扱う。発射、ANGLE/THRUST、スリングショット、LIVE GRAVITY、予測、固定刻み1/120秒、1〜100倍、連続衝突判定は既存処理を使用する。章や判断による自動操縦、速度補正、飛行途中のワープは行わない。

## 物語の整理

観測網は未来の予測器ではなく、時空異常を通る船の航行記録を異なる時間軸へ転送する仕組みだった。過去の台帳・受信された記録の古さと、通信に含まれる72時間先の発信時刻は、同一の時間基準に並べられない。既存の「記録に矛盾がある」という調査段階の文章は変更しない。

消失した調査船イサリの記録には、本船ヒナギが別の航路を選んだ場合の記録が重なった可能性がある。転送の仕組みは中枢調査で判明するが、イサリの乗員が本船と同一だったとは断定しない。未来は固定されず、帰還・救難・真相調査・異常調査・探索継続の判断がそれぞれの結末を作る。

実際の日付から未来の時刻を生成しない。72時間は既存設定の固定した差であり、取得日時は通常の保存日時として別に管理する。

## 5章

| 章 | 表示・進行 |
|---|---|
| 01 THE LAST SIGNAL | 最終章へ入ると短い最後の通信を日誌へ登録 |
| 02 THE OBSERVATION NETWORK | 観測網の反応を提示。中枢への実到達で転送機構の通信を解放 |
| 03 THE CHOICE | 最終判断を選ぶ。履歴を残し、選び直し可能 |
| 04 THE FINAL APPROACH | 自分で発射。救難・調査・最終目的地への複数航行が可能 |
| 05 HOME | 条件に合う目的地への実到達後、結末を表示・保存 |

通信は短い通知とマップ内の再確認欄、航海日誌に表示する。通知を閉じても記録を失わない。飛行中に目的地や判断を変えても位置・速度・経過時間を変更しない。マップを開いている間の一時停止は従来仕様どおり。物語通知そのものによる自動停止はない。

既存DEEP側の座標・名称・条件はそのまま。最終宙域での意味を別データとして定義する。異常の危険中心は既存の(5000,6000)、作用範囲1400。通過地点の成功は危険中心への衝突を意味しない。境界の外側を実際に航行し、選択した調査点へ到達する必要がある。

寄港後の次の航行は既存の安全な出航位置計算を再利用する。新しい北側中継点では惑星・危険本体との距離とワールド境界を確認する。同じ寄港地点を選んだだけでは再取得しない。別の航路で再出航してから、再度目的地へ到達する。

## 明示的な結末判定

全結末に、既存物理の `status=cleared`、選択目標と `state.target` / `state.goal.id` の一致、到達座標が目標円内であることを要求する。失敗・単なる判断ボタンの選択・別目的地への到達では付与しない。

| 結末 | 最終判断 | 実到達先 | 追加条件 |
|---|---|---|---|
| END-01 HOMEWARD | home | earth | なし。手掛かりを集めず帰還できる |
| END-02 RESCUE | rescue | earth | 最終救難地点への実到達、または旧Sector09での救助済み寄港記録 |
| END-03 THE TRUTH | truth | earth | CLUE-01/02/03/06/07/09、DS02/03/06調査済みと `final-voyage-chart`、最終章の中枢への実到達 |
| END-04 THE OTHER SIDE | other | passage | 最終章の中枢への実到達 |
| END-05 ENDLESS VOYAGE | continue | observatory | なし。探索継続状態であり、他の結末を封鎖しない |

CLUE-04/05/08は既存の情報解放の過程で利用されるが、追加の収集条件として重ねて要求しない。`final-voyage-chart` は既存DEEPのDS02・DS03・DS06調査で得る。新しい不要な収集作業は加えない。

複数条件が揃っていても、最後に選んだ判断と実到達先だけを採用する。たとえば救難・真相条件が揃っていてもhomeで帰還すればEND-01。truthで帰還して必要情報が不足していれば、理由を表示して寄港状態にする。END-01へ自動で振り替えない。

rescueを選び未救助なら救難地点、truth/otherを選び中枢未調査なら中枢を最初の候補にする。これは目標選択だけで、発射入力や航行は自動化しない。候補を自分で変更できる。救難・中枢調査後は、地球や異常の通過地点を選び直して発射する。

## 演出とクリア後

結末ごとに色・タイトル・最終通信・短い本文を用意する。END-04では青紫の交差する光輪と、本船が送った声を観測する演出を使う。描画上の表現だけで、位置・時間・速度を変更しない。演出は短く、軽量モードでは光輪を減らす。

結末カードは即時に閉じる／スキップできる。到達済みだけ正式名称・内容・初回日時を一覧に表示する。未到達はIDと「未到達」のみ。再閲覧・初回重要航行のCINEMATIC再生を提供する。

END-01〜03は地球帰還を達成した進行として100%を記録する。END-04は最終章の別の結末として通過を記録するが、地球帰還済みにはしない。END-05は最終章のクリアを強制せず探索を続ける。どの結末の後も過去セクター、DEEP、最終章、FREE SPACEへ戻れる。過去の結末や手掛かりは削除しない。

## 保存・保護

HOMEWARDのキー `orbit-maker.homeward.v1` とversion=1を維持する。任意項目 `finalVoyage` を追加。旧保存に存在しない場合は未選択・結末0件として扱い、過去のCLUEや進行だけから結末を推定付与しない。読み込みだけでは保存を書き換えない。

主な追加項目：

- selected / checkpoint / planets / elapsed / visited
- decision / choices（直近100判断）
- chapters / communications（最大60件、最初の章・中枢解読・救難完了・結末通信を優先保持）
- rescueSaved / networkRead
- endings：ID、firstAt、lastAt、初回重要航行flightId
- records：各目的地の初回寄港航行ID

IndexedDBは既存専用DB `orbit-maker-homeward-archive` version1を維持する。追加キーは `ending:END-0x:first` と `final:dock:<destination>:first`。既存のatomicな初回保存と最大3回の再試行を使用し、既存記録を上書き・自動削除しない。

結末別の保護記録は、その結末が成立した最終航行区間。救難・中枢への前の区間も初回寄港記録として別に保護し、日誌から再生できる。全区間を一本へ結合して再計算するものではない。記録はv1形式を維持し、finalVoyage / finalDecision / endingId / storyEvents / destinations等の任意メタデータを加える。

通常ギャラリーの件数整理は専用DBへ干渉しない。既存の段階保存（最大30航行・最大4096点・最大3回再試行）も継続する。容量不足時は通知し、航行・結末取得のメモリ上の処理は継続する。IndexedDB保存に成功した場合だけ保護記録への参照を登録する。保存できたと偽らない。サイトデータ消去からの保護はできない。
