## 2. 再生モード

| モード | 動作 |
|---|---|
| 通常再生 | 従来のワールド全体を画面に収める構図。既定値 |
| FOLLOW | ロケットを追従。通常／OVERVIEWから入る場合は1倍のカメラ倍率で開始 |
| CINEMATIC | 既存のCinematicCameraを使い、飛行状況で位置と倍率を自動調整 |
| OVERVIEW | ワールドと記録された移動範囲を収める全体表示 |
| 手動カメラ | ドラッグ・ピンチ・＋／−操作で移行。自動追従を止め、自由に表示位置を操作 |

一覧の「再生カメラ」で**記録を開く前**に選択できます。再生画面左上でも、再生中・一時停止中に変更できます。切替で再生時刻を巻き戻しません。自動へ戻す場合はFOLLOWまたはCINEMATICを選びます。

従来の「軌道全体」は、航跡を最後まで表示する独立した設定として維持。「全体」カメラボタンはOVERVIEWへ切り替えます。

## 3. CINEMATIC演出

- **出航前**：出発点・目的地を含む全体構図で0.65秒待機。「出航準備」を小さく表示。
- **発射**：ロケット付近へ滑らかに寄り、追従を開始。
- **通常／高速航行**：記録から推定した進行方向・速度を共通カメラへ渡し、前方の余白と画角を調整。
- **惑星接近・スイングバイ**：再生時刻の惑星位置を使用。接近から離脱まで同じ惑星を注目対象として保持。
- **ゴール接近**：ロケットとゲートを含む構図を優先。
- **到着**：共通カメラの到着ズームと0.85秒の余韻。CLEAR／FAILは保存された結果を表示。

待機・余韻は表示時間基準で、0.5〜4倍の速度設定では短縮しません。一時停止すると待機時間とカメラ補間も停止します。失敗記録も終了時に短い余韻を設けます。

場面判定・距離のヒステリシス・ズーム上下限0.1〜3.0倍・ロケットを画面内に保つ処理は `cinematic-camera.js` を再利用。専用の重力計算やステージIDによる固定演出は追加していません。

## 4. 記録形式と互換性

保存形式は既存の **record version 1**、IndexedDB version 1のままです。新しい必須フィールド・マイグレーションはありません。

```text
保存点: [飛行時刻, ロケットX, ロケットY, 惑星1X, 惑星1Y, ...]
表示位置: 既存replayFrameの線形補間
推定速度: 隣接する保存点の位置差 / 時間差
```

終端では直前の有効な区間を使用。同時刻・単一点等で推定できなければ保存された発射速度、さらに欠けていればゼロ速度で安全に扱います。惑星の座標が欠ける場合は表示用状態で初期惑星位置を補います。これらは一時的な表示データで、元の記録へ書き戻しません。

保存された位置・惑星移動・時刻・結果をそのまま使い、物理エンジンで再計算しません。補間位置は従来と一致します。ただし、間引かれた点から求める速度は推定値です。実飛行時の厳密な速度やカメラ軌跡をそのまま復元するものではありません。

## 5. 再生操作と速度

| 操作 | 動作 |
|---|---|
| 再生／一時停止 | 再生位置とカメラを同時に開始・停止。途中から再開可能 |
| 最初から | 時刻0へ戻し、演出判定を初期化。CINEMATICでは出航待機から開始 |
| 位置スライダー | 一時停止して指定時刻へシーク。自動カメラの注目対象を初期化 |
| 再生速度 | 従来の0.5／1／2／4倍。変更で再生時刻は戻らない |
| 映像の1本指ドラッグ | 6 CSS px以上の移動で手動カメラへ。小さなタップでは切り替えない |
| 2本指 | 手動カメラへ切り替え、ピンチ・パン |
| ＋／− | 手動カメラでズーム |
| 全体 | OVERVIEWへ |
| カメラ選択 | 自動モードへ復帰。シーク後も現在の保存位置から利用可能 |

再生速度はゲームの航行速度1／2／5／10／50／100倍と独立しています。終了後に「再生」を押すと最初から。余韻の途中で一時停止・再開した場合は、終端位置から余韻を続けます。バックグラウンドでは一時停止し、復帰後の再生操作で続きます。

## 8. 既存機能への影響・残存課題

基準v1.0.3との差分で、物理エンジン、1/120秒の実行処理、航行倍率、軌道予測、Stage01〜20、HOMEWARD、進行保存、記録生成、IndexedDB保存、音声、通常飛行のカメラ処理が未変更であることを確認しました。保存形式と元の座標は維持しています。

既存の一覧、お気に入り、削除、画像保存・共有の処理は維持。再生カメラの新設定はこの画面内だけで、進行保存・記録へ追加していません。

残存課題はiPhoneの実際の操作感・視認性・持続負荷の確認です。推定速度は保存点の密度に依存するため、実飛行カメラと完全に同一の構図とは限りません。
