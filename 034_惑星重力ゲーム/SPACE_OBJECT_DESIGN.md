# 宇宙ギミックの拡張方針（v0.9.2）

今回の実装は画面・入力用の `Camera` のみ。隕石・彗星・UFO等は追加していない。

既存の `stage.planets`、惑星7種類、`physics.js`、固定刻み1/120秒、ステージ01〜20、保存形式は維持する。新オブジェクト導入時も、惑星を一斉に別形式へ移行させない。

推奨するステージ追加フィールド：

```js
objects: [{
  id: 'comet-01', kind: 'comet',
  transform: { position: {x: 800, y: 400}, rotation: 0 },
  motion: { model: 'linear', velocity: {x: -12, y: 3} },
  collider: { shape: 'circle', radius: 12, response: 'fail' },
  gravity: null,
  effect: { type: 'none' },
  render: { style: 'comet', layer: 20 },
}]
```

種類定義を別の設定データに置き、インスタンスはID・座標・個別設定を持つ。`world` は物理的なステージ境界、CameraはCSSピクセルへの表示変換とする。見えている範囲を失敗境界に使わない。ワームホールはリンク先ID、宇宙ステーションは到達領域など、種類別の設定を `effect` へ追加できる。

物理処理は純粋関数のステップ列に追加する：移動オブジェクトの位置更新 → 重力源の収集 → 既存ロケット積分 → 相対移動を考慮した連続衝突・領域通過 → 終了・特殊効果。型別の小さな処理表を使い、描画とゲームUIを呼び出さない。無オブジェクトの場合は既存処理をそのまま通す。乱数が必要ならステージのseedと固定ステップ番号から決定的に生成する。

予測は実飛行と同じステップ関数・初期スナップショットを使用し、ステップ数上限を維持する。描画だけ可視範囲で間引く。新しい移動体を記録再生する段階で、記録形式の明示的な新バージョンと旧v1読み込みアダプターを導入する。現在のギャラリー・PNG出力はCameraに依存させない。

Cameraは `toWorld` / `toScreen`、`zoomAt`、2点ジェスチャー、`fit` を提供する。将来 `fit` の対象境界へobjectsの描画範囲を加える。大ステージでは背景グリッド・星・オブジェクトを可視範囲で描画し、物理演算対象を描画カリングで削除しない。
