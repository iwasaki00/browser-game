# 宇宙ギミックの拡張方針（v0.9.2）

## v1.1.0での実装

惑星を移行せず、新物体を `stage.encounters` に分離した。インスタンスは `id / type / x / y / radius / speed / angleDeg / count / strength / tailMode / tailLength / tailWidth / reactionRadius / route / fixed` を持つ。x・yは初期アンカーで、移動位置はシミュレーション時刻から求める。

`encounters.js` が定義・移動・効果領域・編集制限、`encounter-render.js` が表示、`encounter-samples.js` が実験配置を担当する。ギミックがなければ従来の物理処理を通し、存在する場合だけ追加効果と相対移動の連続衝突を合成する。予測は同じステップを使う。

イベントは `{id, type, time}` として移動モデルから分離。現行はステーション発見と未知物体の反応で、UFO通信や補給・修理の追加時にはイベント内容を拡張できる。

記録の行配列を変更する必要がなかったため、全体のv1形式を維持。任意の `encounterVersion: 1`、`encounters`、`encounterEvents` を追加した。再生は保存したモデル・時刻から位置を求め、ロケットの物理を再実行しない。将来、互換性のない移動モデルを加える場合は `encounterVersion` と読み込み処理を併せて更新する。

以下の「未追加」「新バージョン導入」は初期設計当時の記述。

v0.9.3追記：`worlds.js` が物理ワールド寸法・飛行時間・予測時間を定義する。`flightLimits` はシミュレーションのスナップショットに引き継ぐ。Cameraの倍率基準は従来375×500の表示スケールで、HUGEの全体表示は0.1倍。可視範囲と物理境界は別。描画カリングを重力・衝突処理の除外条件にしない。記録は旧v1行配列を維持し、長時間の場合だけ間引き、終端とその直前を保存する。

今回の実装は画面・入力用の `Camera` のみ。隕石・彗星・UFO等は追加していない。

既存の `stage.planets`、惑星7種類、`physics.js`、固定刻み1/120秒、ステージ01〜20、保存形式は維持する。新オブジェクト導入時も、惑星を一斉に別形式へ移行させない。

推奨するステージ追加フィールド：

```js
objects: [{
  id: 'comet-01', kind: 'comet',
  transform: { position: {x: 800, y: 400}, rotation: 0 },
  motion: { model: 'linear', velocity: {x: -12, y: 3} },
  collider: { shape: 'circle', radius: 12, response: 'fail' },
  gravity: null,
  effect: { type: 'none' },
  render: { style: 'comet', layer: 20 },
}]
```

種類定義を別の設定データに置き、インスタンスはID・座標・個別設定を持つ。`world` は物理的なステージ境界、CameraはCSSピクセルへの表示変換とする。見えている範囲を失敗境界に使わない。ワームホールはリンク先ID、宇宙ステーションは到達領域など、種類別の設定を `effect` へ追加できる。

物理処理は純粋関数のステップ列に追加する：移動オブジェクトの位置更新 → 重力源の収集 → 既存ロケット積分 → 相対移動を考慮した連続衝突・領域通過 → 終了・特殊効果。型別の小さな処理表を使い、描画とゲームUIを呼び出さない。無オブジェクトの場合は既存処理をそのまま通す。乱数が必要ならステージのseedと固定ステップ番号から決定的に生成する。

予測は実飛行と同じステップ関数・初期スナップショットを使用し、ステップ数上限を維持する。描画だけ可視範囲で間引く。新しい移動体を記録再生する段階で、記録形式の明示的な新バージョンと旧v1読み込みアダプターを導入する。現在のギャラリー・PNG出力はCameraに依存させない。

Cameraは `toWorld` / `toScreen`、`zoomAt`、2点ジェスチャー、`fit` を提供する。将来 `fit` の対象境界へobjectsの描画範囲を加える。大ステージでは背景グリッド・星・オブジェクトを可視範囲で描画し、物理演算対象を描画カリングで削除しない。
