# テーマ収集と探索目標の連携

現行 Version **1.0.0-rc.1** の機能追加。バージョン番号は変更しない。

## 通常プレイ

「図鑑・記録」→「テーマ収集」→テーマを開く。未発見品は仮名称と共通シルエットで表示し、「探索ヒント」から条件を確認できる。「探索目標にする」で既存の目標1枠へ設定する。設定時にもヒントが開く。既存目標があれば置き換え、対象に「探索中」を表示する。発見済み品には設定ボタンを出さない。

テーマ欄の「探索目標を解除」、従来の目標一覧の解除、HUDの解除は同じ `setExplorationGoal` を利用する。従来の目標一覧で変更した場合もテーマ欄へ即時反映する。テーマの進捗と目標達成はともに既存 `discoveredTreasures` を参照する。テーマ独自の目標・保存データは作らない。

採取画面の既存HUDは、仮名称・推奨場所・短い採取手順を表示。開くとエリア解放条件、必須条件、おすすめ、目標変更・解除を表示する。閉じた状態では採取画面を圧迫しない。

## 登録と同時達成

「川底の工具」2/3で最後の未発見品を目標にする→回収して未洗浄保管→目標は未達成、テーマは2/3→既存の洗浄・図鑑登録→目標達成とテーマ3/3。

既存洗浄結果欄に「探索目標を達成」と「テーマ完成 — 川底の工具」を各1回表示する。2行が絵に重ならないよう、固定モーダルの結果欄だけを内容の高さに追従させる。再読み込み・重複回収・図鑑閲覧では通知しない。報酬や経済は変えない。

保存形式は `explorationGoal: {target, completed}` のまま。9件固定の達成履歴上限を対象リストの長さ（16件）へ変更し、全16件の保存復元・無効ID／重複ID拒否を確認する。旧9点の目標、完了履歴、図鑑、通貨は維持する。旧IDの並びを先頭に残して仮名称の番号も維持する。

## 最短の確認手順

対象フォルダで `npm.cmd run build`、`npm.cmd run build:debug`。`npm.cmd run preview:both` で表示される通常 `/dist/index.html`、DEBUG `/dist-debug/index.html` のURLを開く。終了はCtrl+C。

通常版：図鑑・記録→テーマ収集→未発見品の「探索ヒント」→「探索目標にする」。別の品で切替、「探索目標を解除」で解除。採取画面HUDを開き、目標変更・解除も確認できる。通常版は `?debug=1` でもデバッグ機能は使えない。

DEBUG版：

1. DEBUG LAB→お宝→テーマ収集の確認→テーマ選択→「残り1点の状態を作る」。**テスト用進行を置き換える操作なので確認ダイアログあり。通常セーブには触れない。**
2. 閉じる→図鑑・記録→テーマ収集→2/3のテーマを開く→未発見品を「探索目標にする」。ヒントと「探索中」を確認。
3. DEBUG LAB→お宝→「選んだ品を即回収」（最後の品が選択済み。B005／R026／G009）。図鑑を開いても2/3、目標は探索中のまま。
4. 洗浄→洗う。目標達成とテーマ完成の両方を確認。
5. 再読み込みして完成が維持されること、同じ品を再回収・洗浄しても達成表示が再発しないことを確認。

全300点の閲覧は正式登録ではない。静的DEBUG版のテーマ欄も未発見の実名・絵を伏せ、閲覧だけでは目標もテーマも進まない。46道具＋3設備、∞ FN、`finders-static-debug-v1` の保存分離を維持する。
