# Version 0.5.0 — AUTOMATION BALANCE

## 再現条件

npm.cmd run balance:automation。乱数5000〜5099の100シード。3分野×5構成＝1,500試行。A＝全分野manual、B＝砂浜semi、C＝川底semi、D＝河原semi、E＝全分野comboです。機械処理の関数は通常プレイと共通です。

採取済みの同一初期材料と固定個体で比較し、通常採取の所要時間・探索時間はこの処理比較に含めません。BはB101で採取した約69単位、RはR-Bの先頭12対象、Gは3地点からG101で採取した約64単位。手動とsemiは同じ基本道具構成。comboのみ明示した強力磁石/滑車、多段ふるい/砂鉄分離/バケツ/吸引瓶などを加えます。材料の追加抽選はありません。

操作時間はモデル定数：手動砂選別0.6秒、磁石選択0.5秒・引き0.75秒、砂利負荷1秒・揺らし0.2秒、精密回収0.45秒、洗浄1.4秒、材料登録0.6秒、設備開始0.4秒。砂・砂利のまとめて投入は1操作、川底は対象ごとに1操作。設備の待ち時間も所要時間に含めます。人間の実プレイ時間ではありません。

starvedは初期在庫のうち1袋/1対象だけ投入し、残りは在庫として保持。screenLimitedはG103の66.67単位/分の能力制限を再現する基準構成で、semiと同条件です。独立した性能向上の試験とは扱いません。G202を組み合わせると83.33単位/分へ上がります。B/Rのこの欄も基準条件の再現です。

## 工程能力と投資回収

B301は180砂単位/分、入力240・出力8。R301は基準93.33引き量/秒、R110の速度効果を実際に適用し、対象の重量/難易度で必要時間が増えます。G304は供給180、粒径66.67/83.33、比重は保存された負荷のrequiredから計算。袋単位の工程を直列に実行するため、全体の速度は単純な各工程の最小値より低くなります。精密回収と洗浄は手動です。

改善すると別の工程が残ります。砂の自動選別後は洗浄、川底は対象指定・道具能力、河原は粒径選別から精密回収が次の候補です。通常UIでは実在の待ち在庫と能力値に基づいて表示し、未計測はデータ不足とします。

**投資回収時間はデータ不足（JSONではnull）です。** 同じ固定材料を処理するだけでは設備価格に対応する追加FNは確定しません。設備稼働中に増やせる採取量・他分野収入・洗浄能力を継続計測せず、価格÷FN/分を投資回収と呼ぶことはしません。

## 8時間稼働

各分野8ゲーム時間、合計24時間。10秒刻みで2,880回、120秒ごとに通常の区画生成と採取/対象指定を行い、出力を手動で受け取り、16回JSON保存復元。これは時間を進める計算試験であり、実機を8時間放置した試験ではありません。

- B：履歴100件、進行中0件、保存235,204 bytes、二重支払なし=true、非表示中状態不変=true、復帰時加算0秒。
- R：履歴100件、進行中0件、保存333,518 bytes、二重支払なし=true、非表示中状態不変=true、復帰時加算0秒。
- G：履歴100件、進行中0件、保存554,015 bytes、二重支払なし=true、非表示中状態不変=true、復帰時加算0秒。

未受取品や残渣を履歴整理で消さず、完了した作業要約だけ最新100件に制限します。既存の回収UID台帳・収益/回収履歴は実際の回収数で増えるため、将来は互換を保った集計・圧縮を検討します。

## 証跡と次版
