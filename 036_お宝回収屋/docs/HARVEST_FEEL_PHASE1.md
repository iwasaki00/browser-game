# 採取操作の気持ちよさ改善 Phase 1

対象は既存 Version 1.0.0-rc.1。Version・採取量・処理速度・最大深度・体力消費・重量／距離／粒径／比重判定・報酬・保存形式・300画像を維持する。

## 実装前の調査

ソース調査後、変更前の静的DEBUG版をChrome 390×844で操作し、砂浜、強力磁石＋ロープ、ふるい、パンニング、吸引、スルースの6状況を確認した。画像・動画・モデル状態は `harvest-phase1/baseline/`。

| 分野 | 良い点 | 問題点 | 改善候補・優先度 |
|---|---|---|---|
| 砂浜 | 投影と逆投影が共通。20msの時間積分入力でイベント数によらない作業量。穴の縁・濃さ・層、道具の限界と速度は既に描画・表示される。砂粒は標準70／軽量20個で上限付き。 | 指上の道具アイコンと、時間積分が実際に処理した場所を区別しづらい。露出閾値を越えた瞬間は既存の光る印に切り替わるだけ。 | P1：実処理位置の短い接地痕。P1：初めて回収可能になった瞬間だけ反応。P2：砂粒増量は既存表示と重なるため不採用。 |
| 川底 | トング・フック・磁石・ロープは共通の距離、重量、障害物、磁性・吸着力判定を使う。ロープ先端とCanvas進捗バーは同じ進捗から描かれる。失敗理由は既に日本語表示。 | 引き寄せ中も対象の影が元の位置に残る。DOMの進捗文字は約250ms更新でCanvasより遅い。成功時の通常トーストが、小さい探索面を覆う。 | P1：対象・先端・進捗の同期。P1：成功を探索面内で短く示し、通常成功トーストで覆わない。P2：ロープ物理の追加は不要。 |
| 河原 | 採取地点の石数が在庫比率で減る。未分離粒は操作ボタンにならず、分離済み粒は最大12個のボタン。黄鉄鉱も金色に見せ、正体は洗浄まで確定表示しない。道具で回収操作回数が異なる。 | 選別1回の完了後も未処理在庫があれば砂が大きい表示へ戻る。保持操作で進む選別の砂表示は主に100ms更新。回収した微粒はすぐ消え、成功位置を追いづらい。 | P1：投入分の減少と終了後の残留表示を連続させる。P1：実回収時だけ消失位置に短い輪。既存の分離済み枠・大きい吸引ヒット領域は維持し、二重に足さない。 |

入力の1サンプルでは、pointerdownからモデル初回深度更新まで32.6msを観測した。動画記録ありの1回の値であり、画面の実表示遅延やiPhoneの値ではない。入力方式や掘削速度を変える根拠にはしない。

DEBUGバナー等がある縦画面では既存の探索面が縦に圧縮されることも確認した。今回は画面構成の全面変更をせず、同じ領域で比較する。

## 採用範囲

各分野で2件まで。新しい物理演算・採取システムは追加しない。

- 砂浜：実際の掘削サンプル位置への接地痕、実際に露出閾値を越えた品への一度だけの短い反応。
- 川底：回収中の匿名の影を先端と同じ座標へ移し、進捗文字も同期。通常成功は既存のガイドと短い局所反応へまとめ、失敗理由の表示は維持。
- 河原：投入分の表示を進捗に追従させ、完了時に未処理在庫を勝手に再投入したような見え方へ戻さない。粒の実回収成功時だけ短い反応。

不採用：砂粒の増量、深度・速度変更、ロープ物理、失敗メッセージの追加重複、未鑑定粒の正体を先取りする色分け、既存粒枠の二重表示、大きいUI刷新。

## 実装内容と制約

砂浜の接地痕は入力イベントの座標を先行表示せず、実際に掘削量が増えた時間積分サンプルの位置を使う。160msで消え、回収可能な露出へ初めて到達した個体には550msの輪と小さな菱形を出す。既に露出済みの個体や同じ個体には繰り返さない。画像や品名を先取りしない。

川底の匿名の影をロープ／道具先端と同じ投影座標へ移し、進捗文字を実際の回収処理と同期する。成功時だけ岸の550msの輪と既存ガイドを使い、通常成功トーストで探索面を覆わない。重量・距離・磁性・障害物による失敗理由は既存どおり表示する。投擲・巻取り・回収完了までの時間は変えない。

河原は操作中の投入分だけを描画フレームに合わせて減らし、選別完了時は小さな残留物として表示する。未処理の袋在庫を勝手に大きい砂表示へ戻さず、次の手動投入で改めて表示する。袋の数量は従来の在庫表示が正であり、この縮尺は在庫全体の質量を表すゲージではない。粒の回収が実際に成功した位置だけ450msの輪を表示する。粒径や比重、黄鉄鉱の正体、報酬の判定は変更しない。

追加Canvas反応は最大8個＋接地痕1個、河原の輪は常に1個。既存砂粒の標準70個／軽量20個という上限は維持する。`prefers-reduced-motion`では追加の拡大・移動を静かな印に置き換え、砂粒も出さない。既存の演出OFF設定では追加表示もしない。必要な操作領域だけの既存タッチ対策を維持し、ページズームは制限しない。

モーダルで覆われた探索Canvasと画面外のCanvasは描画を停止する。河原の選別台では操作中の砂のtransformだけを追従更新し、粒ボタン等の全面更新は既存の100ms間隔を維持する。Canvas描画から川底の進行計算を分離し、モーダルを開いても従来の回収時計が変わらないようにする。非表示時は接地痕・輪・砂粒を消し、既存のゲーム時計・保存処理を利用する。保存する演出状態は追加しない。

## DEBUG LABの比較方法

静的デバッグ版を開始 → DEBUG LAB → シナリオ →「採取操作の比較」。砂浜1、川底6、河原5の計12状況を選べる。

1. 状況を選び「同じ初期状態を再現」を押し、テスト進行の置換を確認する。
2. 追加フィードバックをOFFにし「採取へ」。従来の表示で操作する。
3. LABへ戻り、同じ状況を再現してONにする。同じセッション内では個体IDを含む初期状態も同じ。
4. 「描画診断を表示」で反応数・上限・描画／省略フレーム・砂の更新回数を見る。数値を再計測する場合は診断をリセットする。

スイッチはメモリ上の表示設定だけで、セーブへ保存しない。共通の操作カウンターにも加算しない。通常版には比較UI・診断APIを含めない。静的版は起動時から専用保存領域を使用し、通常セーブを読み書きしない。46道具＋3設備、∞ FN、全300点閲覧、即回収、発見演出プレビューも維持する。

## 起動とiPhoneでの最短確認

対象フォルダーで`npm.cmd run preview:both`を実行し、表示された通常版／デバッグ版URLを開く。必要なら`npm.cmd run build`、`npm.cmd run build:debug`で再生成する。確認サーバーはローカル専用で、公開やアップロードは不要。

iPhoneからは同じWi-FiでPCのLANアドレスを使う。`preview:both`はPC内専用なので、LAN確認時は別々のPowerShellで通常版`npm.cmd run preview -- --port 4173 --strictPort`、デバッグ版`npm.cmd run preview -- --outDir dist-debug --port 4174 --strictPort`を実行する。既存のpreview設定で`0.0.0.0`へ待ち受ける。`ipconfig`のWi-Fi IPv4を使い、通常版`http://PCのIPv4:4173/`、デバッグ版`http://PCのIPv4:4174/`を入力する。確認後は両PowerShellでCtrl+C。PCにブラウザの許可確認が出た場合は同じプライベートWi-Fi内に限定する。通常プレイのセーブを保護するため、比較シナリオはデバッグ版だけで使う。

- 砂浜：比較状況「接地点・露出」を再現 → 採取へ → 中央付近を保持・なぞる → 接地痕と短い露出反応 → 光った場所を回収。
- 川底：「ロープ・重量物」→ 岸から奥へスワイプ →「押し続けて引く」→ 影・ロープ先端・進捗が一緒に動くこと、成功時に画面をトーストが覆わないことを確認。「重量不足」「磁性不一致」も試し、対象が消えないことを見る。
- 河原：「パンニング」→ 皿を保持／揺らす → 処理完了で勝手に砂が大きく戻らないことを確認。「微細粒の吸引」→ 粒をタップ → 消えた位置の短い輪を確認。
- 同じ状況を再現しOFF／ONを比較する。縦持ちで押しやすさ、指の下の見やすさ、スクロールとの干渉を確認。端末の「視差効果を減らす」でも試す。

iPhone Safari実機は未確認。PCのモバイル相当設定による試験は実機の代わりにはならない。次フェーズは実機での入力・描画・電池負荷と、既存の狭い探索面の操作余地を評価する。大きなUI刷新やロープ物理、採取／経済バランスの調整は今回行わない。

## 性能比較の実測

変更前はGitの読み取り専用スナップショット`6b1e82b7f6cdba0db8c52413a651dcc9fee4a907`を使用し、追加診断APIがないことを先に検査した。現行版の追加演出OFF／ONと、同一シード・道具・在庫で比較。Chrome headless、390×844、動画なし、各条件3回、順序を入れ替えた計27サンプル。Bは3.2秒、R/Gは2.2秒の保持操作。詳細は`harvest-phase1/performance.json`、集計は`performance-summary.json`。

| 操作 | 変更前 RAF/秒 | 現行OFF | 現行ON | Canvas描画CPU時間：前→ON |
|---|---:|---:|---:|---:|
| 砂浜 | 59.95 | 58.83 | 59.95 | 2.192→2.735ms |
| 川底ロープ | 59.95 | 59.95 | 57.34 | 0.709→0.812ms |
| 河原パンニング | 56.22 | 46.24 | 59.95 | 0.859ms→描画0回 |

上記はブラウザのRAF間隔から算出した3回の平均で、物理画面の表示FPSやiPhone性能ではない。GPU・入力端末・ネットワークは計測していない。川底ONの1回は52.13、河原OFFの1回は18.82まで低下し、他の多くは59.95だった。50ms超の長いフレームはB-OFF、R-ON、G-変更前、G-OFFに各1回、他は0回。実行環境由来を含むばらつきがあり、安定したFPS向上や因果関係は断定しない。

河原の砂transform更新は3回合計で変更前65回→ON330回、背後Canvasは現行OFF／ONとも描画0回。実操作への追従と不要描画停止を確認できた。追加反応の計測ピークは砂浜2個、回収前の川底・選別中の河原0個。別の実操作試験で成功時の反応と粒回収1個、上限を確認した。追加の描画コストはゼロではないが、オブジェクト数は上限付きである。

初回計測は比較元が追加実装を含んでいたため無効とし、`invalid-initial-*`に隔離した。結果として引用しない。実装前動画の入力32.6msも1サンプルだけなので、入力遅延改善率は算出しない。
