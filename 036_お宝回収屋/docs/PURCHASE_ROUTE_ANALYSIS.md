# Version 0.4.1 — PURCHASE ROUTE ANALYSIS

## 4ルートの定義

Aは目標に必要な道具を優先。Bは安い前処理・回収の組み合わせを先に整える。Cは探索・回収・選別を段階的に強化。Dは対象分野の全実装道具を購入する方針です。Aが常に最速とは仮定せず、同じ条件で実測した4候補のうち速いものを表で判断します。数学的な全順序の最適解探索ではありません。

砂浜の第5層AはB101→B104→B105→B302（合計41050FN）。B203や探知機の全購入は要求しません。Bはバケツと広域採砂を追加。Cは探知機と第4層・交換ふるいを経由。Dは20道具です。

川底Aの重量物目標はロープ・強力磁石・滑車を優先。Bは伸縮棒・フック等の安い回収具、Cは段階的な回収と巻取り、Dは13道具。河原Aは採取・皿・スルース、Bはふるい・皿・ピンセットの工程、Cは観察・吸引と容量、Dは13道具を買います。具体的な順序は結果JSONのpurchasesとdev-routes.tsのpurchaseOrderで再現できます。

## 共通条件

各比較は同じシード、FN0、体力100、初期XP0、同じ初期配置です。川底/河原だけはエリア解放に必要な砂浜20個の実績を共通で与え、資金・身体能力は増やしません。Jを除外。初期エリアはB-A/R-A/G-Aで、進行に応じた通常の区画移動・道具購入・報酬を使います。処理量や購入費用を足すだけの計算ではありません。

砂浜は20px格子、1掘削0.32秒、回収0.45秒、選別0.6秒、初回公開ガイドを使用。川底は見えている影を探索2秒、対象選択/投擲0.5秒、引く0.75秒。河原は採取1.2秒、投入1秒、皿の作業単位0.6秒、粒回収0.45秒。洗浄1.4秒、購入2秒を共通にし、待機時の体力回復も通常どおり処理します。上限600分。これはモデル操作時間で、人間のプレイ時間を保証しません。

同一条件での再実行が同じ結果になることを自動試験し、実行条件・初期配置・購入順序・費用・操作数・使用回数・成功/失敗・収益・体力をJSONへ保存します。界面はコピー/保存、中止に対応。比較中に通常セーブを変更しません。

## 前版の約328分の照合

0.4.0の保存結果beach-balance-v040.jsonは、第5層19704.54秒（328.409分）、100シード、FN0、J0、全20道具購入です。新モデルのDは19698.737秒（328.312分）で近い値です。

ただし、前版は購入直後に道具別の試し操作をし、最後に第4/第5層用の区画で中央を掘りました。今回はその余分な試行を省き、目標道具購入後に公開中心へ到達確認を行います。初期資金・価格・基礎操作時間が共通でも完全に同じ操作列ではないため、約6秒の差を性能改善率にしません。比較JSONでもdirectlyComparable:falseと明記しました。A/B/C/D同士は今回の共通モデル内で比較します。

## バランス調整案と次版

- 既存価格・報酬は変更せず採用。全購入と目標到達の違いをショップ/説明で伝えることを優先。
- 河原はふるい・皿・精密回収の安価な工程投資が有効。高額装置の購入を急がせる一律倍率は不要。
- 川底は重量だけでなく、非磁性物・距離・障害物・広い照準を選べる配置を維持。
- 人間の購入順と操作時間、品質保護の分かりやすさ、長時間の保存/処理負荷を実機で計測。
- 0.5.0の設備は供給・選別・回収・運搬のボトルネックを独立して設計し、今回の手動作業を残す。
