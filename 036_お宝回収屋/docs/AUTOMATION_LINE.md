# Version 0.6.0 — AUTOMATION LINE

## 購入と接続

既存設備のID・名称・価格を維持する。B301 電動ふるい25,000 FN、R301 電動ウインチ30,000 FN、G304 電動砂利搬送機48,000 FN。ライン接続そのものの追加料金はない。既存46道具と126道具マスターを維持する。

QUICK TOOLSの「設備」→「設備・作業キュー」→「工程を接続・ライン管理」から基本工程を接続する。稼働・停止、工程単位の一時停止、設備／手動の方式、道具構成と優先順位を変更できる。手動工程は「1回処理」、最終精密回収は選別台を使う。採取と洗浄は引き続きプレイヤーの仕事。

## 工程と材料

| 分野 | 接続 | 手動で残る工程 |
|---|---|---|
| 砂浜 | 採取砂→搬送→砂選別→回収物整理→未洗浄品 | 掘削・露出品回収・洗浄 |
| 川底 | 指定対象→引き上げ→回収物整理→未洗浄品 | 対象指定・洗浄 |
| 河原 | 採取砂利→搬送→任意の砂鉄分離→粒径選別→比重選別→濃縮物 | 採取・最終精密回収・洗浄 |

自由配置エディターではなく、材料型の合う基本順序から方式を選ぶ。型違い、順序違い、重複、循環、終端欠落を拒否する。工程追加・削除はキューが空のときだけ。進行中の負荷・個体IDを保ったまま方式や一時停止を変更する。

## 能力と容量

| 工程 | 基本能力 | 構成による改善 |
|---|---|---|
| 砂搬送 | 90単位/分 | B108:240、B110:360 |
| 砂選別 | B104:180単位/分 | B208の細目設定:288 |
| 砂整理 | 20個/分 | B109:40、B110:60 |
| 川底引き上げ | 93.3引き量/秒 | 実際に使用するR110など既存能力を適用 |
| 川底整理 | 15個/分 | R101:40 |
| 砂利搬送 | 180単位/分 | G108:270 |
| 砂利粒径選別 | G103:66.7単位/分 | G202:83.3 |
| 比重選別 | 通常GoldWorkの負荷・粗粒率・方式に従う | G203や実作業のC10を適用 |
| 精密回収 | 手動 | 吸引瓶等の既存性能を適用 |

搬送前設備入力は砂・砂利240単位、川底12件。工程間の選別前容量は基本96単位、B108で144、B110またはG108で192。整理前8個、濃縮物の出力は分離済み12個体制限、未洗浄品は既存保管容量を使う。個数と材料単位と引き量は別単位。上流は下流が満杯なら停止する。濃縮物数は分離済み個体数を表示する。

## 作業と在庫

既存の予約付きAutoJobを拡張し、lineIdと現在工程を記録する。同じ材料を手動と設備で共有消費しない。砂・砂利の個体は採取時に確定したものを使い、再抽選しない。整理前の個体はtransit状態となり、洗浄報酬の対象にならない。整理でstoredへ移動して初めて洗浄できる。旧データなどの単一袋が工程間容量を超える場合は能力不足と表示し、予約解除後に手動で部分選別するか、運搬補助の構成を改善する。

砂・砂利は未予約在庫から容量内で自動搬送する。川底はプレイヤーが影を指定して登録した対象だけ。磁性、距離、ロープ、障害物、吸着力、重量、引き上げ能力の通常判定を維持する。失敗対象は区画に残り、無限再試行はしない。ラインの作業キュー、または従来の設備画面から構成を変えて再指示できる。

川底の未完了作業を残して区画を移る際は確認を表示し、予約を解除する。未回収対象と旧地形は破棄するが、回収確定品、砂・砂利、途中工程、中間在庫は保持する。

## 優先順位と表示

登録順、既知の処理量による少量バッチ優先、川底の観察済み対象優先、河原の精密回収優先から分野に応じて選ぶ。精密回収優先は分離済み個体が4個以上あると上流供給を抑える。未知の価値・レア度を参照しない。処理中の作業は中断して並べ替えない。

通常画面は入力・中間・搬送中・整理前・濃縮物・未洗浄品と実際の確定FNを表示する。停止理由・満杯を優先し、直近約10ゲーム秒の在庫増減と稼働実績から滞留工程を一箇所だけ強調する。5秒未満の計測はデータ不足。最小公称速度だけで断定しない。

## 保存と時間

saveVersion2と旧進行を維持し、任意のlinesフィールドを追加する。構成、工程統計、予約、途中量、transit、個体ID、出力を同じスナップショットに保存する。再読込は全設備・ライン停止で復元し、手動で再開する。詳細履歴と厳密な報酬資格は別管理。[保存最適化](SAVE_OPTIMIZATION.md)参照。

進行は表示中のゲーム時間だけ。非表示・終了時間を遡らない。SessionClockの復帰リセットで長時間分を一括処理しない。開発版の1/2/10倍速も同じ小刻みな工程処理を使う。計算とUIは分離し、通常管理画面は400msごと、開発詳細は1秒ごとに更新する。表示キューは最大8件、作業上限64件、履歴100件、計測61標本。

## DEBUG LAB

開発サーバーで設定を開き、バージョン表示を5回タップ。既存8タブ・44通常シナリオ・15 AUTOシナリオを維持し、「探索」「シナリオ」内のAUTOMATION LINEを開く。LINE-01〜20、工程JSON、1/2/10倍比較、WorkerのA/B/C/D比較・中止・JSON/CSV出力を追加。LINE-18/19は比較Workerを起動する。LINE-20は短時間の連続負荷再現、24時間試験は`npm.cmd run test:line-stress`で実行する。

通常セーブとデバッグセーブは分離する。強制操作・比較WorkerはDEVからのみ到達し、本番バンドルには含めない。比較処理は独立したメモリー状態を使い、中止しても通常セーブは変更しない。
