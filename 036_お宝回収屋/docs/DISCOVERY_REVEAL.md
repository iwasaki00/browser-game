# DISCOVERY REVEAL — 発見演出強化

Version **1.0.0-rc.1** 据え置き。300点の専用画像、9スプライトシート、画像マッピング、図鑑登録・報酬・保存形式、採取／経済バランスは変更しない。新規ゲーム用PNG・SVG・外部素材は追加しない。

## 表示と時間

| 正式登録結果 | 発見演出 | 洗浄完了後の演出時間 |
|---|---|---:|
| C / U の初登録 | 軽い拡大、NEW！ | 700ms |
| R の初登録 | 拡大、短い光 | 1,000ms |
| SR の初登録 | 拡大、光の輪、短い輝き | 1,500ms |
| J の初登録 | 特別な輝き、JACKPOT表示、大きめのドット絵 | 1,500ms |
| 2回目以降 | 通常結果。レア度の枠・名称は維持し、長い初発見演出を再生しない | 0ms |

「短縮」または「軽い演出」は最大300ms。演出オフまたは `prefers-reduced-motion: reduce` は拡大・光・点滅を省略し、結果をすぐ表示する。C/UでもNEW表示は残す。SR/J再取得は静的なレア度表示だけで、初回の長い演出を繰り返さない。

上表は洗浄完了後の時間。従来の洗浄は通常1,400ms、短縮350msを維持し、reduced-motionでも350msで静的に切り替える。既存音声設定を尊重し、新しい音声は追加しない。

## 正式登録と演出の分離

`mountReveal` は従来どおり `reward(s, uid)` を1回実行し、更新後の図鑑、支払済み状態、探索目標、テーマの状態から結果を作る。既存の確定コールバックが保存を開始した後で、共通の `playDiscovery` へ表示用の結果を渡す。

描画側は `State`・報酬処理・保存処理へ依存しない。アニメーション終了、タップ、演出終了ボタンから報酬処理を呼ばない。洗浄ボタンの連打、切り替え済みの「次へ」ボタンの古いイベント、プレビューの再生連打でも登録・支払いを追加実行しない。

「次へ」「閉じる」は演出を待たず操作できる。画像のタップ、または右下の「演出終了」で動きだけを終了し、結果を読み続けられる。演出終了後に追加の待ち時間はない。従来の洗浄スキップと、洗浄途中で閉じた場合に未洗浄品を保持する動作も維持する。

ブラウザが非表示になれば演出を終了する。初めから非表示なら再生しない。表示・メディア変更のリスナーとタイマーは閉じる／次へ／プレビュー再生時に破棄する。演出用の再生待ち状態をセーブへ追加しないため、再読み込みで演出や達成通知を再発させない。

## テーマ完成と探索目標

既存の3テーマを対象とし、最後の品の初登録でのみ「テーマ完成！ — テーマ名」、`3 / 3`、「図鑑で見る」を表示する。追加報酬はない。

目標も同時に達成した場合は、同じ結果欄へ「探索目標を達成」を各1回表示する。複数のモーダルや通知を積み重ねない。まずお宝の演出を見せ、同じタイムラインの60%時点（最大750ms）で進捗・図鑑ボタンを表示する。演出終了操作なら即時表示する。図鑑ボタンは完成テーマを開く。

## ドット絵と小画面

既存 `treasureShape`・画像マッピング・フォールバックを利用し、32×32の切り出しは変更しない。通常は4倍128px、Jは余裕のある画面で5倍160px、低い画面では3倍96px。整数倍の静止表示と `image-rendering: pixelated`、32px枠の `overflow: hidden` を維持する。

未洗浄中は画像本体を隠し、既存の汚れと仮見出しだけを表示する。洗浄後に正式名称・画像を出す。画像読込に失敗しても、既存SVGフォールバックで進行を止めない。

外側の洗浄モーダルは固定サイズを維持し、結果・画像・説明・報酬・ボタンの枠を小画面向けに調整する。汚れ落としと発見演出は軽いCSS処理で、フレームごとのJavaScriptや新しい画像生成は行わない。

画像の操作領域とボタンに限定して `touch-action: manipulation`、画像領域に `-webkit-touch-callout: none` を使う。ページ全体のズーム設定は変更しない。結果欄は `role="status"`、画像と操作は名前付きグループにし、演出終了ボタンをキーボードでも操作できる。

## DEBUG LABの確認手順

両ビルド後、対象フォルダで `npm.cmd run preview:both`。表示された `/dist-debug/index.html` を開く。起動時からDEBUG／テスト用セーブで、通常セーブとは別領域。

1. DEBUG LAB →「お宝」→「発見演出プレビュー（閲覧専用）」を開く。
2. C・U・R・SR・Jの初発見、テーマ完成、目標＋テーマ同時達成、SR/J再取得から選んで「演出プレビュー」。
3. 画像タップ／「演出終了」で停止。「再生し直す」で同じ演出を再生し、「LABへ戻る」で戻る。

プレビューは表示用データだけで再生し、登録・FN・発見履歴・探索目標を変更しない。「図鑑で見る」は実際の現在の図鑑へ移動するため、プレビューで3/3を見ても本来の図鑑が未完成のままでよい。ゲーム時間・通常の自動保存は従来どおりで、プレビュー自体は登録や報酬を呼ばない。

実登録を確認する場合は従来の「選んだ品を即回収」→「洗浄」を使う。同時達成は「テーマ収集の確認」で残り1点のテスト状態を作り、テーマで探索目標を設定→即回収→洗浄で確認できる。テスト進行を置き換える操作は既存の確認ダイアログを維持する。

通常版 `/dist/index.html` は従来どおりDEBUG操作を公開しない。共通描画処理は通常版にも含むが、DEBUG専用プレビューの選択UI・シナリオ定義・起動処理は通常ビルドに含めない。

## 検証と確認画像

最終集計は `discovery-reveal/verification.json`、各ログとブラウザ結果は同じフォルダを参照。

自動テスト730件成功、失敗・スキップ0。通常版・静的DEBUG版のTypeScript検査と本番ビルド成功。ブラウザは演出17、従来洗浄2、目標／テーマ連携24、静的DEBUG10の計53ケース成功。Chrome 390×844、Edge 320×568、Chrome 1280×920で確認し、reduced-motionとPNG失敗時のSVGフォールバックも確認した。

9シートは変更前とバイナリSHA-256が一致。300件の画像マッピング、既存スプライト描画・SVGフォールバック、マスター、経済・報酬・保存処理も内容一致（テキストはGitチェックアウトの改行差を除く）。プレビューのFN・図鑑・履歴不変、通常セーブ分離、通常版からのプレビューUI除外、編集ファイルのLFを確認した。

- 自動テスト：`npm.cmd test`。
- 両ビルド：`npm.cmd run build`、`npm.cmd run build:debug`。
- 演出試験：`node --import tsx scripts/discovery-browser.mjs`。
- 従来洗浄：`node scripts/discovery-legacy-browser.mjs`（空きポートのViteを自動起動・停止）。
- 目標／テーマ連携：`node --import tsx scripts/theme-goals-browser.mjs`。
- 静的DEBUG：`node --import tsx scripts/static-debug-browser.mjs`。

確認画像は `docs/discovery-reveal/`：`first-C.png`、`first-U.png`、`first-R.png`、`first-SR.png`、`first-J.png`、`theme-and-goal.png`、`preview-theme.png`、`preview-combined.png`、`reduced-motion.png`。

ブラウザの非表示は、`visibilitychange` と `document.hidden` を用いたシミュレーションを含む。iPhone Safari実機は未確認。Windowsで同じWi-Fiから確認する起動方法は [テーマ収集の説明](COLLECTION_THEMES.md) の4173／4174ポートの手順を利用できる。実機では各レア度、連続洗浄、演出終了、テーマから図鑑への移動、タブ切替、reduced-motionを確認する。
