# 探索目標・DEBUG LAB素材確認

確認日：2026-11-15。Versionは **1.0.0-rc.1** のままです。

## 追加内容

「図鑑・記録」の先頭に折りたたみ式の「探索目標」を追加しました。未発見の候補9点から同時に1点を選択・変更・解除できます。未発見時は「砂浜の目標1」等の仮見出しと共通シルエットを表示し、実名・専用絵は公開しません。採取画面ではキャンバス外、洗浄ボタンの上に短いヒントを表示します。この表示を押しても目標選択へ戻れます。

出現場所・深さ・道具能力・出現率・品質・売値・報酬は変更していません。目標設定による確定出現や追加報酬もありません。

R-Aは砂浜の累計登録10個、G-Aは砂浜20個または川底5個、G-Bは河原10個またはパンニング5回等の既存解放判定を使用します。画面には場所の「未解放」と条件、推奨道具の「未解放・未所持／購入可能・未所持／所持」を表示します。目標を選んだだけでは解放しません。各対象が案内場所に実際に生成されることを100シードの生成テストでも確認しています（出現率を変更する試験ではありません）。

## 達成と保存

- 通常の `reward()` が初めて図鑑登録する時だけ目標を達成し、設定を解除します。回収済み・未洗浄の段階では未達成です。
- 洗浄結果の既存登録表示へ「探索目標を達成」を短く添えます。達成キューや再表示待ち通知は保存しません。
- `explorationGoal` は任意の追加項目（targetと最大9件のcompleted）。saveVersionと既存保存キーは変更していません。
- 旧セーブには目標を付与せず、所持品・発見記録・通貨等を保持します。変更・解除・途中状態・達成済み状態を保存できます。
- 別の品の登録、同じ個体の二重支払い、同種品の再回収、読み込み直後では達成通知を繰り返しません。次の目標は手動で選びます。

## DEBUG LABの開き方と確認操作

開発サーバーで `/?debug=1` を開くと、起動時のセッション取得・読込・保存から `finders-debug-v1` だけを使います。通常の開発プレイは `finders-dev-v1`、本番は `finders-v1` です。テスト起動は通常の保存領域を読み込まず、テスト保存がなければ初期状態を使います。

既存入口も維持しました：「☰」→設定内のVERSIONを素早く5回タップ。既存の8タブ構成はそのままです。入口から切り替える際は、通常状態の保存とセッション解放後、テスト保存領域のセッションを取得します。テスト保存がない初回だけ退避した通常状態のコピーから開始します。URLも `debug=1` に切り替え、再読み込みで通常保存に戻ってしまうことを防ぎます。「通常プレイへ戻る」で通常領域を改めて読み込みます。

テスト利用中は採取画面に「DEBUG／テスト用セーブ」が表示され、「DEBUG LAB」ボタンから戻れます。

**全300点の閲覧：** DEBUG LABの「お宝」タブ→「全300点を表示」。既存図鑑の12件ページ送りと分野フィルターを使い、品名・IDでも検索できます。未発見品も実名・ドット絵・詳細を閲覧できますが、図鑑の登録数、発見フラグ、FN、探索目標は変更しません。「未発見・閲覧のみ」と表示します。

**選んだ品を即回収：** 同じ「お宝」タブで品名またはIDを入力→対象1点を選択→「選んだ品を即回収」→「洗浄へ」。既存 `spawn(..., {state:'stored'})` を使い、通常の個体ID・品質・回収状態を持つ未洗浄品を1点追加します。以降は既存の洗浄・登録・FN確定処理です。満杯なら追加を止めます。閲覧や即回収だけで目標を達成させません。

本番ビルドにはこのデバッグモジュール・強制操作・API・テスト保存キーを含めません。`?debug=1&dev=1&revealAll=1&lab=1` を付けても動作せず、隠し入口も無効です。
