# Version 0.8.0 — ADVANCED AUTOMATION

## 調査と互換設計

0.7.0では分野B/R/Gのキーがそのまま唯一のラインで、automation.machinesのB301/R301/G304も一台だけだった。工程・キュー・個体予約・報酬台帳は再利用し、設備種別IDと物理的なinstanceIdを分けた。既存46道具、126道具、300お宝、12エリア、3設備のID・名称・価格は維持。

既存購入分はB301:1/R301:1/G304:1へ一度だけ移行する。追加購入は:2で、各種類最大2台、各分野最大2ライン・合計6。旧キーB/R/GとLINE-B/R/Gを維持し、追加はB2/R2/G2とLINE-B2/R2/G2。設備個体はinstancesで管理し、旧machinesは一台目を参照する互換窓口。読込時に参照を結び直し、移行を繰り返しても個体を追加しない。

## ラインと材料配分

設定→設備・作業キュー→工程を接続・ライン管理。初回設備購入と基本ライン作成の後、設備一覧で増設し、分野の2本目を接続する。未使用の対応設備を、停止・空キューのラインに割り当てられる。同じ設備個体の二重接続は作成・設定・保存検証で拒否し、進行処理でも同一個体を二度実行しない。

ライン一覧から一つずつ詳細を開く。開始・停止、工程、道具、優先順位、目幅、材料指定を個別設定する。砂浜はB208粗目の大量処理と細目＋B106ブラシの精密処理を選べる。品質は未確定分だけ既存の道具判定で維持し、既に損傷した品を復元しない。川底は通常磁石とR203＋R104＋R110＋R206による吊り構成を分けられる。河原はふるい・スルース・砂鉄分離の組合せで微粒捕捉と速度が変わり、最後の精密回収は手動。ライン名でレア品やFNを増やさない。

- 手動指定：材料・指定済み対象を選び、ラインへ投入。川底は影をタップする対象指定もライン別。
- 均等配分：投入成功ごとに交互へ。個体・袋を無理に二分しない。
- 処理能力優先：各工程の能力、現在の待ち量、入力の空きを考慮。未知の品名・評価額は参照しない。
- 空き容量優先：入力の余裕が大きい受入可能ラインへ。空きがなければ元の材料庫へ残す。

自動配分は稼働中の受入工程だけが対象。方針変更は新しい投入にだけ反映する。停止ラインの予約を別ラインが奪わない。川底は配分設定にかかわらずプレイヤーが指定した対象だけを処理し、未知の水底を自動探索しない。

## 部分投入と予約

作業にlineIdとinstanceIdを保存。元バッチのautomationJobが唯一の予約所有者となり、1袋を複数ラインで同時処理しない。大袋はsandStart/sourceStartとamountで区間予約する。投入区間を処理した後、未投入の尾部だけ次の配分対象になる。前区間の未回収出力は元ラインに残し、次区間のラインへ移さない。固定個体ID・割当・残渣・品質を再抽選しない。

未着手でfed=processed=0、巻取りやGoldWorkがない作業だけreassignMaterialで安全に移せる。進行中の移動は拒否する。出力満杯・停止・失敗では元材料と予約を保持。川底の能力不足は一度失敗して再指示待ちとなり、対象は消さない。通常UIは途中作業を自動移動しない。

## 稼働・統計・保存

入力・中間・出力、工程実速度、待ち時間、稼働率、累計処理・FNはライン別。全体表示は実際に材料がある稼働ラインの滞留候補を示す。空ラインをカタログ値だけでボトルネックにせず、情報が足りなければデータ不足。

設備・ライン構成・レベル・配分・区間・予約・出力・統計を保存し、再読込時は全台・全ライン停止。現在区画を再抽選しない。厳密な個体台帳、最近200件と累計集計、IndexedDB単一進行タブとCAS保存を維持。公開版finders-v1／開発通常finders-dev-v1／LAB用finders-debug-v1を分離。

機械計算は10Hzを基本とし描画から分離。表示は400msごとで、材料数だけDOMを増やさない。非表示・終了中は処理せず、SessionClockの実時間差を再開時にまとめて使わない。

## DEBUG LAB

開発版の設定でバージョンを5回タップ。「探索」または「シナリオ」のADVANCED AUTOMATIONを開く。既存8タブ・99シナリオにADV-01〜20を追加し計119。6ライン・二重予約・設備接続・配分・強化・移行・成長・300品を再現できる。ADV-20は中止可能なWorkerで24ゲーム時間を試験する（初期材料を処理後は材料待ち）。継続投入・1002個の本格負荷はCLIで別検証する。

Workerの5構成比較は設備付与・材料準備済み・資金制約なしの性能比較。JSONに個体ID、レベル、道具、処理・操作・FN・稼働・在庫・待ち・投資回収を出力。追加収益がない条件の投資回収はnullとし、操作・時間削減として説明する。中止・終了・パネルを閉じる際にWorkerを破棄し、通常セーブを変更しない。DEVモジュールは本番から除外する。
