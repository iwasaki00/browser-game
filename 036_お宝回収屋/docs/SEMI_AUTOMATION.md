# Version 0.5.0 — SEMI AUTOMATION

採取済みの材料と指定した対象の反復作業を設備へ任せる版です。FNは既存の洗浄・報酬確定時だけ増えます。

126種の元マスターのID・名称・価格を維持しました。G304は採取済み砂利を工程へ運ぶ小規模設備として使用。G401自動砂利供給機（260,000 FN）は将来の大型設備のままです。46種の手動道具、36種のお宝、16組み合わせ、既存エリアを維持しています。設備は所持道具や4枠の装備とは別管理です。マスターの catalogOnly の3項目は設備画面経由で実装し、通常ショップにも「設備画面で購入／設備所持」と表示します。手動46＋設備3＋未実装77＝126です。

磁石・フックのいずれでも、R104のロープを実際の作業構成に含めます。R301の実効速度には実際の道具構成のR110（2.6倍）等を適用。1対象の必要引き量は既存式110＋重量kg×48＋難易度×12です。磁性・距離・吸着力・障害物・引上げ能力の判定は既存riverCheckを再利用し、能力不足を解除しません。

G304は袋ごとに供給→任意の砂鉄分離→粒径→比重選別を順に進めます。同時並列の生産ラインはありません。粒径工程の設備動作は1作業単位3秒、G103が66.67単位/分、G202が83.33単位/分。手で速く振る操作には速度面の役割を残します。比重工程は既存GoldWork.requiredを使用し、スルースは水流秒、皿は作業単位0.6秒。選別済み通常スルースは133.33単位/分で、C10は実際に砂鉄を分離した負荷だけ時間・捕捉率へ反映されます。大型皿の容量、細粒捕捉、多段ふるい、バケツの準備、吸引瓶の精密回収は従来通りです。

## 使い方

1. ショップ上部の「半自動設備を購入・管理」、またはQUICK TOOLS行の「設備」を開く。
2. 設備カードを展開し、前提・価格・容量を確認して購入。
3. 砂・砂利は袋を指定して投入、または容量までまとめて投入。入らない袋は元在庫に残ります。
4. 川底は主道具と補助道具を最大4種で構成し「川底の影をタップして登録」。影を自分で指定します。
5. 「稼働開始」。材料待ちになっても開始状態を保持するので、次の投入後に続きます。
6. 出力が増えたら「処理結果を確認」。砂浜・川底は洗浄、河原は選別台で粒の精密回収、その後洗浄。

別分野に移っても登録済み材料を処理します。未登録の未知の場所から自動発見はしません。川底の失敗対象は再指示待ちとなり消えません。主道具・補助構成を変えて再指示、または予約解除できます。失敗作業だけを繰り返さず、後続の有効な作業へ進みます。

## 作業キュー・在庫

作業はプレイヤーID＋増加する連番の作業ID、作成順序、分野、設備、元バッチ/対象UID、処理量、処理済/残量、進捗、状態、出力UID、道具構成を保存。材料側に同じ作業IDを予約し、通常の採取追記・手動選別・スルース登録との重複を拒否します。作業は設備ごとにFIFO、同時1件、全設備の進行中作業は最大64件。

砂は元バッチの固定UID・割当位置・既存品質を使います。累計物理処理量はscreenedUnitsの増加分。残渣への追加作業は砂を新規発生させず、処理済み物理量を二重加算しません。洗浄待ちへの移動に既存sortBatchを使用します。

河原も元のcontents、goldAllocation、captureRank、goldCaptureを使用します。選別の再抽選、未採取個体の追加、報酬の直接生成はありません。出力不足時は次の負荷の確定を保留し、進捗をrequired以下で保持します。回収済みUIDと通常の報酬確定履歴で二重取得を防ぎます。残渣はそのまま保存し、設備作業終了後に従来の手動再処理ができます。

区画移動時は予約済みの川底対象もretainedFindsへ保持し、登録時の位置・エリア・道具構成で回収します。前の地形は保持しません。砂・砂利・未受取品は既存の在庫へ残します。

## 状態とボトルネック

未購入／停止中／稼働中／材料待ち／出力満杯／処理不能。理由は日本語表示。入力待ち量、全未処理在庫、出力数、累計処理量、進捗を確認できます。

未計測は「データ不足」。10秒以上の観測と実在する待ち在庫・能力差がある場合に、供給不足、砂の選別待ち、川底の引上げ待ち、河原の遅い工程を表示。洗浄保管満杯を優先し、河原の分離粒の満杯は精密回収を案内します。G103の能力不足なら、多段ふるいの構成が具体的な改善案になります。架空の設備アップグレードを薦めません。

## 停止・保存・時間

一時停止は予約と途中進捗を保持します。予約解除には確認を挟み、材料を戻します。GoldWorkが途中の場合は解除せず、一時停止・再開を利用してください。

saveVersion=2を維持し、任意のautomation.version=1を追加。旧セーブには設備を付与せず、FN・道具・図鑑・砂・砂利を維持します。購入済み設備、稼働フラグ、キュー、負荷の途中進捗、出力個体、累計処理/稼働/停止時間/回収品数/確定FNを保存。読込後はすべて停止中となり、プレイヤーが開始します。

画面表示中のゲーム時間だけが処理に使われます。非表示への切替で時計をリセットし、再表示の初回は0秒。閉じていた時間の差分は保存も計算もしません。通常1倍、DEBUG LABの2倍・10倍は同じ0.1ゲーム秒以下の刻みで計算します。画面更新は通常HUD0.25秒、設備詳細0.4秒、開発統計1秒。設備は操作中の体力を消費せず、採取・精密回収の体力は従来通りです。

完了作業の出力UID配列はキューから除き、要約履歴を最新100件まで保持。生きている予約・未受取個体・残渣は削除しません。既存の実回収UID台帳や収益履歴は互換性のため維持しており、実績数に比例する増加は残ります。

## DEBUG LAB

開発版で設定・ヘルプのVERSIONを5回連続タップ。通常状態は退避し、finders-debug-v1のみを変更します。「探索」または「シナリオ」タブのSEMI AUTOMATIONを展開。既存8タブ・44シナリオを維持し、AUTO-01〜15を追加しました。

- 開始、材料不足、待ち在庫増加、出力、連続回収、重量/磁性失敗。
- 砂利連続供給、工程待ち、精密回収待ち、途中停止、保存復元。
- 大量材料、3設備の在庫、長時間稼働。
- 入力/処理/出力速度、在庫、能力、稼働率、停止時間、処理量、回収品、確定FNの数値とJSONコピー。
- 同一シードの手動/設備/道具併用/供給不足/基本ふるい条件をWorker比較。1〜100シード、途中中止、JSON保存。固定操作時間と投資回収のデータ不足を明記。

開発モジュール、強制状態生成、比較Worker、時間倍率UIはimport.meta.env.DEV分岐からのみロード。本番版は設備を通常購入・通常材料で操作でき、強制付与・倍率操作はできません。保存・リセットなどの既存確認も維持します。
