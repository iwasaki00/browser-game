## 3. 移動速度低下の再現

再現せず。ただし「iPhone実時間でも正常」との意味ではない。固定入力・固定刻みで実際の`game.js:update`→`moveClassPlayer`→`movePlayerBody`を実行。描画から移動量を推定したり、別の移動計算式を代用したりしていない。

平坦な隔離LAB地形、敵・弾・ヒットストップ・回復アイテムなし、開始X=1800。4兵科・左右・1秒／3秒・30／60／144Hz相当の更新を比較した。これは地形や戦闘の影響を除いた測定で、通常人手攻略ではない。

## 6. カメラの影響

### ほぼ固定の場面

X=64・右へ1秒、左カメラ端。全4兵科・3版ともカメラX=0、倍率0.50で一致。背景スクロール量0。表示解像度・ズームによる画面上の距離とワールド距離を混同しない。

### 追従する場面

RANGER、X=1800、初期顔向き右から左移動。開始カメラX=1544、画面内X=128、倍率0.50、先読み+32（論理画面px）。1秒後プレイヤーX=1705は全版共通。

| 値 | A1 | B | B1 |
| --- | ---: | ---: | ---: |
| 左向き確定まで（60Hz） | 0.0167秒 | 0.1333秒 | 0.0167秒 |
| 1秒後カメラX | 1347.128 | 1351.251 | 1347.128 |
| 1秒後画面内プレイヤーX | 178.936 | 176.875 | 178.936 |
| カメラ由来の背景スクロール量（符号付き論理px） | -98.436 | -96.375 | -98.436 |
| 1秒後先読み量（論理px） | -30.828 | -30.131 | -30.828 |
| 目標カメラとの残差（world px） | -23.783 | -26.512 | -23.783 |

背景値はカメラ移動量×0.50。個々のパララックス層は別の係数で動くため、その層の実画像変位ではない。残差は瞬時の先読み目標に対する位置差で、時間遅延へ換算していない。

Bは新しい方向を一律0.12秒待ち、60Hzでは8更新目に切り替わった。1秒の背景スクロール量が約2.06論理px少ない。開始時から右方向へ継続したケースはA1/B/B1で一致した。したがって、これは**左向き開始・反転時の体感に影響し得る確認済みの差**で、継続直進の遅さ全体の根本原因とは断定しない。

B1では入力が設定した`player.face`と速度方向が一致する場合のみ即時反映する。顔向きと一致しない速度ノイズには従来の確認待ちを維持。倍率式・0.35〜0.85・追従係数5・方向補間4・ボス枠・座標変換は不変。全4兵科の意図した反転は、1秒分のカメラX・画面内X・先読みが各更新でA1と一致した。

## 7. 入力処理の影響

Bの通常長押しに入力途切れは再現しなかった。pointermoveでボタン外座標へ動かしても押下継続し、個別pointercancelはその指だけを解除。WING FLY/HOLD/FIRE同時押し、他指のキャンセル、pagehide・touchcancel・lostcapture・回転・ポーズでの解除を関連テストで確認した。

入力処理はBから変更していない。A1の「所有状態を先に消す→キャプチャ明示解放」の順序、リザルト入力解除・SW長押し解除も維持。Safari固有のイベント到達順や実際の中断復帰は未確認。

## 8. アニメーションの影響

`p.anim += dt * (移動中10 / 停止中4)`、`classPlayerFrame`、歩行・飛行の選択条件はA1と同一。1秒／3秒移動でカウンター増分10／30、ジャンプ中も同じ。WINGは既存の上昇／ホバーポーズを選択する。周期低下は再現せず、変更なし。

実際の`loop(ts)`もA1/B/B1で同一。rAF相当30／60／144回/秒を入力する試験でも、内部60Hz固定更新で`実移動量 = 実際に進んだゲーム時間 × 95`となった。浮動小数の端では1更新未満がaccに残るため、描画回数や予定壁時計秒を移動時間とみなしていない。実機停止・長フレーム時の0.1秒上限も元から同じで、今回変更していない。
