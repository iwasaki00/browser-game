# CAMPAIGN INTEGRATION QA / 1.1.0

## 目的・実行

M01〜M08の正式出撃・必須ギミック・ボス撃破・報酬・保存・完結を、後から同じ条件で再実行する。新ミッション・武器・兵科・実績は追加しない。

```powershell
npm run qa:campaign
```

Node標準機能だけを使用する。実装は`tools/campaign-integration.mjs`、既存の`tests/helpers/runtime.mjs`と`campaign-routes.mjs`。既存game.jsをVMで実行するDOMアダプターを再利用し、別の戦闘エンジンは作らない。描画はスタブ、判定・移動・射撃・敵AI・正式クリア／報酬・統計は実ゲームコードを通す。ランナーは固定乱数seed11001008、固定刻み1/60秒。成果物は`reports/campaign-integration/results.json`、`README.md`、`related-tests.txt`。

部分確認は次のいずれか。部分JSONは全体結果と別ファイルへ出力する。

```powershell
node tools/campaign-integration.mjs --section=chain
node tools/campaign-integration.mjs --section=matrix
node tools/campaign-integration.mjs --section=normal
node tools/campaign-integration.mjs --section=saves
node tools/campaign-integration.mjs --section=weapons
```

## 4つの試験区分

| 区分 | 実行内容・認定範囲 |
| --- | --- |
| STRUCTURAL | 32到達試験は敵攻撃なし、LAB AREA01から実移動。64初期武器試験はボス地点開始＋LAB無敵で実射撃、盾・必須部位・撃破・結果を検証。ワープなし通常全編攻略とは言わない |
| ASSISTED | 新規保存から通常司令部→装備→出撃し、唯一の補助invuln=3600でM01〜M08を通し攻略。敵HP・座標・フラグ・武器を攻略途中で書き換えない |
| NORMAL_SIM | 無敵なし、通常HP・被弾・死亡あり。指定8ケースの入力専用controllerによる自動戦闘。今回の未クリアと人手の攻略不能は別 |
| HUMAN | 人手・実機の通常攻略。今回は全8件NOT_RUN、1.2.0対象 |

既存LABのA/B/C/D文字は過去の区分であり、1.1.0レポートの上記名称とは別。例：旧LAB Cの無敵ボス攻撃確認をSTRUCTURAL欄で利用する場合、無敵・途中開始をmethod欄に明記する。

1. 隔離Mapの空保存でM01のみOPENを確認。
2. UIイベントの司令部・ミッション選択・兵科選択・装備・出撃を通す。
3. 入力専用controller→既存update／shoot／命中処理で全5エリア・ボス撃破へ進む。
4. 既存の撃破後タイマーだけを実行し、正式リザルト・報酬・保存を確認。
5. 保存したJSONを新しいruntimeへ渡してゲーム再初期化、次作戦解放を確認。
6. M08最終撃破直後の保存・再読込、全6シーン、8/8・再視聴・スキップ・再出撃へ。

各武器を所持済みテスト保存から通常UIで装備し、実発射・設置・攻撃オブジェクト生成・静止標的へのダメージ・使用／有効命中統計・再出撃時の残留消去を確認する。標的HP50000はこの個別試験のフィクスチャのみ。連続キャンペーンの敵HPは変えない。

- S01新規、S02 M01済、S03 M03済、S04 M05済、S05 M06済、S06 M07済、S07 M08済は同一実行の正式連続進行スナップショットを利用。
- S08は既存テストと同じ実在するv1の`cleared`／`unlocked`／`equipped`等。未記録の兵科・武器統計は推測しない。
- S09欠損値・記録0と不明、S10不正値・不明ID・称号ガード。起動時に正当な旧実績を補完する仕様を保存破損と誤認しない。
- LABでは200体生成／消去、ボス撃破、仮想完結、終了を通し、通常JSONの全バイト一致とstorage.setItem呼出数0を確認。起動時の正常化保存は基準前。
- 通常攻略QAプリセットを実UIハンドラーで適用し、無敵OFF・初期2武器を確認して被弾・死亡後も通常保存不変。その後のLAB無敵ボス撃破も隔離。
- 各runtimeは別Mapで、ユーザーのブラウザlocalStorage・ファイル・通常セーブへ接続しない。独立sentinel保存の不変性も回帰テストに含む。
- 司令部0/8〜8/8と30実績を区別。全6作戦・全20武器等の固定対象、称号ガード、通知重複、既存取得日時、カテゴリ代表イベントは関連スイートで確認。

## NORMAL_SIMと不具合分類

対象：RANGER/M01、GUARDIAN/M02、SCOUT/M03、WING/M04、RANGER/M05、GUARDIAN/M06、SCOUT/M07、WING/M08。最大HP・実被弾回数・累計被害・致死量／発生元X／位置／時刻・エリア・撃破・ボス到達・予兆観測を記録する。発生元Xだけから攻撃名を断定しない。

A地形衝突、B必須部位攻撃不能、C回避経路欠如、D進行保存、E自動操作能力不足、Fその他を区別する。今回controllerには一般的な反応回避がなく、NORMAL_SIM未クリアはE暫定。理論上の回避不能を実証しておらず、難易度を下げない。

重大度はBLOCKER（起動・進行・保存・完結不可）、HIGH（部位撃破不能・報酬重複・隔離漏れ・兵科進行不能）、MEDIUM（限定的攻撃／統計／残留）、LOW（外見等）。テスト基盤の不正な期待値と本体の不具合も分ける。

## 今回の修正・保護範囲

本体の戦闘・地形・保存形式のBLOCKER/HIGHは試験範囲で再現しなかったため、性能調整はしていない。バージョン表示・QAランナー・既存controllerの共通化・ストレージ書込監視を追加。旧M04/M05テストの実装状態／リトライ統計期待値を現行仕様へ修正し、入力専用制約・正常キャンペーン実射撃＋sentinel隔離・無敵なし死亡計測の回帰テストを追加した。

通常320、LAB640、UNIFIED 01、LAB5タブ、司令部4タブ、武器20、兵科4、既存AI・HP・カメラ・保存キー・30実績・Arcade031は維持。
