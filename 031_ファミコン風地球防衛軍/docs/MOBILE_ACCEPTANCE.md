## 目的と未認定事項

## Windows → iPhone Safari

本プロジェクトはHTML/CSS/ES Modulesの静的アプリで、起動にビルドは不要。開発機ではPythonの`py -3`でHTTP配信できることを確認済み。下記LAN配信は利用者が信頼できるプライベートLANで実行する手順であり、今回こちらからLAN公開・ファイアウォール変更はしていない。

1. WindowsとiPhoneを同じ信頼できるWi-Fi/LANへ接続。PCがスリープしない状態にする。
2. PowerShellで**このプロジェクトだけ**を配信する。8120が使用中なら未使用の検証専用ポートへ変更する。

   ```powershell
   Set-Location -LiteralPath 'C:\_wk\github\browser-game\031_ファミコン風地球防衛軍'
   py -3 -m http.server 8120 --bind 0.0.0.0
   ```

3. 別PowerShellで`ipconfig`を実行し、現在接続中のWi-Fi/EthernetのIPv4を確認する。VPN・仮想NICの値や過去の固定IPを使わない。
4. iPhone Safariで`http://<今回確認したPCのIPv4>:8120/?debug=1`へ接続。`0.0.0.0`は待受指定であってアクセス先ではない。iPhoneの`localhost`／`127.0.0.1`はPCを指さない。
5. タイトル→TEST LAB→「計測」→実機診断。横向き推奨だが縦でも継続可能。バージョン1.2.0-Aを確認する。
6. 終了時はサーバーのPowerShellでCtrl+C。ルーターのポート開放・外部公開・GitHub Pages更新は不要。

Pythonの待受オプションは[公式http.server CLI](https://docs.python.org/3/library/http.server.html#command-line-interface)に基づく。配信フォルダに秘密情報を置かず、親リポジトリ・ホームフォルダ全体を配信しない。

### 接続できない場合

- PC自身で同じIPv4 URLを開く。サーバーが127.0.0.1のみで待受していないか、ポート・フォルダ・IPv4が正しいか確認する。
- ゲストWi-Fi、APクライアント隔離、VPN、組織ネットワークは端末間通信を遮断することがある。許可されたネットワークで確認する。
- Windowsファイアウォールに阻止される場合は利用者の管理方針に従い、Python／該当ポートの**プライベートネットワークだけ**の許可を確認する。ファイアウォール全体を無効にしない。セキュリティ警告を無視する手順は使わない。
- LAN HTTPではClipboard APIの自動コピーが使えない場合がある（[writeTextはsecure contextが必要](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText)）。ゲーム自体の確認は可能。出力欄を長押し→選択→コピーを使う。JSONの端末内保存もSafari挙動を実機確認し、失敗時はテキストで保管する。
- このプロジェクトにService Worker登録はない。古い画面なら再読込とバージョンを確認し、必要なら未使用の検証用ポートを使う。普段のサイトデータ全消去は通常セーブも消すため行わない。HTTPS警告回避やOSの画面向き固定APIの成功を前提にしない。

## B：無敵なし通常ミッションの人手試験

LABの装備自由・途中開始・無敵QAと、通常の攻略は別の試験である。今回通常保存方式は増やさず、**未使用の別ポート（別origin）**を検証用プロフィールとして使う。

1. 通常利用していないポート8121で、同じプロジェクトに対して別のサーバーを起動する。

   ```powershell
   Set-Location -LiteralPath 'C:\_wk\github\browser-game\031_ファミコン風地球防衛軍'
   py -3 -m http.server 8121 --bind 0.0.0.0
   ```

2. iPhoneで`http://<PCのIPv4>:8121/`を開く。**debugクエリなし**。いつものURL・ポートと異なることを確認。protocol／host／portが同じならクエリだけ変えても保存隔離にはならない。
3. 新規状態からM01を選び、通常の武器解放・被ダメージ・死亡・ボス遷移・クリア条件で遊ぶ。M08等は通常進行で解放してから試す。普段のセーブをコピー・初期化したり、未解放武器を注入したりしない。
4. 兵科・武器・密度・エリア・プレイ秒数・クリア／敗北／中断を手動記録。再読込して同じ検証用originの進行が復元されるか確認する。
5. LAB側8120の実機診断→履歴・人手評価→「B：通常URLで遊んだ結果を手動記録」を展開。結果文脈を入力し、無敵なし確認をチェック→「通常URLの人手記録を新規作成（計測なし）」。計測値は未取得のまま。これは自己申告で、通常ゲームのクリア・報酬・実績を付与しない。

LABから本編へ抜けるだけを保存隔離の根拠にしない。測定しない通常プレイのFPSを、別のLAB試験の値で埋めない。通常HUMAN試験は今回未実施。

## 評価・問題とPhase B

5項目（操作・視認性・難易度・音声・性能）は未評価=`null`、1=問題大〜5=良好。未評価を1に置き換えない。端末名は任意、個人情報は入力しない。自由メモ・結果・問題だけの短い入力でも保存できる。

| 重大度 | 例 |
| --- | --- |
| BLOCKER | 起動不能・進行不能・セーブ消失 |
| HIGH | 操作不能・ボス撃破不能・重大な処理落ち・LABの通常セーブ混入 |
| MEDIUM | 見づらい予兆・誤タップ・特定場面の遅延・音声不具合 |
| LOW | 装飾・文言・軽微な配置の違和感 |

問題は試験IDへ紐づく一意の記録ID、ミッション、条件、再現、影響、計測値／状況、備考を持つ。追加時はOPEN。修正状況は明示操作でのみRETEST／RESOLVEDへ変更。Phase BではJSONと再現手順・画像を添え、同じ機種・場面・入力条件で再確認してから解決判定する。測定値だけを理由に武器・敵・兵科を大幅変更しない。

診断履歴は直近20件・問題は各12件。20件を超える前にJSONまたはテキストで保管する。容量エラー時はメモリ内の結果をコピーし、通常保存は触らない。外部送信・端末固有ID取得なし。ブラウザが保存を消去する場合への保証ではない。

[実装・自動テスト・Chrome画像](../reports/mobile-acceptance/README.md)。次段階へ残るのはiPhone実タッチ／音声／中断復帰、LAN到達、通常人手攻略、連続負荷・熱による長時間変化の実観察。温度そのものの数値は取得しない。
