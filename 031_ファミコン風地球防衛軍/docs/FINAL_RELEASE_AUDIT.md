# 1.2.0-C5 — FINAL RELEASE AUDIT

C4を基準にしたローカル最終回帰・配列安全性・公開前監査。新コンテンツ追加なし。公開・commit・push・デプロイは実施しない。実施結果・変更一覧は[レポート](../reports/final-release-audit/README.md)、機械可読証拠は[results.json](../reports/final-release-audit/results.json)。

## 判定の扱い

PASS＝実行して確認、FAIL＝実行して問題を検出、NOT RUN＝未実施、BLOCKED＝前提問題で実施できない。ASSISTED／URL無敵・地形到達・ボス地点開始・人手通常攻略を区別する。NORMAL_SIM未クリアをPASSへ読み替えない。Node VMのRAF呼出しやCPU所要時間を実機FPSと呼ばない。

公開判断はREADY／CONDITIONAL／NOT READY。実機受入が未完了ならREADYにしない。公開候補の静的／自動試験が通っても、実際のPages・CDN・キャッシュ・端末での成功保証ではない。

1. M08の形態1／2でT-16とM-20の予約が同時に存在すると、T-16による形態移行でjobsが0件になり、旧件数で次の`job.weapon`を参照して例外。`i < initial && i < jobs.length && jobs === g.arsenal.jobs`へ変更。

修正前：新規配列8試験のうち7 FAIL／1 PASS。修正後：8 PASS。非致死時のタレット保持と70ダメージも確認。武器・兵科・敵・ボスの能力値は一切変更しない。

## 保存・資産・監査の限界

- 通常キー／debug2キー／LABメモリ／QA Mapを区別。通常／旧セーブ、報酬二重防止、兵科・武器統計、30実績・称号、完結・再視聴の既存試験を利用する。実ユーザーのSafari保存領域は読まない・書かない・初期化しない。
- 静的監査は秘密候補・相対参照・大文字小文字・PNG署名／寸法・外部通信・ライブラリを検査。秘密候補の実値を出力しない。全履歴・バイナリ内部・あらゆる認証情報を検出する保証ではない。
- 実行時画像は固定シードPython/Pillow生成器・マニフェスト由来。音声はWeb Audio合成、フォントは端末システム指定。ブラウザへ配る外部ライブラリ／フォント・音声ファイルは見つからない。Pillowは開発側のみ。正式な権利帰属・公開ライセンスの選択は所有者の確認待ちで、勝手にライセンスを付けない。
- 公開候補へはHTML/CSS/JS/実行時assetsのみ。docs・reports・tests・tools・ローカル監査ログ等は除外。一覧は[public-manifest.json](../reports/final-release-audit/public-manifest.json)。ソース全体のまま配信すると内部文書・テストも参照可能になるため区別する。
