## 2. 新しい方向：FIELD STEEL / LIVING CARAPACE

16bit寄りの、読みやすい軍事SFピクセルアート。味方は角張った鋼板と布・装備、侵略生物は重なる曲面甲殻と節足。共通の暗い輪郭、左上光源、少数の段階的な色面で同じ世界にまとめる。過度な写実、写真テクスチャ、ぼかし・自動アンチエイリアス、全面的な微細ノイズは使わない。

- 優先順位：輪郭 → 大きい明暗 → 向き/部位 → 材質 → 微細情報。
- 1pxの点を撒くより2〜6px程度のピクセル群で面を作る。斜線は一定の段差リズム、輪郭は必要な場所だけ1〜2px。
- 明るい顔/照準・武器先端、暗い胴、読み分けられる腕/脚。全周を白で縁取らない。
- ダメージ範囲・武器性能・既存の当たり判定を見た目の変更に合わせて拡大しない。

## 3. 配色

共有パレットをサンプル生成モジュールに集約する。光源は左上、金属のハイライトは冷たい灰緑、反射は控えめな青緑、敵の装甲は紫褐色から銅/珊瑚色。白に近い色は顔・刃先・エネルギー核だけへ限定する。

| 用途 | 色の役割 |
| --- | --- |
| 共通輪郭 | 青黒。真っ黒一色の太い縁で面を潰さない |
| 味方 | スレート/オリーブの4〜5段階＋青緑バイザー＋小さな象牙色 |
| 敵 | 紫褐色の影＋銅/珊瑚色の甲殻＋酸黄の眼/器官。味方の青緑を主要面に使わない |
| 武器 | 共通の鋼材。アサルト=青緑、ロケット=琥珀、誘導=酸黄、雷撃=青紫、設置=青緑＋警告色。色だけで分類しない |
| M01 | 冷たい青灰の空気遠近、崩れた都市と少数の暖色窓。活動物より低彩度 |
| M02 | 濃い青緑の閉鎖空間、太い配管/金属、局所的な鈍い酸黄。M01より天井と奥行きの暗さを強める |

キャラクター/敵/ボスの単一コマは概ね8〜20色を目安とする。陰影のための色であり、細かな色差だけの大量パレットは作らない。背景は別の抑えたランプを使用する。

## 4. キャラクター

- RANGER：実用的な低いヘルメット、片肩装甲、箱形バックパック、銃床から銃口へ水平の線。前足/後足の間を空け、顔・銃の向きを明確にする。
- WING：背中から開く2枚の翼/推進ユニット、軽装の細い胴、浮いた膝。RANGERの帽子や色だけを変える案にしない。噴射がなくても背中の輪郭で識別する。
- 将来のSCOUT：後傾した輪郭・軽い脚・短いマント。GUARDIAN：広い肩・厚い前腕・低い重心。今回は制作しない。
- 今回は各兵科2ポーズのルック検証。歩行/被弾/死亡などの完成アニメーションではない。

## 5. 敵・ボス

- 地上敵E-01：低い六脚、前向きの小頭部、左右に分かれる大顎、段階的な甲殻。脚間の抜けを保つ。
- 飛行敵E-03：横に広がる翼、軽い腹節、下向きの器官。地上敵と同じ甲殻言語だが、接地しない輪郭・姿勢を持つ。
- B-01：重い腹部を背後に置き、複数の甲殻板、巨大な前脚/顎、小さく鋭い眼、明確な腹部器官。顔を大きくして雑魚を拡大しただけにしない。今回は移動/攻撃のルック2ポーズ。
- 本フェーズではB-02・E-02・E-04〜06・ネストは未制作。将来は同じ材質規則で展開し、巣は構造物でなく生物として読める接地部を設ける。

## 6. 武器・効果

対象はA-01 / R-04 / H-08 / T-06 / D-19の5種。ID/名称/性能は既存データを保持する。5アイコン、5装備表示、5弾体、各4段階の命中/特殊効果の見本を作る。

- アサルト：細長い銃身、箱型マガジン、短い実体弾と小火花。
- ロケット：太い単筒、肩当て、太い弾頭/短い排気と琥珀色の衝撃輪。
- ホーミング：斜めの連装ポッド、独立した小弾頭/操舵翼。
- ライトニング：二股の電極・絶縁部、分岐した電撃。直線レーザーと区別する。
- 設置D-19：三脚＋回転砲頭。銃のアイコンを置くだけにしない。
- フレア/火花の白い核は短く小さく、長い不透明な煙で敵や床を隠さない。今回のFXは美術見本で、ゲームの効果上限や描画処理には接続しない。

## 7. 背景・地形

- 遠景：輪郭と空気の色、低コントラスト。中景：建物・柱・配管のまとまり。近景：少数のフレーム構造。レイヤー別PNGと合成PNGを保存する。
- M01：被災した高層建物、道路/高架、遠いビーコンと煙。M02：地下鉄跡・太い輸送管・支柱・奥の坑道。看板や窓を全面へ等間隔に配置しない。
- 前景は画面端中心。プレイヤーの頭/武器/足元に相当する中央の戦闘帯を、明るい細線や瓦礫の塊で埋めない。
- 各ステージ8タイル。歩ける上端は連続した明るさ、側面は暗い面。ひび・ボルト・パネル継ぎ目は変種で散らすが、足場の高さを偽装しない。
- 新背景は雰囲気見本であり、現行ステージの地形配置・天井高さ・障害物を変更する図面ではない。

| 素材 | 今回の原画セル | 比較時のワールド/表示サイズ |

ワールド素材を2倍密度で新規に描く。旧素材を単に拡大/フィルター処理する方式ではない。既存素材の拡大は比較用だけに行う。

- 一覧画像で原画を整数拡大して面と輪郭を比較する。
- 独立プレビューではズーム0.35 / 0.50 / 0.85、現行320×180と提案640×360の描画面を切り替え、同じワールドサイズで比較する。提案640は**プレビュー内だけ**。ゲームのCanvas/カメラ/HUDは変更しない。
- 現行320の0.35倍では細部が欠落する。まず顔・武器方向・翼/脚の大きな形が残ることを優先し、情報を足し過ぎない。
- iPhone横844×390程度では一覧を内部/ページスクロール可能にし、ピクセル画像はnearest-neighbor、操作対象44CSS px以上、safe-areaを確保する。小さな文字をスプライトへ焼き込まない。
- 明度だけの縮小・単色シルエットも一覧に載せ、色差なしでもRANGER/WING・地上/飛行を区別できるか確認する。
- 全採用前に実機で一度、現行320を維持する案と描画面のみ640へ上げる案を評価する必要がある。後者は座標変換/HUD/負荷の検証を伴う別承認作業であり、今回未実装。

## 10. 全展開ルール・概算

1. このルックを確認し、色/密度/頭身/ボス方向と、現行描画面の扱いを決める。
2. 兵科・敵・ボス・武器の原画枠/接地線/銃口アンカーを固定。画像寸法と当たり判定は別データとして扱う。

4. 武器20種をカテゴリ単位で展開し、全兵科装備・飛行/ダッシュ・同時爆発で読めるか確認。
5. M01/M02のタイル接続、背景ループ/パララックス/カメラ両端を検証。全置換は切替可能な別セットで段階導入する。
6. 844×390で0.35/0.50/0.85、50/100/200体、LEVEL1〜3の重なり/負荷/端末温度を確認する。見えない細部は削る。

概算は1人の作業日換算（1日約6時間の集中作業、レビュー待ちを除外）。承認後の4兵科全動作2〜3日、通常敵/巣/2ボス3〜4日、20武器/弾/FX3〜5日、M01/M02背景・地形2〜3日、組込み・表示/性能QA2〜3日、調整余裕2日、合計14〜20作業日（約84〜120時間）。描画面の640化を採用する場合は別途2〜4日程度。採用条件・アニメーション品質で変動し、今回のサンプルだけで全量の完成度/性能を保証しない。

### 改善点と限界

- RANGERは装甲・布・前腕・銃を同じ水平の向きへ整理。WINGは大きく開く背面フィンと浮いた膝で、単色でもRANGERと区別できる。
- 敵の主面を暖色へ統一。地上の低い六脚と飛行の翼膜を明確に分け、味方の青緑バイザーと競合しない。
- B-01は縦色帯主体から、重なる甲殻/節/大顎の造形へ。描画枠は同じなので、巨大化による印象差ではない。
- 武器は銃身/単筒/連装ポッド/電極/三脚で外形を分け、弾と命中見本にも対応する色/形を持たせた。
- 市街地は空気遠近、損傷建物と高架。地下は閉鎖的なアーチ・配管・放置車両。窓・柱・タイルの単純な等間隔反復を減らした。近景は左右へ寄せ、中央は活動物より抑えた明度にした。
- 初回の縮小確認で味方の金属/布が背景へ沈みやすかったため、中間色・縁の明度とバイザー面積を調整した。派手な全面発光で解決する案にはしていない。
- **320×180・0.35倍では細部が消える**。原画を整数拡大した一覧だけで評価せず、比較ビューも確認する必要がある。左右比較は1枚あたりのCSS幅が実ゲームと異なり、iPhone実機の見やすさを保証しない。
- 背景はルック見本。継ぎ目・パララックス・高所/大量戦闘の遮蔽は全採用前のゲーム内検証が必要。今回、全素材差し替え・描画面変更・完成アニメーション制作は行っていない。
