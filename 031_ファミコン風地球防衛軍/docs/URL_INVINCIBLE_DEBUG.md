# URL無敵試験 / 1.2.0-C3

通常画面・通常エンジンの進行を確認するためのローカル試験モード。正式攻略の記録ではなく、特権・認証機構でもない。公開・commit・push・デプロイは行っていない。

## URLと初期状態

| URL | 動作 | 保存先 |
| --- | --- | --- |
| `index.html` / `?debug=0` | 従来の通常プレイ | `pixel-defense-front-save-v1` |
| `?debug=1` | 従来の開発UI・TEST LAB | 既存仕様（LAB操作は保存しない） |
| `?debug=2` | 通常画面の無敵試験 | `pixel-defense-front-save-v1-debug2` |
| `?debug=20` / `02` / `true` / `2abc`等 | 通常プレイ | 通常保存先 |

`URLSearchParams(location.search).get('debug') === '2'`で厳密判定する。標準のURLデコード後の値を用いるため`%32`は`2`と同じ。重複指定はURLSearchParamsに従い先頭値を採用する。ページ起動ごとに判定し、URL変更には再読み込みが必要。debug=1用の`DEBUG`とは独立しており、debug=2でTEST LAB、BENCH、640描画、`__PDF_GAME__`を表示・公開しない。

初回の専用セーブは既存の既定値（M01／RANGER／A-01,S-02）から開始する。通常セーブは読み出し元にも使わない。試験を急ぐ場合、タイトルの「DEBUG 2：試験用ステージ解放」内のボタンで実装済みM01〜M08だけを解放できる。これは明示操作で、クリア履歴・報酬・武器・戦績の付与はしない。選択・装備・出撃・リザルト・次出撃・エンディングは通常と同じ画面／条件処理を利用する。

## 無敵処理と保護

- `js/game.js`の共通`hurtPlayer`で、HP減算の一文だけをURLモードで抑える。毎フレーム回復する実装ではない。
- 接触／弾命中、被弾ポーズ・音・揺れ、通常の1秒被弾無敵、ノックバックは維持。既存の設定を尊重する。敵のHP／AI／攻撃や武器ダメージは変えない。
- RANGER／SCOUT／GUARDIAN／WINGの能力は不変。WINGのENも通常どおり消費・回復する。
- M03〜M07の落下被害も共通ダメージを通るためHPは減らず、各ミッションの安全復帰を維持。M08は既存の安全復帰、M01/M02は既存の地形下限を維持する。独立した即死／強制GAME OVER経路は見つからなかった。進行不能に対する無条件クリアは追加しない。
- URLモードはページ内定数で、ポーズ・再開・再出撃では変わらない。通常ゲームのLAB無敵スイッチは変更しない。

## 保存と診断

起動時の`loadSave()`より前に`activeSaveKey`を決定する。既存の`sanitizeSave`・`storeSave`・正常化保存・例外案内／再試行を再利用し、形式や報酬処理を複製しない。報酬・実績・称号・クリア・解放・戦績・武器使用・最高点・最短時間・兵科・装備・設定・キャンペーン完結も、すべて同じ専用キーに保存する。

通常キーへの書込・削除や、専用セーブから通常セーブへのマージは行わない。容量制限等で専用保存に失敗しても通常キーへフォールバックせず、「未保存」と既存の再試行操作を表示する。その場合、ページを閉じると未保存進行を失う可能性がある。

既存の遷移診断を継続利用し、debug=2では`sessionStorage`の`pdf-result-transition-debug2-v1`へ隔離する。JSONの`saveScope`は`DEBUG2`、通常は`NORMAL`。通常の診断アーカイブは上書きしない。外部送信なし。C2のRAF保護、崩壊・保存の分離、入力解除は維持する。

## iPhone Safariでの確認手順（実機未実施）

1. 通常URLの司令部で、現在のクリア・武器・実績・兵科等を控える。保存データを消さない。
2. 同じパスの`index.html?debug=2`へ移動し、バッジ表示を確認する。専用セーブが初期状態でも正常。
3. 必要ならタイトルの試験用解放ボタンを使用。M04／WING／A-01,S-02／STANDARDで正式に出撃する。
4. 被弾反応がありHPが減らないこと、FLY/HOLD＋移動＋射撃、ポーズと再開を確認する。
5. 砲台→左右装置→コアを実射撃で撃破。崩壊→リザルト→司令部→M05選択→出撃後に移動・射撃する。保持入力中と解放後の撃破も比較する。
6. リロード後もdebug=2のままで専用のM04記録・M05解放が残ることを確認する。ミッション途中の戦闘位置復元は既存仕様外。
7. 通常URLへ戻し、控えた正式記録が試験結果で書き換わっていないこと、被ダメージとバッジ非表示を確認する。
8. `debug=1`の既存LAB、`debug=0`、`20`／`02`／`true`／`2abc`を確認。844×390／780×360／390×844でバッジ・操作・試験用解放へ到達できることも確認する。

再発時は既存の「遷移診断」を表示・コピーする。C3は元の実機停止症状が解消した証明ではない。iPhone実機・人手通常攻略・実FPSは別途受入が必要。[今回の結果](../reports/url-invincible-debug/README.md)。
