# Version 0.1.4 — MASS INVASION

## 保存・適用

`DENSITY_MODES` はLIGHT30 / STANDARD50 / MASSIVE100。装備画面から `settings.enemyDensity` を保存する。既存のlocalStorageキーと形式v2を継続し、v1/v2で値がない、または不正な場合はSTANDARDを補う。ステージ・武器・装備の記録は移行を伴わず維持する。

ミッション開始時に `game.density` と `enemyLimit` を固定し、リトライは新しい設定を読み直す。実行中に保存設定が変わっても当該ミッションの上限は変えない。HUDはモード名と `HOSTILES 生存数/上限` の2行のみ追加する。TITLE・ポーズ・仮想パッドの操作は維持する。

## SpawnDirector

`js/invasion.js` に実装。M01の発動定義は `M01_ENCOUNTERS`、パターン既定値は `SPAWN_PATTERNS`、調整値は `INVASION` にある。

| 方式 | 動作 | M01での使用 |
| --- | --- | --- |
| WAVE | 小バッチを指定間隔で投入 | 使用 |
| SWARM | 大バッチを短い間隔で投入 | 使用 |
| PINCER | 同じ投入で前後の出現側を交互にする | 将来用定義のみ |
| AIR_RAID | 高度を分散した飛行群 | 将来用定義のみ |
| REINFORCEMENT | 生存雑魚が上限の指定割合以下なら補充 | 将来用定義のみ |

イベントはID、開始X、終了X、パターン、敵種、総数または上限に対する割合、バッチ数、間隔、固定位置、発動条件を持つ。通常イベントの固定数は0.6/1/2倍、割合指定は選択上限を掛ける。中ボスは1体固定でスケールしない。

- 上限に達したら出現済み数を進めず待機する。倒した枠へ次のバッチを投入する。
- 終了Xを過ぎた未出現分は終了する。出現済み敵の削除や転送には使用しない。
- 進行方向のカメラ端より36px以上外、かつプレイヤーから180px以上離れた場所へ配置する。ワールド端で安全距離を確保できなければ待機する。
- 群れは12列・23px間隔を基準にずらし、地上敵は地面上、天井敵は高度28〜40px、飛行敵は35〜97pxへ配置する。M01の既存足場は変更しない。
- 中ボス出現までは通常イベントの上限を1枠減らし、X1980で中ボスを確実に出す。進行ゲートX2150を維持する。
- 中ボス戦の新規投入上限は、生存敵合計で護衛6/8/12体＋中ボス1体。既存雑魚が多い間は追加しない。
- ボス開始時は従来どおり通常戦から切り替える。召喚雑魚は8/12/18体以内、プレイヤーとの距離90px以上を確保し、酸弾・召喚・突進の選択と基本パターンは維持する。

## 群れ・攻撃制御

- 各雑魚の速度へID由来の±10%のばらつき、アニメーション位相・射撃待ち時間へ差を付ける。HP・攻撃力は変更しない。
- 64pxの空間グリッドで、26px以内の同種近隣のみを集計する。分離速度は横18px/s、飛行敵の縦12px/sを上限とする。全個体の分離量を計算してから移動へ適用する。
- 至近距離の地上群はIDごとに0〜56pxの接近停止距離を分散し、その手前32pxから接近速度を連続的に落とす。全員がプレイヤーの一点へ収束するのを避け、近隣分離が働く余地を作る。中ボス・ボスへ通常分離を適用しない。
- 通常射撃は0.24秒以上空け、0.5秒窓で最大2回開始、通常敵弾は最大28発。許可されなかった敵はIDに応じて再待機する。ボス・中ボス弾はこの制限から独立する。
- 飛行敵の急降下は開始間隔0.35秒、同時2体、継続0.8秒、個体別クールダウン2.4〜3.4秒。高度・軌道・開始位相を分散する。

## 負荷・整合性

- グリッドを近傍分離、弾、爆発、連鎖候補の取得で共有する。候補を絞った後のダメージ計算・貫通回数・爆発半径は既存値を使う。
- ホーミングと連鎖の対象選択から毎回の配列コピー・ソートを除き、走査で選ぶ。敵・弾・エフェクト配列はその場で詰め直す。
- 900pxより遠い飛行・天井敵の軌道計算は0.12秒単位。移動、生存、寿命、衝突候補は継続し、画面外へ出た敵を前方へ転送しない。
- 弾はカメラ外という理由で消さず、寿命とワールド外判定を使う。画面外の敵にも命中する。
- 描画のみ視界外を省略する。通常エフェクト80個、死亡スプライト16体まで。死亡音も0.05秒以上空ける。制限は演出だけで、撃破数・得点・ドロップ・ダメージを省略しない。
- 現段階ではオブジェクトプールは追加せず、グリッド／候補配列の再利用・配列圧縮・演出制限を使用する。実機計測でGCが問題となる場合は弾・演出のプールを次に検討する。
- カメラ倍率0.35〜0.85、敵なし0.50、評価半径600px、ボス専用構図は維持する。

## 計測方法

`npm run benchmark` は実際のゲーム更新処理をNode上で動かし、240更新のウォームアップ後に1200更新を計測する。音声なし、Canvasは空実装で、表示FPSを測るものではない。通常射撃と2秒ごとの爆発バーストを、密度上限まで補充しながら測る。

`?debug=1` のBENCHボタンは実際のCanvas描画を含めて6秒間測る。指定個体数を補充し、平均FPS、最も遅い1%のフレーム間隔から求めるFPS、同期CPU処理時間の平均・95%点・最大値を `canvas[data-benchmark]` と画面へ出す。音声は計測中のみ抑制する。ブラウザの描画間引きや遠隔観測の影響と、ゲームのCPU処理時間を分けて解釈する。
