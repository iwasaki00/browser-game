# 1.2.0-C2 — BOSS DEFEAT & SORTIE TRANSITION

## C4追記：M-20更新中の弾配列消去

C3実機診断の`expanded`参照例外は、`js/weapons.js`の拡張弾ループ中、M-20がB-04を倒し`game.shots.length=0`となった後、保存済みの変更前件数でループを続行することが原因だった。実機ログと同じHP1→-34、保存成功→例外の経路を隔離Nodeで再現した。

C4では当初件数の上限に加え、現在の弾配列長も継続条件にする。例外を握りつぶしたり、弾・武器ダメージやボスHPを変更したりしない。詳細は[C4レポート](../reports/projectile-completion/README.md)。C2のRAF保護・保存と崩壊の分離・入力解除、C3の専用セーブは維持。以下はC2時点の調査履歴で、C4の特定済み原因と未確認範囲は追記を優先する。

## 確認済みの原因と未確定事項

実機のM04→M05出撃不能そのものは未再現。Safariの実セーブ・実機コンソール・今回の画像ファイルにはアクセスしていない。C1のNode成功を実機成功へ置き換えない。

C1（履歴`7c36f7f`）へ描画例外を1回注入すると、末尾の`requestAnimationFrame(loop)`へ到達せずRAF予約が増えなくなる。一方、documentのクリックハンドラーは残るため、結果→司令部→M05→出撃で`state=play`・M05初期化はできても、その後の自動更新がない状態を再現できた。**停止機構は再現済みだが、実Safariで発生した例外の種類・発生元は未確定**。

C2はRAF用の入口`animationFrame()`で更新・描画例外を採取し、次フレーム予約を維持する。例外が発生した戦闘は入力解除・ポーズ・警告表示とし、途中適用された更新を自動再試行しない。失敗後の描画は保留し、再開・新しい正式出撃時にCanvasの描画状態を初期化する。速度・60Hz累積更新・カメラ計算は変更しない。永続エラーなら再びポーズと診断になるため、無条件に成功扱いにはしない。

## 出撃診断

既存C1の遷移診断を、次の出撃まで保持する。最大64イベント（C1の24件から拡張）。リング外へ古い記録が落ちるため、複数ミッション全履歴の保存ではない。

| イベント | 意味 |
| --- | --- |
| mission-prepare-request / equipment-ready | 司令部からの対象選択・装備画面準備 |
| sortie-request / accepted / rejected | 出撃操作の受付、可否と拒否理由 |
| initialization-start / done / error | ミッション初期化の進捗 |
| frame-enter / frame-ready / frame-error | RAF入口、初回処理完了、更新／描画例外 |
| store-ok / store-failed | 通常セーブ書込の成功・失敗 |
| boss-low-hit / boss-defeated | 撃破直前の実ダメージと撃破確定 |

スナップショットは現在画面、選択ミッション・兵科・武器、HP・EN・座標、入力所有数、タイマー数、RAF回数／時刻／エラー状態、解放状態・保存失敗有無。個人情報や端末のローカルパス、セーブ全文、秘密情報は独自に収集しない。例外本文は180文字まで。外部送信なし。

通常診断は専用`sessionStorage`キー`pdf-result-transition-v1`を使い、通常進行のlocalStorageへ追加しない。LABのボス直前試験はメモリだけの別記録とし、通常診断アーカイブも上書きしない。保存制限時は診断保存だけを断念する。タブ終了・OS側の破棄では記録が失われ得る。

ポーズ・結果・司令部・装備画面、LABステージタブの「遷移診断」→「診断を表示・コピー」。クリップボード不可ならreadonly欄を長押しコピー。出撃できないときは、装備画面のログが`sortie-request`まで届いているか、拒否／初期化／frame-readyのどこで止まるかを確認する。

## B-04の撃破表示

C1のB-04は通常死亡表示の約0.48秒（演出レベルで延長）と、結果確定待ち1600msが一致せず、死亡画像が先に消えることを実更新で確認した。C2はこの短い通常死体表現からB-04を分離する。

| 状態 | 処理 |
| --- | --- |
| ALIVE | 既存のHP・装置・Phase・攻撃を維持 |
| DEFEAT_CONFIRMED | 実ダメージでHP≤0、攻撃停止・入力解除・撃破を一度だけ確定 |
| DEATH_ANIMATION | 約2.8秒。装甲周辺の連続爆発→コアの局所発光・亀裂→大きな既存爆発→沈降・フェード |
| RESULT_READY | 終了タイマーまたはスキップで一度だけ結果表示 |

通常M04のクリア・報酬・解放・保存は撃破確定時に実行し、装飾の完了を待たない。記録されるクリア時間も撃破確定時点。保存失敗時は既存の未保存警告と保存だけの再試行を維持する。結果表示のタイマーは更新／描画とは独立し、演出中にポーズ・描画例外・音声失敗があっても作動する。タイマーはページ破棄・ブラウザ停止の影響まで保証するものではない。

専用スキップボタンは同じ終了関数を呼ぶだけで、クリア条件や報酬処理を呼び直さない。遅れて発火するタイマーもfinishedガードで無害。次の出撃で実行時のボス演出・タイマー・弾・入力は破棄する。新しいPNG・音声素材は作らず、既存のB-04／爆発／Web Audioを再利用。追加破壊FXは最大16回＋最終爆発1回、既存のFX全体上限も適用。

B-04の全8フレームPNGは存在し、idle／hit／open／damagedの描画元矩形も範囲内。hitフレームは小さな明色アクセントで、本体全体を白矩形へ置き換えてはいない。攻撃予兆には仕様上の半透明矩形がある。実機画像の矩形がこれらのどれかは未確定。**生存中の消失まで修正済みとは報告しない**。

B-01〜03・05〜08の既存の演出時間・最終崩壊・エンディングは置換しない。RAF例外時の保護・新出撃の初期化・診断だけは共通。B-08にB-04用演出を二重再生しない。
