# CAMPAIGN COMMAND / Version 0.8.0

## 0.8.0の拡張

司令部はミッション／兵科戦績／武器コレクション／実績の4タブ。既存出撃導線は変更しない。「実績」には30件の一覧・詳細・進捗、カテゴリと達成状態フィルター、おすすめ最大3件を追加。バッジ・称号コレクションで取得済み称号を選択すると、司令部フッターのプロフィールへ表示し保存する。

実績マスタと評価処理を分け、既存CampaignRunへChallengeRunを合成する。正確な0.7統計を再利用し、旧履歴の特殊条件は推測しない。LAB／QAからの記録は一切混入させない。通知はゲームや保存から独立し、上部で約3秒・1件ずつ、×でスキップ可能。

[30条件・保存スキーマ・イベント・変更ファイル](CHALLENGE_OPERATIONS.md) · [0.8.0確認結果](../reports/challenge-operations/README.md)。以下は0.7.0から引き継ぐ基礎仕様で、3タブの記述は当時の構成を示す。

## 0.7.0時点の画面と出撃（基礎仕様）

タイトルの `MISSION START` / `CONTINUE` → キャンペーン司令部 → 出撃準備 → 従来の兵科・2枠装備画面 → 出撃。ミッション選択は従来の `canPlayMission` を再利用し、ロック中／未実装ミッションを開始しない。

| タブ | 内容 |
| --- | --- |
| ミッション | マスタ全件の一覧、状態、記録、初回報酬、同一画面内の詳細、プレビュー、出撃 |
| 兵科戦績 | 4兵科の累積記録、折りたたみ式のミッション別最高記録 |
| 武器コレクション | マスタ全武器のアイコン・解放状態・性能・使用記録、名前／ID検索、カテゴリフィルター |

一覧と詳細だけを内部スクロールし、タブ・進行率・戻る／出撃を固定。横画面は一覧／詳細の2列、縦画面は上下2段。Tab、Enter、Spaceに加え、タブ上の左右キー／Home／Endでタブ移動可能。武器コレクションは閲覧専用で、解放や装備を変更しない。

進行率は `MISSIONS.filter(m => m.implemented)` のクリア済み数÷件数。現在6ミッション、M07はCOMING SOONとして一覧に出すが分母には含めない。次の目標は解放済み・実装済み・未クリアの先頭。武器取得率も `WEAPONS` の実件数と既存の `unlocked` から計算する。固定の6／20やダミー記録は使用しない。

## 過去分と0の区別

- 従来の `clearedMissions` / `missionStats` / `unlockedMissions` / `unlocked` をそのまま参照。全体の最高スコア・最短時間も維持する。
- 統計追加前の兵科・武器履歴は推測しない。行そのものが存在しない場合は「未記録」、正式出撃などで行を作った後の0は「0」。
- 旧セーブは `legacyUnrecorded: true` とし、画面下に「過去分未記録」を明示する。
- スコア／時間の旧既定値0は有効記録とはせず「記録なし」。有効な既存値は従来どおり表示。
- 旧クリア履歴だけでは初回報酬の取得イベントを確定できないため「過去分未記録」。0.7.0以降の正式な初回クリア時のみ取得フラグを記録。再クリアで過去分を推測したり追加報酬を付けたりしない。

## 累積データと定義

既存の保存キーと `version: 2` を維持し、次の任意フィールドを追加する。

```json
{
  "campaignStats": {
    "schemaVersion": 1,
    "sinceVersion": "0.7.0",
    "legacyUnrecorded": true,
    "classes": {},
    "weapons": {},
    "firstRewards": {}
  }
}
```

| 格納先 | フィールド | 定義 |
| --- | --- | --- |
| classes[classId] | sorties | 初期化に成功した正式通常出撃の回数。リトライは新しい出撃 |
| 同上 | clears / gameOvers | クリア確定／HP0確定。途中終了はどちらにも加算しない |
| 同上 | kills | 死亡確定したE-/B-敵。砲台・装置・ノード・外殻・ネスト等は除外 |
| 同上 | playSeconds | 前景・フォーカスあり・生存中の固定ステップ実行秒。ヒットストップを含み、ポーズ・非表示・ゲームオーバー後・ボス崩壊演出を除外 |
| classes[classId].missions[missionId] | highScore / bestTime | その兵科による正式クリア時の最終スコア／ミッション時間。既存全体記録とは別 |
| weapons[weaponId] | equipped | 出撃時に装備した回数。2枠に同じIDがある場合も1出撃1回 |
| 同上 | uses | 受理された発射／設置操作。散弾・分裂・時間差攻撃は親操作1回 |
| 同上 | hits | 防御処理後、正のダメージが実際に適用された回数。空振り・無敵・死亡済み対象は除外 |
| 同上 | placements | マイン／タレットの設置成功回数。上限等で拒否された設置は除外 |
| 同上 | detonations / minesDetonated | 起爆した操作回数／実際に起爆したマイン数。設置と別集計 |
| firstRewards[missionId] | true | 0.7.0以降に初回クリア報酬の処理が確定したもののみ |

実働時間は壁時計時間ではない。ブラウザ停止による未実行秒を後から足さない。ミッション最短時間は既存 `game.time` の定義を変更しない。

命中数は「撃った弾のうち何発当たったか」ではなく有効ダメージ適用回数。範囲・継続・連鎖攻撃は使用数より命中数が多くなる。従来ロケットの直撃＋爆風など、既存処理がそれぞれダメージを与える経路はそのまま記録し、統計のためにダメージを省略・追加しない。タレットの自動射撃は使用／設置を増やさず、実際の有効命中のみ増やす。

武器IDは発射元データの `weapon.id`、明示的な `weaponId`、有効な `assetIndex` のみを使用。汎用的な `bullet` などからアサルトへ推測しない。固定対空砲台等の武器ID不明な攻撃は武器統計に帰属しない。撃破寄与／アシストは未対応と画面に明示する。

## イベント・保存・隔離

- `js/campaign-stats.js` の `CampaignRun` を、成功した通常 `startMission` の末尾でのみ生成。兵科とミッションは出撃時に確定する。
- 発射成功、既存ダメージ確定、既存死亡確定、結果確定に小さな記録処理を接続。戦闘・当たり判定を作り直さない。
- 死亡は既存 `dead` ガード＋ラン単位WeakSet、終了は `closed` フラグで二重加算を防止。再描画・タブ移動・ポーズで出撃を増やさない。
- メモリ上の累積値を、出撃・結果・画面離脱／ポーズ・再挑戦／終了・pagehide／visibilitychange・実働10秒ごとに保存。弾や命中ごとのlocalStorage書き込みはしない。
- 既存セーブ全体を1回の `setItem` で保存。保存失敗は司令部へ警告し、dirty状態を残して再保存可能にする。OS強制終了等でpagehideが実行されない場合、最後の保存以降の統計は失われ得る。localStorageの永続保証はしない。
- 保存時のデータ参照は最新 `save` を使う。既存クリア処理がサニタイズでセーブオブジェクトを交換しても新しい結果へ集計する。
- 非負有限値・上限MAX_SAFE_INTEGER、既知マスタIDだけへ正規化。個々の射撃／撃破ログは保存せず、容量は兵科×ミッションと武器件数に比例する累積値だけ。
- `labOnly` 起動には通常ランを作らない。後からLAB状態を付けるチェックポイント初期化中も加算しない。通常攻略QA・ボス直接開始・自由配置・BENCHは全て除外。LABでの記録操作・結果・pagehideでも通常保存内容は不変。

## 戦場プレビュー

既存素材のみを320×180の別Canvasへ描画。M01市街／M02地下／M03港湾とスカイレイ／M04空中要塞／M05荒野と移動基地／M06神経中枢を再利用する。単純なフレーム選択・短い移動だけで、敵AI・衝突・報酬・音声は動かさない。

描画は最大10回/秒。ミッションタブ以外・司令部以外・document非表示では更新しない。チェックOFFまたは `prefers-reduced-motion: reduce` は静止画。未読込・素材なしは単色の安全な静止背景へフォールバックし、読込完了時だけ再描画する。新しいPNGや動画は追加しない。

## 拡張手順

1. ミッション／武器の既存マスタを追加。実装済みフラグと既存解放ロジックを設定。
2. 一覧・進行率・取得率・戦績の既知IDは自動追従。M07が実装されたら分母へ入る。
3. 必要に応じて `MISSION_BRIEFINGS` とプレビュー資源マッピングを追加。未定義時はマスタ説明文／静止背景へ安全に退避。
4. 過去の兵科・武器統計を移行時に推測しない。
