# GAMEPLAY POLISH — Version 0.3.2

## 範囲と調査結果

M01〜M03の表示・入力・短い合成音・結果表示を改善する。新ステージ・武器・敵・素材は追加しない。既存の武器属性FX、吹っ飛び、回転、破片、残像、連続撃破表示、ヒットストップ、LEVEL 1〜3を再利用する。

- B-01には正式な弱点倍率が存在しない。弱点を新設せず「ARMOR」と表示する。
- B-02/B-03は既存の弱点座標・開閉条件・1.5倍補正を使い、実際に補正された命中だけをWEAK POINTとする。
- 旧HUDはミッション・兵科ごとに重複し、下段ボスHPとタッチ操作が重なっていた。共通HUDに統合する。
- タッチ入力は単一booleanだったため、指ごとの所有権、キャンセル・回転時の解除を追加する。
- 既存Web Audioの発振器数が無制限だったため、同じ合成方式の上に軽量な上限管理を追加する。
- 旧クリア見出しは全ミッションで市街地向けだったため、実際のミッション名を使う。

## 命中・撃破

| 分類 | 判定と表示 |
| --- | --- |
| HIT | 通常命中。武器属性の火花・短い命中箇所の明滅 |
| ARMOR HIT | 既存の装甲・甲殻系の型。灰青色の小片を加える。新しい減衰補正はしない |
| WEAK POINT | B-02/B-03の既存弱点補正が適用された命中。弱点座標に明るい小さな十字 |
| FINISH | HPが0以下になった一撃。既存の死亡物理・コンボ表示と同期。deadガードで重複加点しない |

`js/impact.js` のFEEDBACK定数で、対象ごと55ms、明滅90ms、全体100msあたり12個（LAB200では6個）に抑える。これは描画・命中音のみの制限で、全命中のダメージは適用する。武器ごとの色・弾道・爆風方向・死亡LEVELは維持する。HIT省略数と分類別件数をLAB JSONへ含める。

### 既存の上限を維持

| 対象 | 上限 |
| --- | --- |
| FX | 80個 |
| 破片 | 通常96個／LAB200時48個 |
| 同時爆発描画 | 8個／LAB200時4個 |
| 死亡状態 | 256体。描画の詳細化は既存上限、超過分も簡易死亡表示 |
| 残像描画 | 32個 |
| 揺れ | 最大6.4ワールドpx、0.18秒、再発動間隔0.24秒。画面揺れOFFを尊重 |
| ヒットストップ | 強攻撃33ms、複数撃破25ms、1秒中66msまで |

## ボスとHUD

- 上段左：兵科、HP現在/最大とバー。WINGはEN、SCOUTはDASH待ち時間。他兵科は短い通常／NO SAVE表記。
- 上段右：Mxx・Axx・敵数（3桁）・時間。両武器枠を常時表示し、使用中の枠を金色と下線で示す。
- ボス戦のみ右上HUD直下にHP現在/最大とバー、CORE OPEN/CLOSED（B-01はARMOR）。下段の操作ボタンと分離する。
- B-02/B-03の弱点は画面座標へ投影し、倍率0.35でも最低7pxの角マーカーを表示。揺れの描画オフセットを含める。実際の弱点半径は不変。
- HUDは320×180の画面座標で描き、ワールドズームや揺れで動かさない。LAB640でも同じ論理座標。LAB計測・開閉表示をHUD下へ移す。
- B-03の予兆1.25秒・波の攻撃後猶予5.25秒、予兆と攻撃位置のロックを維持する。
- スクリーンリーダー向けに同じ戦闘状態を非表示outputへ出力する。aria-liveはOFF、戦闘中は0.25秒ごと、兵科切替・画面切替は即時更新する。

## タッチ入力

指ごとにpointerIdを保持。移動＋JUMP/DASH/FLY/HOLD＋FIREを並行操作できる。同じ移動キーを2本で押した場合も、片方の解除だけでは離さない。FIREとSWにも所有者を設ける。

- pointerup / pointercancel / lostpointercaptureで解除。
- 回転・向き変更・フォーカス喪失・LAB表示・ポーズで全入力／長押しタイマー／押下色を解除。
- SWは既存どおり、マインなしは即切替、設置中は短押し切替／長押し起爆。キャンセルでは起爆・切替しない。
- 押下色・枠・内側ハイライトを追加。操作面は44CSS px以上、横表示は左右グループに余裕を取り、FIREは92×78px。
- safe-area、visualViewport、portraitの既存2段構成は維持する。
- `touch-action:none`はCanvas・仮想パッドに限定。ページ全体のuser-scalable禁止を撤去し、設定・LABのスクロールとテキスト入力を妨げない。

実機の複数指操作感・ホームバー周辺・Safariツールバーの伸縮は未確認。Chromeの指定サイズは実機Safariの代わりにはならない。

## Web Audio

`js/combat-audio.js`は既存の発振器＋Gainによるローカル合成音を管理する。外部API・音声ファイルは使わない。

- ユーザーのクリック・キー・パッド操作で初めてAudioContextを作成し、suspendedならresumeを試みる。戦闘イベントから自動作成しない。
- resume拒否・未対応・音源生成失敗は捕捉し、無音でプレイ継続。
- 同時8音、1秒あたり24音まで。命中種類ごと65ms、弱点100ms、大型撃破200msの最小間隔。
- 通常命中は小音量、装甲・弱点・大型撃破・クリアは短い音色差。既存射撃・メニュー音も同じ全体上限に含める。
- onendedとAudioContext時間ベースの掃除で発振器／Gainを切断。ミュートで停止。既存settings.sound / volumeを維持、音量0は完全に発音しない。
- BENCHは既存どおり音声OFF。BENCHの結果だけで実音声付き負荷を評価しない。

## 結果

通常クリアはM01〜M03共通。ミッション名、兵科、時間、スコア、撃破数、武器箱、既存クリア報酬、道中の武器箱を含む今回の新規武器、実装済みの新しい挑戦可能ミッションを表示する。

M01初回L-03、M02/M03の武器箱、未所持優先、全所持時の既存代替スコアをそのまま使う。重複クリア呼出しは既存clearガードで無効。新ランク・新報酬・セーブ項目は追加しない。新規武器一覧はミッション中だけの一時配列。

GAME OVERはミッションID、兵科、到達エリア番号・名称、時間、撃破数、スコア。既存の再挑戦・ミッション選択・タイトル操作を利用する。LABはQA/NO SAVEを維持し、ボス撃破は通常報酬でなくMISSION REPORTへ進む。

見出し演出は220ms、タップ・キーで省略可能。操作ロックは設けず、prefers-reduced-motionも尊重する。背の低い横画面の結果は2列、本文は既存の内部スクロールを利用する。

## 第5プリセット「通常攻略QA」

`?debug=1` → TEST LAB → クイック設定を開く → 「通常攻略QA（初期武器・無敵なし）」→ **表示された設定を適用（再開始なし）**。

適用すると正式兵科を維持（実験性能の場合RANGERに戻す）、HP/ENを通常値へ補充、無敵OFF、A-01/S-02、使用枠1、QA:B、次の開始密度STANDARD。撃破演出・アート・解像度・カメラはそのまま。現在の位置・敵・時間・スコアは維持し、現在密度も途中変更しない。

「ステージ」でミッション／エリアを選び、**選択地点から開始**を実行してSTANDARDの通常被ダメージ環境を作る。開始後は兵科・武器・無敵などの変更履歴を記録する。JSONのstartedWithGameplayQAは開始時のプリセット使用、gameplayQAは現在も正式兵科・無敵OFF・初期装備・STANDARDかを示す。途中開始はCHECKPOINT_ONLY、通常正式クリア認定は常にfalse。

5タブ・既存4プリセット・20武器リストは維持。通常装備・武器解放・進行・報酬・設定へ一切保存しない。

## 計測と確認手順

「計測」には従来のRAFフレーム間隔・更新／描画CPU・敵／弾／FX／死亡に加え、破片数・揺れ・音声数・省略数を表示。JSONのresourcesに現在値／LABセッション内ピーク・音声状態を含める。数値はLAB用でセーブしない。

1. 50/100/200体を同じ条件で生成。LEVEL1〜3、R-04/G-07、密集／分散を切替。
2. FPS表示をONにし、LABを閉じて画面を前景のまま操作する。音付き試験はBENCHとは別に行う。
3. ウォームアップ500ms後、連続30サンプルかつ有効500ms以上の区間のみ採用。非表示・フォーカスなし・操作停止・250ms超の間隔は除外する。
4. 最低10〜20秒の前景プレイ後、F2／LAB→計測→JSONコピー。RAF、CPU、FX数、粒子、揺れ、音声ピークを別々に比較。
5. 有効0や中断理由が出る場合はFPSを計算しない。同じ自動ブラウザ停止を何度も再試行しない。iPhone Safari実機の人手測定へ切り替える。

実施結果とCPU参考値、ブラウザ画像：[検証レポート](../reports/gameplay-polish/README.md)。無敵なし全編の人手クリア、Safari音声とタッチの実操作、実機FPSは未確認。
