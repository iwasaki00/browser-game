# CHALLENGE OPERATIONS — Version 0.8.0

## 目的・操作

キャンペーン司令部の4タブ目「実績」で、達成率・カテゴリ・状態フィルター、独立スクロールの一覧と詳細、おすすめ最大3件、バッジ・称号を確認する。称号は詳細側の「バッジ・称号コレクション」から選択し、司令部フッターのプロフィールへ表示する。未取得称号は無効。戦闘性能・スコア・解放・武器報酬に効果はない。

通常の出撃導線は `MISSION START → ミッション → 出撃準備 → 兵科・武器 → 出撃` のまま。PCではTab／Enter／Space、司令部タブでは左右／Home／Endが使える。横画面は一覧／詳細を左右に、縦画面は上下に配置する。30件の全体を縦に伸ばさず、中央だけスクロールする。

## マスタ・過去判定

マスタは `js/achievement-master.js`、判定と一時出撃状態は `js/challenges.js`、表示は `js/challenge-ui.js`。IDは公開後に変更しない。各定義にはカテゴリ・説明／条件・目標・判定方式・過去判定区分・難易度・バッジ・称号・表示順・実装状態・非表示条件を持つ。

- A：既存の正式ミッションクリア／武器解放から判定可能。
- B：正確な0.7.0の兵科・武器統計だけを利用。B01は保存済みM05/M06の撃破ベストにも確定根拠がある場合は利用する。
- C：0.8.0以降の正式出撃が必要。旧クリア、装備、最高スコア、武器所持から特殊条件を推測しない。
- 兵科のクリア記録がない旧セーブから兵科勝利を割り当てない。0.7.0の実在する兵科別クリア行は正確な根拠なので利用する。
- 「全20武器」「M01〜M06全クリア」は固定対象のスナップショット。M07／21番目の武器が追加されても条件・達成状態を変更しない。キャンペーン本体の動的分母とは別。

## 確定イベントへの接続

`ChallengeRun` を既存 `CampaignRun` に合成する。通常出撃成功時だけ生成し、別のゲームループや敵AIを作らない。

| 既存イベント | 記録 |
| --- | --- |
| 通常出撃の初期化完了 | ランID、ミッション・兵科、開始HP、空の使用武器Set・撃破・被ダメージ・ボス履歴 |
| 固定ステップの正式な実働時間 | 連続撃破用のactiveTime。0.7.0の前景・フォーカス・生存ガードを再利用 |
| 発射／設置成功 | 使用武器Set。使用種類数は0.7.0の武器使用統計を参照し、装備だけでは増えない |
| マイン起爆成功 | M-18の実使用。設置と同一IDなので種類数は二重に増やさない |
| 敵の死亡確定 | 既存のdead／WeakSetガードを通ったE-/B-だけ。1出撃撃破・連続・0.8累計へ記録 |
| 被ダメージ処理後 | 軽減後の実HP差。無敵で無視された攻撃は0。回復しても履歴は消さない |
| B-05部位破壊処理後 | ボス戦のleft/right装置だけ。対象WeakSet＋種類重複防止で順序を確定 |
| B-06ノード処理前後 | `shielded: true → false` の確定遷移だけを数える。露出中の連打・通常ネットワークノードは数えない |
| 正式GAME OVER | 同一ミッションIDの敗北フラグを保存、ランを閉じる |
| 正式クリア | 現在HP・実使用武器・累積被ダメージ・ボス履歴を判定、既存兵科記録と合わせて解除 |
| 中断／終了／再挑戦 | ランを閉じて連続撃破状態を破棄。再挑戦は新しいラン |

同じダメージや報酬処理をもう一度実行しない。0.7.0の累計撃破はそのまま維持し、0.8.0累計1000体用だけ新しいカウンターを持つ。撃破・クリアの二重加算は既存ランガードと `completionState` で防ぐ。

### 特殊条件の補足

- 初期装備条件はA/Sのどちらかを最低1回使い、他の武器を一度も使わないこと。0回の空集合は達成にしない。
- 装備や武器切替だけでは失格にしない。成功した設置・起爆も実使用とする。
- S05は兵科ごとの最大HPで計算。GUARDIANなら50/200以下。0HPはクリア対象にしない。
- 連続撃破は「全撃破を5秒以内」ではなく「次の撃破まで5秒以内」。境界5秒を含み、超過すると1から再開。ポーズ・非表示・未実行時間を除外する。
- T01は装置を両方破壊して通常クリアした出撃だけを左先行／右先行へ登録。途中敗北・破棄は履歴を追加しない。
- T02の進捗は通常クリア時に保存された最高露出回数。現在出撃中の一時回数を過去達成として保存しない。
- T03の敗北フラグはページ終了後も保持し、違うミッションのクリアでは達成しない。

## 進捗・おすすめ

取得済み／使用済み武器数、既知の兵科勝利、1出撃の最高撃破、最高連続、0.8累計撃破、クリア済み破壊順序数、クリア時の最高露出数を表示する。ラン一時値と保存された最高値を混同しない。

根拠がない値は `null`／行なし→「未記録」。観測できた0と未達成を区別する。進捗バーは目標以下に制限し、解除済みのバーは100%。解除済みIDは後から条件が変わっても削除しない。

おすすめは未解除から最大3件。判定可能な到達済み条件、進捗比、解放済みミッション、未使用兵科／武器、現在ミッションへの対応を優先する。未記録を「あと1回」等へ変換しない。おすすめを押すとフィルターを解除し、その実績と詳細へ移動する。

## 保存と互換性

保存キー `pixel-defense-front-save-v1`、既存セーブ `version:2` は変更しない。任意フィールド `achievements` を追加。

```json
{
  "achievements": {
    "schemaVersion": 1,
    "sinceVersion": "0.8.0",
    "unlocked": {},
    "selectedTitle": null,
    "totals": {"runs": 0, "kills": 0, "bestRunKills": 0, "bestStreak": 0},
    "observed": [],
    "completed": [],
    "b05Orders": [],
    "failedMissions": [],
    "coreExposures": null
  }
}
```

- `unlocked` はID→達成日時のUnixミリ秒。UIの日付はUTC。`selectedTitle` は称号付き実績IDかnull。
- `observed` は新規クリアで判定できた特殊条件、`completed` は成功した特殊条件の根拠。未観測と不成立の0を区別する。
- ランのSet、個々の射撃・死亡・部位イベントログは保存しない。マスタ自体も保存しない。
- 数値は非負有限値・MAX_SAFE_INTEGER以下、日時はDateの有効範囲、配列は既知ID・重複除去。未知称号や未取得称号はnullへ戻す。
- 既存のクリア／解放／装備／設定／スコア・時間を削除しない。初回読込時のA/B判定は静かに保存し、大量通知しない。
- 通常は0.7.0の周期・出撃終了・ポーズ・pagehide保存へ合流。新規解除時だけ追加の保存境界とする。射撃／命中ごとの同期保存はしない。
- 保存失敗時は既存の警告・dirty再試行を利用。OS強制終了等では最後の保存以降が失われ得る。localStorageの永続保証はしない。

## 通知・バッジ・称号

通知は保存／判定と別の `AchievementNotices`。既知IDだけ・一度だけキューへ入れ、1つずつ約3秒表示、×でスキップ可能。ポーズ・確認・設定・装備・LAB・非表示・フォーカスなしでは表示と進行を止める。前景のリザルトでも表示できる。

通知は画面上部のTITLE／SOUND間の領域へ置き、戦場Canvas・HUD・仮想パッドを動かさない。表示処理が失敗しても解除済み保存は巻き戻らない。実績通知の専用音は追加せず、ミュートやSafariの音声起動制限に新しい依存を作らない（従来のUI操作音のみ既存設定を尊重）。

CSSのピクセル状バッジを6カテゴリへ割当：盾／階級章／照準器／爆発星／勲章／作戦記号。未達成は低彩度・暗色、達成すると本来色。外部素材・PNG生成・既存アート上書きなし。

取得可能な5称号：地球防衛の英雄、四兵科の指揮官、武器マスター、無傷の帰還者、神経遮断の達人。称号なしにも戻せる。通常の戦闘計算は称号を参照しない。

## TEST LAB隔離

LAB用のミッション開始には `CampaignRun`／`ChallengeRun` を作らない。設定を後付けする初期化途中でも通常ランを生成しない。撃破・被弾・射撃・クリア・ノード・装置イベントには `normalCampaignRun` の既存ガードを使用する。自由配置／指定開始／無敵QA／通常攻略QA／BENCHの実績・日時・通知・進捗は通常保存へ反映しない。

初回読込で正当な既存保存記録から行う静かな移行はLABの戦闘結果とは別。LAB5タブを維持し、実績検証用の新しいLABタブや通常画面の開発UIは追加していない。
