# ドット防衛戦線 — PIXEL DEFENSE FRONT

Version 0.1.5 — DEBUG PLAYGROUND。ビルド不要で動く、オリジナルの8bit風横スクロール防衛アクションです。

## 起動

リポジトリのルートで静的HTTPサーバーを起動し、`031_ファミコン風地球防衛軍/` を開きます。

```powershell
py -3 -m http.server 8000
```

## 操作

- PC：A/Dまたは左右キーで移動、W/上/Spaceでジャンプ、マウスで照準・射撃、Q/E/Shiftで武器切替、Esc/Pでポーズ
- スマホ：横向き推奨。左側で移動・JUMP、右側で武器切替・FIREを操作します。FIREを押して射撃し、ドラッグで照準方向を変更します。縦向きでも従来のゲーム画面上段・操作面下段の構成でプレイできます。
- 左上の「← TITLE」でゲーム内タイトルへ戻れます。ミッション中は確認を表示し、キャンセルすると継続します。確定すると進行中ミッションを破棄し、取得済み武器とステージ進行記録を保持します。

## モバイル表示

- `portrait` / `landscape` を画面向きから自動判定し、HTMLの `data-layout` に反映します。
- landscape・portrait・PCとも自動ズームです。敵なしは `0.50` 倍、戦況に応じて `0.35〜0.85` 倍（横可視範囲約376〜914ワールドpx）へ滑らかに変化します。背景を含むワールド描画に適用し、HUDは等倍を維持します。
- `100dvh` と `visualViewport.height` を併用し、Safariのアドレスバー伸縮時にもレイアウト高を更新します。
- ヘッダー、操作面、モーダルに `env(safe-area-inset-*)` を適用しています。
- 仮想パッドのFIREは最大132pxの円形操作面とし、狭幅端末向けに104pxまで縮小します。

詳細は `docs/LAYOUT_SPEC.md` を参照してください。

## ダイナミックカメラ

- 600ワールドpx以内のアクティブな敵を、前後それぞれ100px刻みの距離帯へ集計します。画面外も対象ですが、未出現・非アクティブ・死亡した敵は除外します。
- 距離分布、敵数、集団の広がり、進行方向から連続的な目標倍率を計算します。遠方の単独外れ値は影響を弱め、距離帯の境界をまたぐ集団も扱います。
- 評価間隔は0.15秒。0.30秒の安定待ち（敵なしへ戻る際は0.45秒）、0.015の倍率差の無視幅、時間ベースの指数補間で振動を抑えます。
- 進行方向へ少し先を映し、ボス戦ではプレイヤーとボスを同時に収める構図を優先します。ボス中の倍率は初期設定0.35〜0.65で、召喚された通常敵では大きく変動しません。
- 定数は `js/data.js` の `BATTLE_CAMERA`、評価・追従処理は `js/camera.js` にあります。敵密度30〜100体でも同じカメラを使用します。

## 敵密度と大量出現

| モード | 生存敵上限 | 出現数の倍率 |
| --- | ---: | ---: |
| LIGHT | 30体 | STANDARDの0.6倍 |
| STANDARD（初期値） | 50体 | 1倍 |
| MASSIVE | 100体 | 2倍 |

- 装備画面の「敵密度」で選び、`settings.enemyDensity` として同じセーブキーへ保存します。旧セーブはSTANDARDになります。
- 選択は次のミッション開始（リトライを含む）で適用され、進行中のミッションは開始時の設定を保持します。HUD中央に現在モードと生存敵数を表示します。
- M01はデータ定義のWAVE・SWARMを使用します。エリア1で徐々に増加、エリア2で地上群、エリア3で中ボス、エリア4で上限規模の主戦闘、エリア5で既存ボス戦となります。
- 速度±10%・開始アニメーション・飛行高度のばらつきと近傍分離で群れを表現します。通常射撃と急降下の開始を分散し、ボス攻撃は独立管理します。
- 詳細・調整箇所は `docs/INVASION_SPEC.md` にあります。

## ステージ進行とセーブ

- セーブは同じlocalStorageキー `pixel-defense-front-save-v1` を継続使用し、中身を形式バージョン2へ移行します。
- `clearedMissions` にクリア済みID、`unlockedMissions` に解放済みIDを保存します。初期状態はM01のみ解放です。
- M01クリアでM02の解放記録を保存しますが、現在実装済みなのはM01のみです。M02は `COMING SOON` と表示し選択できません。
- `CLEAR` は再挑戦可能、`OPEN` は挑戦可能、`LOCKED` は未解放、`COMING SOON` は未実装を示します。
- GAME OVER、リトライ、タイトルへの復帰、リロードで解放状態は巻き戻りません。GAME OVER画面からミッション選択へ戻れます。
- 旧セーブの `cleared` を引き継ぎ、武器解放・装備・スコア・設定も保持します。将来の実装判定は `MISSIONS` で管理し、進行記録と分離しています。

## TEST LAB（開発用）

- ゲームURLへ `?debug=1` を付けて起動し、タイトルの「TEST LAB」を選びます。通常起動には専用UIを表示しません。
- 全8武器の2スロット装備、無敵、STANDARD / SPEED / HEAVY / FLIGHT、敵1〜100体の密集・分散配置、AUTO/FIXEDカメラ、FPS・更新/描画CPU表示を試せます。
- プレイ中の「LAB / F2」でパネルを開閉します。表示中は戦闘・操作を停止。FLIGHTはW/S・上下キー、スマホではUP/DOWNで操作します。
- LAB内の装備・スコア・報酬は通常セーブへ反映されません。「LAB終了 → TITLE」で通常ゲームへ戻れます。
- 操作・測定の制約・データ保護方式は [DEBUG_PLAYGROUND](docs/DEBUG_PLAYGROUND.md) を参照してください。

## 開発

- 素材再生成：`py -3 tools/generate_assets.py`
- テスト：`npm test`
- ロジック処理時間計測：`npm run benchmark`（Canvas描画・音声を除外。表示FPSではありません）
- ブラウザ計測：TEST LABのパネル内で `BENCH 30 / 50 / 100` を押します。6秒間、指定数を補充しながら射撃し、実際のフレーム間隔・1% low・同期処理時間を表示します。音声は計測中のみ抑制します。実プレイの軽量オーバーレイとは集計方法が異なります。
- Version 0.1.4の関連テスト・処理時間・FPS観測と制約：[検証結果](docs/PERFORMANCE_0.1.4.md)。iPhone実機のFPS・操作感は未確認です。
- 外部ライブラリ、外部API、ダウンロード素材は使用していません。

仕様資料は `docs/`、生成素材一覧は `docs/ASSET_MANIFEST.md` にあります。
