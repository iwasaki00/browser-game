# 一筆で変わる世界 / ONE STROKE WORLDS

Version 0.1.0 — Simulation Foundation

地形データ・整数水流エンジン・Canvasデバッグ画面の実装です。

## 起動

Node.js 20.19以降、または22.12以降の対応バージョンを使用します。

```sh
npm ci
npm run dev
npm test
npm run build
```

開発画面: http://localhost:5173/

`npm run build` は型チェック後、静的配信用ファイルを `play/` へ出力します。
browser-game の一覧は `033_一筆で変わる世界/play/index.html` を参照します。
GitHub Pagesの既存のルート配信に対応するため、`play/` も配信対象として管理してください。
ソース変更後はビルドを再実行します。公開サーバーへの反映・pushはこの作業では行っていません。

## データと計算

任意サイズの盤面に対応し、サンプルは64×64です。heightはUint8Array、waterはFloat64Array、
terrainType・protectedはUint8Arrayを使います。Float64Arrayの水量は、全演算を安全な整数範囲に
制限して使用します。小数による水流計算は行いません。各WorldStateは配列・施設設定を独立して保持します。
protectedは地形編集禁止情報であり、水の通行を妨げる障壁ではありません。

水面は `height * 256 + water`。隣接する高水面側から低水面側へ
`min(waterFrom, floor(diff / 2))` を同量加減します。A=横偶数列、B=横奇数列、C=縦偶数行、D=縦奇数行。
ステップ番号mod4で先頭グループを回転させ、各グループの結果を次に渡します。
流動→供給→取水→排出→保存確認→ステップ更新の順序です。

セル上限は `Number.MAX_SAFE_INTEGER - 255 * 256`。
配列長、値、施設位置、施設重複、各施設のrateを生成時に検証し、Infinityは排出口だけ許可します。
水量・総量・累積量・初期量と累積供給の合計が安全な整数範囲を超える場合は例外です。
取水前の供給直後の総水量も検証します。失敗した論理ステップは元のWorldStateへ反映しません。
閉鎖境界で、取水・排出した水は盤面から除去します。

速度は5/20/60ステップ毎秒。描画とは独立した論理ステップを実行します。
1フレーム最大8ステップ、経過時間は最大250msを採用し、超過した計算の持ち越しを制限します。
重い環境では実時間に対して進行が遅くなりますが、同じ論理ステップの計算結果は変わりません。

### 方向偏りと見た目

WF-09で、平坦な64×64の中央8×8セルに各4096単位を置き、Step1/4/20/100/600で
水平・垂直鏡映差の総和と最大差を記録しました。この条件ではどれも0でした。
2×2の対角に各8単位を置く場合は1ステップで `[4,4,4,4]` になります。

一方、5×1の対称入力 `[0,0,8,0,0]` はStep0のA→B→C→D後に `[0,2,2,2,2]` となり、
方向偏りが残ります。保存則は成立します。更新順序の回転は偏りの完全除去を保証しません。
最初に「必ず偏りが出る」と仮定したテストは64×64の観測結果と合わなかったため、
測定用テストと、偏りが再現する奇数幅の具体例に修正しました。計算アルゴリズムは変更していません。

視覚的な水の広がりと施設付近の流動は確認済みです。水量の色は対数スケールで、
水が1単位でもあれば着色するため、薄い水も広範囲に表示されます。
自然な河川表現・方向偏りの見た目の許容基準は今後の評価事項です。
