# 3. 品質診断機能

開発サーバーのURLへ`?quality=1`を付けた時だけ表示します。通常開発URLと本番ビルドには計測パネルを読み込みません。

- RAFの平均・直近FPS、間隔p95・最大・50ms超回数。
- Canvas描画CPU時間、フレーム処理CPU時間、単独・A/B比較・内部結果集計別の論理ステップ時間。
- ステージ・画面・論理ステップ、操作と試行状態、ポインター数、ズーム、Viewport・Canvas内部/CSSサイズ・DPR。
- A/Bのステップ一致（比較なしは対象外）、水量収支、既存エラー。
- ON/OFF、計測だけのRESET、折りたたみ、環境の手動記入、結果JSON表示・閉じる。

有効時だけ既存の呼出しを計時し、引数・戻り値・例外・確定順序を維持します。OFFでは元のメソッドを復元し、計時時計を読みません。別のタイマーやログ出力、全世界の履歴保存は追加していません。統計は全期間の集計＋直近最大240観測、表示更新は0.5秒ごと。タブ非表示・フォーカス喪失の停止時にRAF基準時刻を破棄します。

PLAY中の比較時間は「バッチ時間÷確定A+B同期ステップ数」で、平均はステップ件数による重み付けです。比較の最大値は最大バッチ平均であり、個別ステップの最悪時間ではありません。描画はCanvas呼出し側のCPU経過時間でGPU時間ではありません。計測されない値はnull/未取得です。

# 8. 水流方向偏りの現状

既存`diagnoseMirroring`で、F(入力)と反転して計算後に戻した水量配列を比較しました。L1は絶対差合計、maximumは最大セル差、normalizedL1はL1÷最終盤面総水量。反転時も同じA〜D位相です。町の目標や全ステップの浸水履歴を比較する指標ではありません。

- 奇数5×1・同高度・水量`[0,0,8,0,0]`・1ステップ・左右反転: **L1=4、最大差2、正規化0.5**。既知問題は残存。
- 奇数5×5・中央32単位: Step 1のX/YともL1=16・最大差2。Step 4/20はL1=16・最大差1。丸めと巡回順序による差を記録。
- 偶数4×4の対称入力、Step 1/4/20のX/Y: L1=0。
- 標準64×64の3サンプル、Step 1/20/600のX/Y、計18条件: 最終盤面水量の反転差は**影響未検出**（L1=0）。すべての入力・途中時刻への無影響を証明したものではない。
- 現行6面の基準・成功地形、各終了StepのX/Y、計24条件: 同指標の差は**影響未検出**。保存成功ストロークの成否は実シミュレーションのテストで維持。反転した町の浸水履歴・目標の成否そのものはこの診断では未確認。

[55条件の記録](QUALITY-BIAS-v0.7.0.json)では7条件が非ゼロ。奇数幅の公平性が必要な面、鏡像に同じ結果を要求する仕様、取水締切・浸水閾値の近くで差が成否へ影響する時は改めて修正候補を検討します。今回アルゴリズムを変更せず、数学的な収支・決定性の正しさと、見た目・公平性の納得感を分けて扱います。

約1秒のRAF間隔が多数現れた性能低下は観測済みですが、ゲーム本体と実行環境のどちらが原因かは未確定です。
