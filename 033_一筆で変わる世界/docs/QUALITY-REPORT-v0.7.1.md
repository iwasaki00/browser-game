# 3. RAF約1秒問題の再現条件

Chromeの開発用診断、操作ツール接続あり、Stage 01、速度20、通常地図、流向OFF、Viewport 1136×903、DPR 1、カメラ1倍で部分測定しました。UAはChrome/156.0.0.0（Windows）ですが、ブラウザー完全版・OS完全版・電源・CPU条件は今回未取得です。

**document API上のvisibleかつhasFocus=trueでも約1001msを再現しました。** 単独再生のStep 102時点では44間隔中20件が100ms超、p95/最大1001ms。比較終了後の静止期間も含む記録では107間隔中103件が100ms超、中央値1000.8msでした。両記録に条件境界はなく、非表示期間や復帰間隔の通常統計への混入だけでは説明できません。

一方、停止表示の直近240件は平均17.03ms・p95 16.80ms、プレビューの直近240件は平均16.68msでした。同一条件を固定した3回の反復比較は未実施で、常に再現するとは断定しません。約1秒になる発火条件・根本原因は**未特定**です。

原因候補は、操作ツール接続によるスケジューリングへの影響、Chromeのウィンドウ遮蔽・節電等の抑制、他処理/OSの待ちです。物理的なウィンドウ前面状態を独立確認していないため、hasFocus=trueだけでOS上の状態を断定しません。Canvas・計算外のメインスレッド処理も未調査で、候補から除外しません。
