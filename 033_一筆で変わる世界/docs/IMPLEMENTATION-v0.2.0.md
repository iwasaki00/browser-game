# Version 0.2.0 — One Stroke 実装結果

検証日: 2026-10-20（日本時間）

## 1. Version

一筆で変わる世界 / ONE STROKE WORLDS 0.2.0。
0.1.0の水流コア（world.ts / simulation.ts / runner.ts）を変更せず、地形編集層を追加しました。

## 2. 実装した機能

- 1試行1本の一筆。RAISE / LOWER、長さ12セル、半径2セル、高度変化12。
- 上限で線分を切り詰め、有効線を実線、超過部分を赤い破線で表示。
- 変更予定セルの半透明表示、変更後高度の描画、選択セルの変更前→変更予定値表示。
- protected・水源・取水・排出口を編集対象から除外。施設に明示的なprotectedがなくても保護。
- READY → DRAWING → PREVIEW → SIMULATING → RESULT。PREVIEWからはキャンセルして再描画、または実行。
- 実行時に初期状態を再生成して地形だけ変更。初期水量・施設を保持し、ステップ0から開始。
- RESETで初期地形、水量、集計値、編集状態を復元。実行速度と表示用カメラは維持。
- 既存のサンプル選択、PLAY / PAUSE / STEP / SPEED、保存則検査を維持。
- 一筆なしのPLAY / STEPも利用可能。PREVIEW中は専用の「地形変更を実行」を使用。
- 描画・移動モード、1〜4倍ズーム、全体表示へ復帰、Esc・pointercancel・入力喪失時の取消。

## 4. 一筆の適用アルゴリズム

地形座標は盤面の左上が(0,0)、セル(x,y)の中心が(x+0.5,y+0.5)です。
線分を盤面矩形でクリッピングし、盤面内の線分長の合計が12になる位置で最後の線分を補間して切断します。
盤面外を経由して再入場する場合も、外側の移動は加算せず、無関係な内側のセルを直線でつなぎません。
保護区域内は長さを消費します。超過部分はプレビュー側だけが保持し、適用用Strokeのpoints・segmentsには入りません。
pointsは有効頂点、segmentsは盤面外による経路の切れ目を保持します。

セル中心から各有効線分への最短距離を求め、半径以下のセルをSetで重複排除します。
保護セル・施設セルを除き、LOWERはmax(0,h−12)、RAISEはmin(255,h＋12)。
高度が変わらないセルは「変更予定セル」から除外します。点だけの入力は円形のブラシとして扱います。
境界での浮動小数の丸め誤差には1e−9セルの許容差を使い、同じ幾何線分の疎密サンプルで変更セルが一致することを検証しています。

`strokeEdits`がプレビューと`applyStroke`の共通処理です。プレビュー描画では計画値を参照するだけでWorldStateを変更しません。
実行時は保管済みの初期定義からWorldStateを再生成して適用し、新しいSimulationRunnerへ渡します。
水流演算、施設処理、水量収支、A〜D巡回更新はそのままです。

## 5. 入力・ズーム・座標変換

Pointer Eventsとpointer captureを使用し、Canvas外で離してもpointerupを処理します。
描画中に2本目が触れた場合は描画を破棄して、2本指の重心によるパン・指間距離比によるピンチへ移行します。
2本指操作後に残った1本の指から、勝手に新しい一筆は始めません。
取得可能ならcoalesced eventsも読みます。直線上の同方向サンプルは幾何形状を変えずに統合します。

座標変換はCSSピクセルで統一し、Canvasの内部640×640解像度とは分離しています。
入力と描画は同じcameraと共通の座標変換を使用します。
ズームはポインター位置を基準にoffsetを調整し、1〜4倍・盤面が画面外へ消えない範囲に制限します。
ズームボタンは表示中央を基準にします。ホイール・表示操作中に描画が残っている場合は、安全のためその描画を取り消します。

Canvasだけにtouch-action:noneとuser-select:noneを適用しています。周辺のUIでは通常のページスクロールが可能です。

## 9. 方向偏りの追加診断

比較は同じ論理ステップ・更新位相で、`F(初期状態)`と`反転(F(反転した初期状態)))`の全セル水量を比較。
L1は絶対差の総和、最大差は1セルの最大差、正規化L1はL1/総水量です。

| 入力 | ステップ | 左右L1 / 最大差 | 上下L1 / 最大差 | 正規化L1（左右 / 上下） |
| --- | --- | --- | --- | --- |
| 4×4平坦・中央2×2に各8単位 | 1 / 4 / 20 | すべて0 / 0 | すべて0 / 0 | 0 / 0 |
| 5×5平坦・中央に32単位 | 1 | 16 / 2 | 16 / 2 | 0.5 / 0.5 |
| 同上 | 4 / 20 | 16 / 1 | 16 / 1 | 0.5 / 0.5 |
| 5×5非対称地形・1地点に4096単位 | 20 | 178 / 33 | 82 / 16 | 0.04345703125 / 0.02001953125 |
| 標準64×64平坦・中央8×8に各4096単位 | 1 / 20 / 600 | すべて0 / 0 | すべて0 / 0 | 0 / 0 |

非対称地形はheight[i]=(i*7)%4、water[6]=4096、その他の水量0です。
既知の5×1の対称入力[0,0,8,0,0]も、1ステップ後[0,2,2,2,2]を再現。
左右反転とのL1差4、最大差2、正規化L1=0.5です。全ケースで保存則を検査しています。

原因: 奇数幅・奇数高さでは反転によって偶数開始と奇数開始のペア群が入れ替わります。
順次平衡化のA→BとB→Aは同じ結果を保証しません。位相の巡回は、各時点の対称性や最終的な完全解消を保証しません。
小水量では整数切り捨てで差1の移動が止まることも影響します。標準サンプルの0という結果は、任意地形の偏りなしを保証しません。

再現: `npm test -- tests/bias.test.ts --reporter=verbose`。
次版で対称な更新スケジュールや同期的な再配分方式を比較する余地がありますが、保存性・決定性・整数上限を改めて検証する必要があります。
今回の水流アルゴリズムには変更を加えていません。

## 10. 判明した問題と制約

- 方向偏りは上記のとおり残存します。自然さの主観評価と数学的保存則は別の評価です。
- スマホ幅の画面確認はPC上の表示領域変更です。実タッチ・ピンチの端末評価は未確認です。
- 1本の入力は8192点まで。上限到達・非有限座標などは明示エラーで取消し、RESETで再挑戦します。黙って別の地形にはしません。
- ブラシ設定は今回の固定初期値。0または255で変化しない場合や保護セルだけの場合は実行できない理由を表示します。
- カメラは表示専用で、水流計算やストローク座標を変更しません。計算負荷が高いと実時間に対する進行は遅くなります。
