# Windows Chrome 性能計測手順 — 0.7.0

目的は問題の再現・原因の切り分けです。FPSだけでゲームの合否を決めません。端末の違う結果を直接比較せず、取得できない数値は「未取得」と記録します。

## 起動と環境記録

1. プロジェクトのフォルダーでターミナルを開き、依存導入済みなら `npm run dev -- --host 127.0.0.1 --port 5187 --strictPort` を実行します。未導入なら先に `npm ci`。ポートが使用中なら別の番号にし、全試行で同じ番号を使います。
2. 表示されたURLへ `?quality=1` を付け、Windows Chromeで開きます。通常の開発URLには診断が出ません。`npm run build` の `play/` ではクエリーを付けても診断は入りません。
3. Windows「設定→システム→バージョン情報」でOS版・ビルド、Chrome「ヘルプ→Google Chromeについて」でブラウザー版を記録します。機種、CPU、メモリー、電源、省電力、他アプリ、拡張機能も記録します。取得できない情報をUAから推測しません。
4. ブラウザーの拡大率を100%に揃えます。画面サイズ、診断のViewport、DPR、Canvasの内部サイズとCSSサイズを記録します。計測中は同じウィンドウサイズ・カメラ倍率を使います。
5. 「測定条件を記入」に環境と試行名を入力します。「結果をテキスト表示」で、その時点のJSONをテキスト欄へ出せます。コピーして試行名を付けて保存します。入力内容やJSONはサーバーへ送信されず、自動保存もされません。

## 指標の意味

| 指標 | 意味と限界 |
| --- | --- |
| FPS平均・現在 | requestAnimationFrame間隔の逆数。現在は直近最大240観測、平均はリセット以降。GPUが完成させたフレーム数ではない。 |
| フレーム間隔p95・最大・長いフレーム | p95は直近240観測、最大と50ms超の回数は全期間。バックグラウンド抑制、他アプリ、ツール接続待ちも含み得る。 |
| 描画CPU時間 | 実際に描画したCanvas呼出しの経過時間。GPU時間ではない。静止時に描画しなければ未取得のまま。A/Bでは見えている両Canvasの合計。 |
| フレーム処理CPU | 既存のフレーム処理本体の時間。診断パネル自身のDOM更新時間は外側なので含まない。 |
| 単独1ステップ | 既存SimulationRunner.step呼出し。目標・流量記録も含む。失敗して確定しなかったステップは件数に加えない。 |
| A+B同期1ステップ | 既存の原子的なA+B計算。PLAYはバッチ呼出し時間÷確定同期ステップ数。平均は件数で重み付け。最大値とp95はバッチ平均の値で、個別ステップの最悪時間ではない。 |
| 結果集計1同期ステップ | 通常結果画面が内部で行うA/B集計を、比較画面と分けて記録。 |
| 未取得/null | 該当操作がない等で測れていない。0ms・合格を意味しない。 |

各系列の直近値は最大240観測に限定し、全ステップの状態は保存しません。診断表示は0.5秒ごとに更新します。「診断値」を閉じても計測は続きます。「診断を停止」で計測メソッドを復元し、以降の時計読み取りを止めます。「計測をリセット」は計測値だけを消し、世界や進捗を変えません。ゲームのRESETとは別です。

## 共通の進め方

- 本番の進捗と混ざらない試験用プロファイル・専用オリジンを使います。初期化操作をする場合は試験用データだけで行います。
- 初回読込み（冷状態）を1回、同じページの安定後を3回に分けます。キャッシュを本当に消していない再読込みを「コールド」と呼ばず、条件を記載します。
- 各回、場面を用意→計測をリセット→操作→結果を出力、の順。静止・操作場面は30秒を目安とし、短いステージでは終了までの実際の秒数と件数を記録します。終了後の長い静止時間を再生性能へ混ぜません。
- タブを前面にし、DevToolsは必要時だけ開きます。タブ移動・ウィンドウの遮蔽・操作ツールの待機を記録します。非表示・フォーカス喪失でゲームは停止し、自動再開しません。診断のフレーム間隔も停止区間をまたぎません。
- 同じ一筆・速度・表示・カメラで繰り返します。描画プレビューは再描画操作を挟みます。途中で長さ超過や保護領域に当たった場合も条件に残します。
- 診断ONの測定には診断自身の負荷があります。最後に診断OFFで同じ操作を行い、明らかな入力遅延の有無を人が確認します。OFF時の診断FPSを推定で記入しません。必要時はChrome Performance記録を別試行として取得します。

## 測定シナリオ

| ID | 用意と操作 | 主に記録するもの |
| --- | --- | --- |
| PF-01 通常地形 | チャレンジ01またはデバッグ64×64の平坦サンプルを停止して表示。全体表示で30秒。条件を混ぜず別試行にする。 | RAF、描画件数、サイズ。静止中の描画なしは正常な未取得。 |
| PF-02 水流再生 | デバッグの施設サンプルをRESET、速度20または60でPLAYし600ステップまで。Stage 01も別途120まで。 | FPS、単独ステップ時間、長い間隔、実際の秒数、収支。 |
| PF-03 PC左右比較 | 有効な一筆を確定して世界A/B比較。十分な幅で左右2画面を確認し、共通速度で終了まで再生。 | A/B一致、同期ペア時間、両画面描画CPU、成否と差分。 |
| PF-04 一筆・プレビュー | Stage 01で尾根に短い線→プレビュー→キャンセルを10回。30秒を目安にする。 | FPS、描画CPU、線が指・マウスに追従するか、超過時の遅延。 |
| PF-05 高度・流向 | 同じサンプル・同じ速度で「高度と境界線」と通常＋流向ONを別試行で再生。 | それぞれのFPS、描画CPU、計算CPU。表示条件を分ける。 |
| PF-06 6面切替 | 通常のプレイで全6面を解放した試験進捗を用意。ステージ一覧から01→06→01を3周。 | 切替時の長い間隔、遅延、地図・指標・診断のステージID初期化。未解放なら未実施。 |
| PF-07 連続リトライ | 同一面で描く→実行→リトライを10回以上。回数と総時間を記録。 | 初回/後半の時間傾向、描画・入力状態残り、取水/浸水/Step初期化。 |
