## 同じ縦長画像の寸法比較

600×1000画像を使用した計算結果。縦横比を保持して元画像から取り込む。表はグリッド上の幅・高さであり、キャンバスをそれぞれ180×300／270×450 CSS pxで表示した場合にはそのまま表示寸法になる。実iPhoneの表示寸法やスクリーンショットではない。

| 品質 | v0.4.0の初期写真 | v0.4.1の初期写真 | 高さの増加 | v0.4.1の80% |
| --- | --- | --- | ---: | --- |
| 標準180×300 | 99×165 | 126×210 | 約27.3% | 144×240 |
| 高精細270×450 | 149×248 | 189×315 | 約27.0% | 216×360 |

フリーは高さ70%を目安とし、幅86%で制限する。80%でも上の余白8%＋画像80%で、下に12%以上を残す。横長・正方形は幅で収まるため、70%から80%へ動かしても画像寸法が変わらない場合がある。この場合はサイズ値だけ保持し、砂を初期化しない。透明ピクセルを除き半透明RGBAを保持する。比率の誤差はグリッドの整数丸めのみ。

## 最大サイズの粒子数と流下

すべて全画素不透明。砂時計の100%はv0.4.0の安全範囲を維持し、40〜100%で縮小する。最大取り込み面積はグリッドの7.5%以下、写真の全行が壁の内側に入る。流下中の粒削除、壁通過、色の置き換えは行っていない。

| モード / 設定 | 元画像 | 標準の取り込み・粒子数 | 高精細の取り込み・粒子数 |
| --- | --- | --- | --- |
| フリー80% | 620×960 | 155×240 / 37,200 | 232×360 / 83,520 |
| 砂時計100% | 750×540 | 75×54 / 4,050 | 112×81 / 9,072 |
| 砂時計100% | 600×1000 | 49×82 / 4,018 | 73×123 / 8,979 |
| 砂時計100% | 680×1340 | 45×89 / 4,005 | 68×134 / 9,112 |
| 砂時計100% | 1000×1000 | 63×63 / 3,969 | 95×95 / 9,025 |

砂時計は各画像・各品質で、直立の上側残数0、全IDの壁侵入なし、流下後の反転と再流下、色配列・個数不変、リセットの初期グリッド一致を確認した。750×540は標準の面積上限4,050粒、680×1340は高精細の面積上限9,112粒まで使う。750×540の中央通過時間は標準32.58秒／高精細45.22秒相当。これは固定ステップを60／90Hzに換算した時間であり、ブラウザ実時間ではない。

フリーの最大画像でも一斉崩壊後の復元、初期配置・色・個数への一致、即時リセットを確認した。寸法・生のCPU時間・各条件は [node-results.json](node-results.json)。崩壊中の実ブラウザFPSは未取得。

## アプリの状態保持テスト

模擬DOMとCanvasアダプターで実際のアプリのイベント・RAFハンドラーを動かした。画像の実デコードとCanvasのブラウザ描画、CSSレイアウトは模擬対象であり、確認済みとはしていない。

- 設定・サイズパネル中は物理・復元の経過時間を進めない。サイズプレビューを6秒表示しても、実粒子数・復元進捗は同一。キャンセルとEscapeで元の描画を正確に復帰。
- 変更なしの適用はエンジンを再生成しない。横幅制限で同じ取り込み寸法になるときも配置を保持。
- サイズ変更は現在のモードだけを再生成。フリーの復元を途中で止めたまま砂時計を60%へ適用し、フリーへ戻って同じ進捗から再開できた。逆方向でも砂時計の流下途中の配置を保持。
- 崩した写真に異なるサイズをプレビューしたときは初期化の注意を表示。適用失敗は旧サイズ・旧配置を保持。品質変更でもモードごとの80%／60%を維持し、両方を再生成。
- 模擬した390×844／375×667およびバー相当の高さ縮小では、表示寸法の変更だけで変換回数・グリッドサイズ・粒子描画が変わらないことを確認。ただし実CSSでのボタンの見え方・クリック可能性は未確認。
- フリーの部分崩壊・スワイプ・一斉崩壊・復元・即時リセット、砂時計の反転、傾き初回待機・手動復帰・回転停止の既存テストを再実行。砂の物理ルールと傾き監視は変更していない。

## 縦画面の構成と残る確認

メイン画面は上部のタイトル／モード／設定、可変高キャンバス、下部2段の操作だけにした。画像・重力は開いたときだけパネル表示し、設定はスクロールする本文とスクロール外の閉じるボタンを持つ。サイズパネルはキャンバスの下に入り、プレビューを見ながら操作する。必要なエラー・初期化注意は該当パネルへ表示する。

`100dvh`、上下左右のセーフエリア、キャンバスの最小高0、主要ボタンの最小44px相当を使用。文字拡大では相対単位の最小画面高とページスクロールで操作を優先する。閉じたパネルは `hidden`、モーダル中の背景は `inert` とし、Escape・フォーカス復帰・モーダルのTab循環に対応した。

これらは実装方針であり、iPhoneでの確認済み結果ではない。以下は未確認：

- 390×844、375×667、Safariのバー展開時にメインボタンへスクロールなしで到達できるか。
- 設定・重力・画像パネルの本文をスクロールしても閉じるボタンが見えるか。
- 文字200%で操作が隠れず、必要ならページスクロールで到達できるか。
- パネル・バーの伸縮後に実指のタッチ位置が合うか。長押し・ダブルタップの抑止。
- 最大サイズの崩壊中FPS、iPhoneの縦向きロックON/OFFでの傾き・画面回転。
