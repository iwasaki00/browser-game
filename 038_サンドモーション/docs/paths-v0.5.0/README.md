## 物理テスト

壁はグリッドと同じ解像度のUint8Arrayで管理し、砂のIDを持たない。標準の描画半径2セル／消去半径5セルをグリッド幅で拡大する。太さは固定で、砂ブラシの設定や指の速さに依存しない。

標準180×300・高精細270×450のそれぞれで以下を確認した。

- 横断する水平壁で砂が溜まり、全粒が静止する。中央だけを消すと近くの自由粒子が起き、穴から落ちる。左右の壁は保持される。
- 45°の連続壁に沿って砂が移り、壁の端から下へ落ちる。壁を横断して両端を画面の端へ接続した場合は、最大速度4セルの勢いでも反対側へ抜けない。
- 高速な斜め1ストロークをカプセル領域として塗り、中心線のセルに欠けがない。2つの固体セルの斜めの継ぎ目もすり抜けない。
- 壁の描画は固定・自由のどちらの砂セルも飛ばす。位置・色・速度・固定／活動配列は編集直後に不変。消去は周辺の自由粒子だけを起こし、固定写真を解放しない。
- 全消去でマスクと壁セル数がゼロになり、支えを失った砂が落ちる。粒子数・RGBA・IDとグリッドの整合性を保持する。
- 復元中は元位置に描いた壁を保持し、確定時だけ初期砂と重なるセルを除去する。重ならない壁を保持し、即時リセットも同じ処理を使う。キャンセル時は壁を変更しない。
- 壁なしのPathEngineと従来のSandEngineを同じseed・砂・ブラシ・8方向入力で480ステップ比較し、座標・速度・活動・固定・色・グリッド・乱数状態が完全一致した。

基底の `src/engine.js` の移動ルール、傾きの `src/tilt.js`、砂時計の容器・流下・反転は変更していない。運動の掃引と斜めの角判定も既存処理を使う。

## アプリの操作と状態保持

模擬DOM／Canvas上で実際のアプリのPointer Events・クリック・RAFハンドラーを実行した。実Canvasの描画処理や画像デコードは代替しているため、実ブラウザの確認とは区別する。

- 標準17,670粒／高精細39,440粒の不透明サンプル相当で、道具選択による自動閉じ、選択中ラベル、タッチ／マウス入力、写真上での描画回避、部分消去、全消去を確認。
- 描画色178/191/184/255のセル数が壁の診断値と一致。壁の描画・消去だけでは砂の描画セル・固定数が変わらない。
- 復元中のポインター、道具選択、全消去の強制イベントを拒否。途中リセットで復元を止め、壁は保持。
- 崩した写真の元位置へ描いた壁を、復元確定時と即時リセット時に初期砂セルだけ除去。「画像と重なる壁を取り除きました」が表示され、約3.5秒で消える。
- 砂時計では道具を隠し、強制クリックでも開かない。往復後にフリーの砂と壁の描画が完全一致する。砂時計だけのサイズ適用でもフリーを保持。
- 画像／品質パネルに壁初期化の事前案内が出る。サイズの実寸法が変わる場合も壁初期化を案内。プレビュー・取消・変更なし・失敗では壁マスクを保持。
- 読込キャンセル・デコード失敗・2モード目の変換失敗でも壁を保持。画像成功・サンプル・品質変更・フリーのサイズ成功ではゼロへ初期化。
- 壁なしの部分崩壊・一斉崩壊・復元、サイズと透明度、傾き・初回待機・回転停止、砂時計の全粒流下・反転の既存テストを再実行。

砂のあるセルには壁を作らないため、その砂が後で動いた場所に空きが残ることは仕様どおりである。勝手に壁を補完したり、砂を押し出したりしない。
