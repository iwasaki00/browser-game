# SAND MOTION v0.3.0 — REASSEMBLY 検証結果

## 実装

既存の粒子ID（TypedArrayのインデックス）と `originX/originY` を再利用しています。粒子の色・数・元位置の対応を変更していません。物理エンジン・品質グリッド・傾きの有効化後4秒監視は変更していません。

`Reassembly.start()` で押下時の位置を記録し、描画用のFloat32Arrayにだけ補間します。開始位置と元位置が同じ固定粒は動きません。部分崩壊・全崩壊・混合状態を同じ仕組みで扱います。未崩壊の状態では開始しません。

| 設定 | 初期値 | 調整 |
|---|---:|---|
| 全体の時間 | 1500ms | UIで0.6〜3秒 |
| 弧の強さ | 0.06 | UIで0〜0.16。移動距離に対する係数 |
| 粒ごとの時間差 | 全体の20%以内 | `REASSEMBLY.staggerFraction` |

IDのハッシュで短い遅延と弧の左右を決めます。物理用の乱数は消費しません。3次ease-outで着地前に減速し、補間進捗に沿う正弦で少しだけ弧を描きます。毎フレームの粒別オブジェクト生成はせず、6本のFloat32Arrayを再利用します。通常の物理更新は停止し、衝突や経路探索はしません。描画上の重なりは許容し、最後に既存の `engine.reset()` で位置・色・占有・固定・速度・数を正確に確定します。

復元中はタッチと一斉崩壊を拒否し、連打でも再開始しません。リセットは常に有効で、復元を破棄して即時に戻します。画像・品質を変更したときは旧インスタンスをキャンセルして、新エンジンに対応した復元インスタンスへ置換します。非同期の画像デコードも既存の世代番号で古い選択を排除します。復元専用タイマーや別のrequestAnimationFrameは作りません。

傾きモードのスマホ横表示では `advance()` を呼ばず、描画だけ続けて同じ進捗を保ちます。縦表示でセンサーが安定した後、経過時間をリセットして続きを進めます。横表示中でもリセットできます。

- 復元7件：部分／全体／混合から初期配列との完全一致、固定粒不動、未崩壊の開始拒否、遅延と減速、設定、バッファ再利用、連打拒否、中断後の古い完了防止。
- 実際の `app.js` を模擬ブラウザで動かす統合1件を拡張。標準・高精細の復元、途中リセット後に再度触れる操作、復元中の品質変更・サンプル切替・非同期画像読み込み、横表示停止・同進捗での再開、横表示中リセットを確認。
