# SAND MOTION v0.2.1 — TILT LAB

写真やイラストを色付きの砂に変えて、タップ・スワイプ・重力で動かす実験用Webアプリです。Canvas 2Dと2Dグリッド方式を使用しています。画像処理は端末内で完結し、外部への送信や保存はしません。

## 起動

Node.js 22以降を用意し、このフォルダーで実行します。依存パッケージのインストールやビルドは不要です。

```sh
npm start
```

表示された `http://127.0.0.1:5173` をブラウザで開いてください。終了はターミナルで `Ctrl+C` です。ポートが使用できない場合は、PowerShellで次のように変更できます。

```powershell
$env:PORT = '8080'
npm start
```

HTMLファイルの直接ダブルクリックではES Modulesの読み込みが制限されるため、HTTPサーバーを使用してください。

将来のGitHub Pages配信では、このディレクトリの `index.html`、`style.css`、`src/` を相対パスを保って配置できます。今回は公開・コミット・pushを実行していません。

## 操作

- 起動時は自動生成した山と砂丘のサンプルを表示します。
- 「画像を選ぶ」からJPEG / PNG / WebPを選択します。縦横比を保って縮小し、完全透過ピクセルを除いて固定砂粒に変換します。
- 画像をタップすると周辺の固定が解除されます。ドラッグ／スワイプすると連続した範囲が崩れ、動きの速さに応じて砂を押します。指を止めている間は押出力を追加しません。
- 「一斉崩壊」はすべての固定粒子を解放します。
- 「リセット」は現在の画像の位置・色・固定状態・粒子数・勢いを瞬時に復元します。選択した重力方向は維持します。
- 矢印で上下左右・斜めの8方向に重力を変更します。
- 初期状態は「手動」です。「傾きで操作」を押したときだけセンサーを開始し、必要ならSafariの許可を求めます。最初の有効な持ち方が下向きの基準になります。「基準を合わせる」で現在の姿勢に合わせ直せます。
- 縦に起こして持ち、左右に軽く傾けると斜め下、もう少し傾けると横へ流れます。基準へ戻すと下向きになります。傾きだけでは固定写真は崩れません。タップや一斉崩壊で解放した砂が動きます。
- 権限確認後は「端末を傾けてください」と表示し、初回の有効値を受け取るまで4秒を超えても待機します。待機中は直前の手動重力を保ち、nullや向きを決められない値を基準にしません。
- 矢印を押すとセンサー入力や初回待機を止め、即座に手動へ戻ります。非対応・許可拒否の場合は理由を表示して手動で続けられます。
- 「実験の設定」で軽量120×200／標準180×300／高精細270×450とブラシサイズを選べます。初期設定は標準です。品質変更は現在の画像を初期状態から再生成する操作です。選択欄の前にも案内を表示しています。自動での品質変更・初期化はありません。
- 高精細では元画像を270×450のグリッドへ取り込み直します。サンプルは標準17,670粒、高精細39,440粒です。表示上のCanvasサイズとブラシ幅を保ち、物理更新頻度を標準60Hz／高精細90Hzにして細かいセルによる移動の遅さを補正します。高精細は負荷が高いため、端末性能によって実際の動きが遅くなる場合があります。
- 右上のボタンから診断情報を開閉できます。FPS、総粒子数、固定／自由粒子数、重力、グリッド、1物理ステップの平均処理時間を表示します。
- ウィンドウの大きさや画面の向きを変更しても、粒子状態は維持します。

砂の操作領域だけスクロール・長押しメニュー・タッチ拡大を抑止しています。設定や通常のページ操作はスクロールできます。

## iPhoneの傾き操作とHTTPS

1. 信頼できるHTTPSの配信先でアプリを開き、Safariのアドレス欄をタップしてURLの先頭が `https://` であることを確認してください。接続に関する警告が出ないことも確認します。HTTPのLANアドレスでは傾き操作を開始できません。
2. 「傾きで操作」をタップします。許可画面が出たら、モーションと方向へのアクセスを許可してください。アプリも `window.isSecureContext` を確認し、安全な接続でない場合は理由を表示します。HTTPSでも端末・Safariの設定によって利用できない場合があります。
3. 端末を縦に起こして持ち、有効な値が届くのを待ちます。画面をほぼ水平に置いた状態では方向が不安定になるため、端末を起こしてから再試行してください。
4. 「基準を合わせる」を押すと、その時点の持ち方で下向きに戻せます。

PCの `http://127.0.0.1:5173` は開発用のローカル接続として扱われますが、iPhoneからそのアドレスでPCに接続することはできません。実機確認には別途、端末が信頼する証明書を持つHTTPSの静的配信環境が必要です。付属の `npm start` はPC内のHTTPプレビュー用です。今回はHTTPSサーバー構築・外部公開は行っていません。

## 縦向きロックと回転時の動作

縦画面のまま遊ぶには、iPhoneのコントロールセンターで「画面縦向きのロック」をオンにしてください。

- Face ID搭載機：画面右上から下へスワイプしてコントロールセンターを開きます。
- ホームボタン搭載機：画面下端から上へスワイプします。
- 鍵と円形の矢印のボタンをタップし、画面縦向きのロックをオンにしてからSafariに戻ります。

ボタンが見当たらない場合はコントロールセンターのコントロールに追加します。[Appleの画面回転・ロックの案内](https://support.apple.com/en-gb/guide/iphone/iph3badf94ec/26/ios/26)も参照してください。

アプリはOSの縦向きロックを変更・検出しません。傾きモード中にスマホの**実際の表示**が横向きになった場合だけ、物理更新・タッチ・画像変更等を一時停止し、「iPhoneを縦に戻してください」と表示します。縦表示に戻し、傾き入力が約350ms安定すると自動再開します。粒子の位置・色・個数・固定／自由・基準姿勢は維持し、グリッドは再生成しません。再開後は一度指を離してから触れ直してください。

傾けただけで縦表示が維持されている場合や、PC・手動モードでは、この回転停止は適用しません。横表示中でも矢印を押せば手動に戻して続けられます。

## 推奨環境と制限

対象はiPhone SafariとWindows Chrome／Edgeの現行版です。`Image.decode`、Pointer Events、ResizeObserver、ES Modulesに対応したブラウザが必要です。v0.2.1はNode自動テストと参照画像で確認しました。ブラウザの崩壊中FPS、Windows版 iPhone Web Emulator 1.1.1、iPhone Safari実機のv0.2.1操作は未確認です。今回のブラウザ操作は、ツールが現在URLを判定できず安全確認のため停止しました。

初回待機と、有効化後の受信断は別の処理です。有効化後は従来の4秒の受信断監視を維持しています。同じ角度の有効値が届き続ければ、5秒以上静止した後も操作できます。一方、静止中にイベント自体が途絶える環境では手動に戻り、再度「傾きで操作」が必要です。これは自動テストで再現済みの制限であり、エミュレータ実環境の原因確定とは区別しています。

EXIFの向きはブラウザ標準の画像デコーダーに従います。iPhoneの撮影方向ごとの実測は未検証です。HEICの直接読み込みには対応していません。JPEG・PNG・WebPに変換して選択してください。

縮小画像の1ピクセルが1粒です。半透明の色・アルファを保持します。大きな写真は縮小前のデコードにもメモリを使うため、端末によって読み込みに時間がかかったり、読み込めなかったりする場合があります。

実験版の離散セル計算のため、実砂の厳密な摩擦・安息角・衝突を再現するものではありません。画像・操作状態はリロードすると失われます。傾きは既存の8方向へ割り当てます。連続ベクトルの物理演算や画像／動画保存は実装していません。感度の初期値は実機調整前です。

## テストと性能測定

```sh
npm test
npm run benchmark
```

`npm test` はNode標準テストランナーによる35テストです。依存パッケージはありません。既存の物理・画像データ変換13件に加え、傾き入力17件、品質4件、アプリ統合1件を確認します。許可API・イベント・画面回転を模擬しています。実際のSafariの許可画面やセンサー測定とは分けて評価してください。

`npm run benchmark` は3品質の物理演算のみを計測します。CPU、Nodeバージョン、粒子数、条件、平均・95パーセンタイル・最大処理時間を出力します。Canvas描画を含むFPSではありません。

`npm run qa` で `http://127.0.0.1:5174/test/quality.html` を開き、「比較を実行して記録」を押すと、実アプリの標準・高精細を順番に動かし、初期Canvas、一斉崩壊／合成スワイプ中のFPS、リセットを測定します。前面タブのまま実行してください。結果を `docs/quality-v0.2.1/` に保存します。このブラウザ比較は今回未実行です。保存APIはQA用サーバーの127.0.0.1だけで利用でき、通常の `npm start` にはありません。

`npm run reference` はWindowsのSystem.Drawingで、アプリのサンプル描画命令を使った参照PNGと、2秒相当の崩壊・スワイプ後の状態を生成します。ブラウザのスクリーンショットではなく、ブラウザとアンチエイリアス等が異なる場合があります。外部ライブラリは不要です。[初期表示の参照比較](docs/quality-v0.2.1/reference-initial-comparison.png)は左が標準、右が高精細です。実測値・環境別の結果は[検証記録](docs/quality-v0.2.1/README.md)を参照してください。

ブラウザ検証ページは、サーバー起動後に `http://127.0.0.1:5173/test/browser.html` を開き「検証を実行」で実行できます。サンプル、PNG／JPEG／WebPデコード、破損画像、透明画像、合成PointerEvent、ボタン、品質変更、リサイズを確認します。このページの実行は今回未検証です。合成イベントでは実機のタッチ感やファイル選択ダイアログを保証できません。
