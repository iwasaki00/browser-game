# ガチャ王 / GACHA KING

Version 0.1.2 — REAL GACHA EXPERIENCE

iPhone Safariを主対象にした、依存ライブラリなしの静的ブラウザゲームです。ガチャで12種類の「へんてこ生物」を集め、即売り・架空フリマ・架空SNSを使って3種類の王を目指します。

Version 0.1.2 — REAL GACHA EXPERIENCEでは、筐体のハンドルを回し、排出口へ落ちたカプセルを開ける遊びに更新しました。以前のPLAYABILITY & BALANCE版の経営・収集バランスを引き継いでいます。Version 0.1.0 / 0.1.1 / 以前の0.1.2のセーブデータを読み込めます。

## ガチャの操作

ホーム中央のハンドルを、外側から時計回りに240度ドラッグすると1回分を購入します。回し切る前に指を離す、指が中心を横切る、画面を離れるなどで操作を中断すると元の位置へ戻ります。ハンドルの上だけスクロールを抑止し、画面の他の場所はスクロールできます。

ドラッグが難しい場合は「タップで回す」を使用できます。キーボードではハンドルにフォーカスしてEnterまたはSpaceでも回せます。

| モード | 操作 |
| --- | --- |
| 通常（初期設定） | ハンドル操作後に排出し、短い待機で自動開封。タップで早く開けることも可能 |
| じっくり | ハンドル操作後に排出し、カプセルをタップまたは上へスワイプして開封 |
| サクサク | ワンタップで回し、排出・開封を短縮 |

設定からモード、演出軽減、ミュートを変更できます。すべてのモードでタップ代替と演出スキップを利用できます。通常の排出は約1.35秒、開封時の分割演出は約0.32秒で、高レアでも待機時間を追加しません。

結果画面には画像・名前・レア度・初発見表示・図鑑進捗・売却価格・SNS効果を表示します。「もう1回回す」で所持品画面を経由せず再挑戦でき、投稿と即売りもその場で行えます。王冠と周回はホームの「王への道」から確認してください。

効果音はWeb Audioで端末内合成します。コイン、ハンドルの段階音、移動、落下、開封、レア別の獲得音を小音量で再生します。ユーザー操作後に音声を開始し、再生できない環境でも進行します。

## 抽選と保存

ハンドルを回し切った時点で、既存の抽選処理を一度だけ呼びます。料金・所持品・初発見判定・未表示結果を、従来の `gacha-king-save-v1` にまとめて保存します。開封演出は抽選確率に影響しません。

演出途中に再読み込みした場合は同じカプセルを復元し、開封済みなら同じ結果画面を再表示します。再表示による追加課金や再抽選は行いません。結果の処理が終わるまでは次の抽選をロックします。設定の操作モードとミュートも保存・周回継承します。

ブラウザでストレージが禁止・消去される場合やプライベートブラウズを終了した場合は、保存の持続を保証できません。

## 現行バランス

| 項目 | 仕様 |
| --- | --- |
| 初期資金 | 1,000 G |
| ガチャ料金 | 1回 200 G |
| 資金王 | 有効資金 3,000 G |
| コレクション王 | 現在所持している異なる8種類 |
| 人気王 | 300フォロワー |
| 周回初GET | その周回で初めて入手した種類ごとに150 G |
| 即売り | アイテム価格の100%、待ち時間なし |
| フリマ | アイテム価格の145%、仮想8秒後に成約 |
| 救済 | 200 G未満かつ所持品・出品が空の時に600 G |

排出率は COMMON 45%、RARE 30%、EPIC 15%、LEGEND 8%、MYTHIC 2%です。SNS投稿は同じ所持品につき一度だけで、11～133人のフォロワーを獲得します。SNSからの資金収入はありません。

周回初GETと救済で受け取った支援金は、画面上の所持金として使用できますが資金王の「有効資金」には含まれません。これにより収集の継続を助けつつ、支援金だけで資金王を取ることはできません。

王冠獲得後は、王冠数・発見済み図鑑・演出設定を継承します。所持金・所持品・出品・投稿・フォロワー・周回内ボーナス履歴はリセットされます。

正式画像12枚は `assets/items/henteko-vol01/`、既存IDと素材IDの対応は同フォルダの `manifest.json` にあります。

## 起動

`index.html` を静的Webサーバーで配信してください。ES Modulesを利用するため、`file://` での直接起動ではなく、VS Code Live Serverや次のコマンドが利用できます。

```powershell
py -m http.server 8080
```

その後 `http://localhost:8080/` を開きます。GitHub Pagesではリポジトリ直下を公開元に指定できます。

## テストとシミュレーション

```powershell
npm test
npm run check
npm run simulate
```

`npm run simulate` は資金・コレクション・人気・バランスの4方針を各1,000シードで実行します。フリマ待機は仮想時刻で進めるため実時間を待ちません。この結果はガチャ回数の比較であり、実プレイ所要時間の推定ではありません。調査結果は `docs/BALANCE_0.1.2.md` に記録しています。

## iPhone Safari 手動受入チェック

以下は実機で実施するためのチェックリストです。PC Chromeの390px縦画面・ブラウザ操作と自動テストは実施していますが、iPhone実機の確認は未実施です。回し心地と10回連続操作の感想を最終受入条件とします。

- [ ] 縦画面で筐体全体とハンドルが見やすく、横スクロールが出ない
- [ ] ハンドルが指に追従し、240度の回転が気持ちよく操作できる
- [ ] 途中で離す・逆方向へ回す・中心を横切る・2本指操作・連打で誤購入が起きない
- [ ] ハンドル上では画面が流れず、ハンドル以外では通常スクロールできる
- [ ] ドームの揺れ、内部移動、排出口の落下とバウンドが自然に見える
- [ ] 通常モードの自動開封と、じっくりモードのタップ／上スワイプ開封が快適
- [ ] サクサクモードとスキップが使え、高レア演出に長い待機や激しい点滅がない
- [ ] コイン・回転・落下・開封・レア獲得の音量が快適で、ミュートが効く
- [ ] 「演出を軽減する」を有効にすると開封演出が短縮される
- [ ] 下部5タブ、ガチャ、詳細画面の各操作を片手で押しやすい
- [ ] 所持品・図鑑に正しい画像、名前、レア度、所持数が表示される
- [ ] 即売りとフリマ成約後に所持品・所持金・進捗が正しく更新される
- [ ] 「開封→投稿→即売り→もう1回」を10回続けても煩雑に感じない
- [ ] SNS投稿後にフォロワーと投稿履歴が増え、同じ所持品を再投稿できない
- [ ] 画面回転後もレイアウトが崩れず、縦向きへ戻した時に操作を継続できる
- [ ] 再読み込み後に所持金・所持品・図鑑・投稿・設定が復元される
- [ ] 排出途中・未開封・開封済みそれぞれで再読み込みしても、同じ結果が復元され追加購入されない
- [ ] アプリ切替後に戻っても未開封カプセルを開け、音が再開できる
- [ ] 王冠獲得と周回後に、王冠・図鑑・設定だけが継承される

セーブデータはブラウザの `localStorage` に保存されます。外部API、実課金、実SNS・フリマ通信はありません。
