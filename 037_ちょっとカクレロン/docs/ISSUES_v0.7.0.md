## QA-01：写真描画失敗で既存写真が消える

- **重大度：High／修正済み**。
- 再現条件：写真を編集し、画像変更時の `drawImage(HTMLImageElement, ...)` を例外にする。ChromeではCanvasRenderingContext2Dを一度だけ差し替えて再現した。端末の実メモリ不足で再現したという意味ではない。
- 修正前：元の写真Canvasのwidth／heightを変更してから新画像を描いていた。描画失敗で写真画素と寸法が壊れ、エラー表示後の再プレビューが以前の内容と一致しない。800×500の旧画像から500×800へ変更失敗後、出力寸法まで500×800に変わった。
- 原因：写真読込のコミットより先に既存のバッファと編集状態を変更していた。
- 対応：新しいCanvasに先に描画し、成功後に写真参照を交換する。交換前に確認ダイアログやキャッシュを消さない。成功時の旧Canvasと失敗時の一時Canvasは1×1へ縮小する。
- 検証：追加内部試験で既存写真の寸法、サイズ20%、塗装履歴、未確定のポーズ確認、URL解放を確認。Chrome実試験でLIE・塗装・Undo、再生成画像の寸法と画素ハッシュが一致。65内部試験と12ブラウザ試験が最終PASS。
- 残事項：実際のiPhone低メモリ環境での確認は待ち。OSがタブ自体を終了する場合まで復元を保証する変更ではない。

## QA-02：横長の完成／答え画像に大きな上下余白

- **重大度：Low／修正済み（今回の明示指定）**。
- 再現条件：390×844pxで800×500の写真を完成→答え表示。
- 修正前：画像枠が幅366px、高さ約413.55px。写真比率1.6に対して枠比率約0.885となり、contain表示の上下に不要な余白があった。
- 原因：`height:clamp(280px,49svh,550px)` と `min-height:220px` の固定枠。
- 対応：固定高さを撤去し、自然な縦横比と最大幅／最大高さを使用。問題／答えの合成処理や赤枠は変更しない。
- 検証：修正後は366×228.75pxで写真比率1.6に一致。5種類のViewport×3写真比率で実測。問題→答え→編集の操作、全体表示・contain、保存操作、PNGの枠位置の画素検査がPASS。
- 残事項：iPhone Safariの実ツールバー開閉・Safe Areaは受入確認待ち。

## QA-03：branchのroot配信では開発用テストと証跡も公開対象になる

- **重大度：Medium／未解決（公開手順）**。
- 再現条件：親README記載のGitHub Pages「Deploy from a branch / main / root」で、`.nojekyll` を含むソースツリー全体を配信する。
- 原因：HTML／JS／CSS／assetsと、`tests/`・`docs/` を区別する配布フィルターが確認できない。ローカルに存在することと実際の公開先へ配信されていることは区別する。リモート設定と公開内容は未確認。
- リスク：不要な開発資料が公開対象となり、依頼の公開ファイル条件を満たせない。今回の証跡はすべて合成画像で、個人写真や認証情報は見つかっていない。
- 対応：既存公開方式を無断で再構成せず記録。必要な配布ファイルのリストをRELEASE_CHECKLISTへ明記した。
- 検証：ソースツリー、親README、`.nojekyll`、公開設定用ローカルファイルを読み取り。テスト除外済みという合格判定はしていない。
- 完了条件：既存公開担当の手順でこのゲームの配布ファイルを限定し、公開アーティファクト／実URLで `tests/`・QA証跡が含まれないことを確認する。rootソース配信を続ける場合はリポジトリ全体の公開手順として解決する。
