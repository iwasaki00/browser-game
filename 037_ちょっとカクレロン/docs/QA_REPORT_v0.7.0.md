# ちょっとカクレロン v0.7.0 QA_REPORT

監査日：2026-11-03。対象：v0.7.0 — FINAL QA / 総合品質確認・公開前監査。

## 判定

**CONDITIONAL**。既知の未解決Critical・Highは0件。写真変更失敗時のデータ破損を修正し、指定のプレビュー余白を改善した。Chromeで実描画・PNG・操作を確認できたが、iPhone Safari、OSの共有シート、LINE送信、実機メモリは未確認。不要なテスト資料を公開物から除く手順も公開前に確定する必要がある。

## 範囲と変更

写真の読込・FIT・向き・更新、4ポーズ、配置／サイズ／回転、スポイト、通常塗装、消しゴム、背景コピー、25操作のUndo／Redo、2／4／8倍編集、380msポーズ演出、問題／答えPNG、保存、共有、キャッシュ、参照解放、配布ファイルを監査した。新機能・依存ライブラリは追加していない。

- `app.js`：新しい写真を一時Canvasへ描画し、成功後に現在の写真へ切り替える。失敗では写真・配置・塗装・履歴・確認ダイアログ・PNGキャッシュを変更しない。一時Canvasと旧写真Canvasの画素領域を解放する。
- `style.css`：プレビューの固定高さ・最小高さを撤去。画像の自然な比率、最大幅100%、最大高さ64svhで全体を表示する。問題／答えの描画座標は変更していない。
- HTML・内部Version・CSS／JSキャッシュキーを0.7.0へ統一した。
- 回帰試験、実ブラウザ試験、監査資料を追加した。マスク・Paint Layer・座標変換・出力処理は既存方式を維持した。

## 環境と再実行

Windows、Node.js v25.9.0、インストール済みGoogle Chrome **156.0.8078.80**、headless実行。隣接プロジェクトの既存Playwrightを利用し、ブラウザ／パッケージのダウンロードは行っていない。実行時にループバックHTTPサーバーを起動し、終了時に停止する。外部サイト・個人写真は使用していない。

```powershell
node --test tests/*.test.cjs
node tests/browser-qa.cjs
```

ブラウザ試験は既定で `../036_お宝回収屋/node_modules/playwright` を利用する。別の既存インストールを使用する場合は `PLAYWRIGHT_MODULE` にそのモジュールのパスを指定する。既定のブラウザchannelは `chrome`。この環境以外で未導入の場合は、内部テストだけを実行できる。アプリ本体にPlaywrightは不要。

## 静的監査

- 写真データの流れはFile→Object URL→Image→端末内Canvas→PNG Blob／File。ネットワーク送信・外部解析・クラウド保存・永続ストレージ・写真ログの処理なし。通信APIや外部URL等の既知表記を検知する回帰試験も追加。これは一般的な安全性の形式証明ではなく、コードの読み取りと実行時監視を併用した監査。
- `connect-src 'none'`、外部script／CSS／画像サービスなし。共有処理は「問題画像を共有」のclickからのみ呼ぶ。READMEの「写真をサーバーへ送信しない」と整合する。
- 問題／答えはCanvasで再合成・再エンコード。元ファイルをPNGとして流用しない。問題には答えの座標・テキスト等の追加メタデータを埋め込まない。画像にカクレロン自体が描かれることはゲーム仕様。
- 相対参照の実在・ファイル名の大小文字一致を試験。Version／キャッシュキー0.7.0、Service Workerなし。既存メニューの037リンクとローカルアイコンを維持。
- プロジェクト内に個人写真・認証情報・デバッグ接続設定・未使用通信コードは見つからない。保存した証跡は合成色面、色勾配、合成JPEG、ローカルSVGだけ。
- 公開用に必要なのはHTML・CSS・6 JS・assets。親READMEのGitHub Pages「branchのrootを配信」と `.nojekyll` の組合せでは、`tests/`・`docs/` も配信対象となる。除外済みとは判断しない。公開構成の変更やデプロイは行っていない。詳細はQA-03。

## 性能・メモリ

実測はheadless Chromeでの機能試験全体の所要時間。最終実行では180条件の座標＋PNG試験約6.1秒、コピー180条件＋履歴試験約7.0秒、12回の読込／往復試験約2.6秒。入力遅延・FPS・iPhone性能の測定値として使わない。画像デコードは合成画像を使用しているため、実写真JPEG／HEICの負荷を代表しない。

写真長辺2048、編集Canvas長辺2048／DPR最大3、Paint Layer幅384（ポーズ別高さ）、履歴25件、PNGキャッシュ最大2件を維持。STANDの履歴25スナップショットは画素だけで約21.1MiBで、これ以外に現在画素・作業Canvas・一時スナップショット等が必要。変更後は読込成功まで旧写真と新写真が一時的に共存する。2048×2048のRGBA Canvasは1枚約16MiB。巨大写真のデコードメモリ自体はこの上限より大きくなり得る。

Canvasプローブは解放を調べるため意図的に参照を保持している。大きいバッファの明示解放を確認したもので、GCの実行やネイティブメモリリークがないことを証明する測定ではない。**iPhone Safariの実RAM・長時間編集・熱・低メモリ時の挙動は未確認**。
