# ちょっとカクレロン

Version **v0.2.0 — CAMOUFLAGE / 擬態ペイント**。iPhone Safariの縦画面を主対象に、写真へ配置した白いカクレロンを背景の色で塗るブラウザゲームです。

## 起動

このフォルダーをGitHub Pagesなどで静的配信し、`index.html` を開きます。ローカルでは任意の静的HTTPサーバーで配信してください。`file://` で直接開く方法はブラウザのCanvasセキュリティ制限を受けるため、ペイント・スポイトの確認にはHTTP配信を使用してください。ビルド、依存ライブラリ、画像処理サーバーは不要です。

## ファイル

- `index.html`：画像選択、モード切替、色見本、履歴・ブラシ操作。
- `style.css`：スマートフォン向けレイアウト、選択状態、Safe Area、ルーペ。
- `app.js`：写真読込・縮小、Canvas合成、スポイト・ルーペ、Pointer Events、既存の配置操作。
- `paint.js`：逆座標変換、マスク、独立したPaint Layer、ストローク単位の履歴。
- `assets/kakureron.svg`：Silhouette MaskおよびWhite Baseの元となる白い人型SVG。
- `assets/menu-icon.svg`：browser-gameメニューのアイコン。
- `tests/app.test.cjs`：描画命令を記録するDOM・Canvas代替による内部テスト。
- `tests/fixtures/photo.svg`：色取得の目視確認用、緑・茶・青の固定画像。

## 操作

1. **画像選択**：「画像を選ぶ」で写真を1枚読み込みます。画像全体を縦横比を保ってFIT表示します。
2. **配置**：カクレロンから1本指／マウスでドラッグ。1本目をカクレロンに置き2本目を添えると、ピンチ・回転・中心移動で調整できます。サイズボタンは画像幅比を2ポイントずつ変更（5〜60%、初期18%）、回転ボタンは5度ずつ変更します。Canvasにフォーカスがある場合は矢印キーでも移動できます。
3. **スポイト**：写真をタップ／なぞります。カクレロンの下も元背景から色を取得し、色見本・HEX値を表示します。操作中は指と反対側の上部に簡易拡大ルーペと中央の印を表示します。写真外の余白では色を変更しません。
4. **ペイント**：カクレロンをなぞると現在色で塗ります。ブラシは小・中・大の3段階です。塗装中にキャラクターは動きません。2本目の指は無視します。
5. **消しゴム**：Paint Layerだけを消し、白い下地を表示します。写真には影響しません。
6. **戻す／やり直す**：ペイント・消しゴムの1ストロークを1操作として扱い、最大25操作を保持します。新しく有効な描画をするとRedoを破棄します。配置変更とスポイトは履歴対象外です。
7. **リセット**：写真を残し、中央・18%・0度へ戻し、塗装とUndo／Redoを消去します。確認ダイアログはありません。モード・現在色・ブラシの選択は維持します。
8. **画像変更**：新画像の読込成功後に配置・塗装・履歴を初期化し、配置モードに戻ります。選択キャンセルや読込失敗では現在の作業を保持します。

モード切替・ブラシ変更・配置補助ボタン・画面リサイズ・入力キャンセル・タブ非表示時は進行中のストロークを確定します。キャラ外を通った後の再入場時は新しい点から再開し、外側を経由した余計な線を結びません。キャラクターの中心は写真内に制限し、写真外の輪郭は表示時にクリップします。

## 描画とメモリー

位置は写真幅・高さに対する正規化座標、サイズは写真幅比、角度はラジアンで保持します。タッチ位置から中心移動分を引き、逆回転と逆スケールを適用してPaint Layerのローカル座標へ変換します。描画済みの塗装もキャラクターと一緒に移動・拡大縮小・回転します。

- **Silhouette Mask**：SVGを384×576の固定Canvasへ描画。アルファでキャラ内を判定します。
- **White Base**：元SVGを白い下地として表示します。
- **Paint Layer**：独立した384×576の透明Canvasに塗装を保持。各描画スタンプを `destination-in` でマスクしてから転写し、キャラ外への漏れを防ぎます。消しゴムは同じマスク付きスタンプを `destination-out` で適用します。
- **履歴**：描画開始前のImageDataを1ストロークにつき1枚保存。25枚で約21MiB、描画中の一時スナップショットは最大1枚です。UndoとRedoで同じ上限内の履歴を移動します。
- **背景**：読込後に長辺2048px以下へ縮小して保持し、表示とスポイトが同じ背景Canvasを参照します。取得色はこの縮小済み背景のピクセル値です。元画像のデコード時はブラウザ側のメモリーが別途必要です。
- **表示**：devicePixelRatioを最大3まで反映。Paint Layerは解像度固定のため、極端な拡大では細部がぼやける場合があります。

## プライバシー

写真は `URL.createObjectURL` と `Image` でメモリー内に読み込み、Object URLは読込後に解放します。画像・色・履歴の外部送信、fetch、解析サービス、アカウント、クラウド保存、LocalStorage、IndexedDBは使用しません。CSPも `connect-src 'none'` で通信を制限しています。写真・塗装・履歴は再読み込みで消えます。

## 検証

```sh
node --check app.js
node --check paint.js
node --test tests/app.test.cjs
```

内部テスト8件成功、0件失敗。既存の画像選択・FIT・ドラッグ・ピンチ・回転・リサイズに加え、元背景へのスポイト要求、モード競合防止、マスク適用の描画命令、消しゴム合成、ストローク単位のUndo／Redo、25操作上限、外からの入場・再入場、リセット・画像変更、移動・回転・拡大縮小の逆変換を確認しています。

Canvas代替では既知の色と合成命令を検証しています。実ブラウザのSVGマスクの描画結果、実ピクセルの境界、写真の色管理、指での操作感は検証していません。ブラウザ連携ホストが利用できず、Windowsアプリ操作も「現在のブラウザURLを十分な確度で判定できない」として停止したため、実ブラウザ検証は未実施です。

## v0.3.0への引き継ぎ

完成画像生成は、画面上の余白を除いて背景を描画し、正規化座標から出力先の変換を計算してWhite BaseとPaint Layerを重ねます。現在は背景長辺2048px、Paint Layer384×576が上限です。高解像度出力を追加する場合は、元画像保持によるメモリー負荷、塗装解像度、SafariでのCanvas上限を別途検討してください。

保存・共有はユーザーの明示操作からBlobを生成し、iPhone SafariのダウンロードやWeb Shareの対応状況を確認する必要があります。現版には完成画像出力・保存・共有・LINE連携・背景コピー筆を実装していません。写真を外部送信しない方針を維持してください。
