# すれ違い郵便局 — SORT & SEND

Version **0.2.0 — PUZZLE FOUNDATION**。分岐の循環パターンを設定し、荷物を同じ色・印の出口へ届ける戦略パズルです。既存0.1.0を拡張し、5ステージ・複数分岐・3色配送に対応しました。

## 開発環境・起動

Node.js 20.19以降または22.12以降の対応版、npm、TypeScript、Vite、Canvas 2D、HTML/CSS、Vitestを使用します。大型フレームワークは使用しません。

```sh
cd sort-and-send
npm ci
npm run dev
```

表示されたURLをブラウザで開きます。

```sh
npm test           # 関連するシミュレーション・構造検証テスト
npm run typecheck  # TypeScript型チェック
npm run build      # 型チェック + Productionビルド
npm run preview    # ビルド結果の確認
```

`sort-and-send/dist/` が静的配信用成果物です。従来どおり成果物も管理対象とし、更新時はソースと一緒に反映してください。browser-gameの公開リンクとURLは変更していません。外部サービスへの接続は不要です。開発サーバー単体では親の一覧を配信しないため、一覧との往復確認はbrowser-game全体を静的配信して行います。

## ステージ

R=RED ●、B=BLUE ▲、Y=YELLOW ◆。初期パターンは全分岐・全枠Lです。

| Stage | 名称 | 配送順序 | 枠数 | 想定解 |
|---|---|---|---|---|
| 01 | はじめての分岐 | R B R | A:2 | A=LR |
| 02 | 同じ色が続く | R R B R R B | A:3 | A=LLR |
| 03 | くり返す道 | R B B R B B R B B | A:3 | A=LRR |
| 04 | 4つの荷物 | R B B R R B B R | A:4 | A=LRRL |
| 05 | 小さな郵便局 | R B Y R B Y | A:3、B:2 | A=LRR、B=LR |

Stage 01〜04はSource → A、A左 → RED出口、A右 → BLUE出口です。Stage 05はSource → A、A左 → RED出口、A右 → B、B左 → BLUE出口、B右 → YELLOW出口です。描画座標は各ノードの`layout`から読み取ります。

## 操作

1. 上部の01〜05ボタンでステージを選びます。配送状態と全分岐の設定は初期値へ戻ります。進行状況は保存しません。
2. HTMLの「分岐 A」「分岐 B」ボタンから編集する分岐を選びます。各ボタンに現在のパターンを併記し、盤面でも選択中の分岐を強調します。
3. 矢印カードをクリック／タップしてL（左）とR（右）を切り替えます。TabとEnter／Spaceでも操作できます。
4. 「配送開始」で実行します。RUN中は矢印編集、ステージ変更、再挑戦、初期化をロックします。分岐の選択は閲覧用に切り替えられます。
5. 結果で正しく届いた個数と、すべての荷物の配送先を確認します。「再挑戦」で全分岐の設定を保持してDESIGNへ戻り、再度「配送開始」を押します。結果画面でカードを編集してもDESIGNへ戻ります。
6. 「初期設定に戻す」で現在ステージのすべての分岐をLへ戻します。
7. クリア後の「次のステージ」で次へ進めます。Stage 05では表示しません。

## 配送ルールと構造

`src/stage.ts`が有向グラフ、荷物ID・色・配送順序、初期パターン、描画用layoutを定義します。`src/simulation.ts`はCanvas／DOMに依存せず、`simulate(stage, patterns)`が経路とイベント履歴を返します。描画座標・画面サイズは配送結果に影響しません。

- 荷物IDの昇順で、0始まりのtickに1個ずつ出発します。
- 各荷物はtick開始時の位置から最大1エッジだけ移動します。出発tickも最初の1エッジのみです。
- 各分岐から送り出す際に現在の矢印を参照し、その分岐のカウンターだけを1つ進めます。最後の枠の次は先頭です。
- 同一tickに同じ分岐から複数荷物を送り出す場合も荷物ID昇順です。
- 各実行で全分岐カウンターを0から開始します。設定・ステージ入力は変更しません。同じ入力から同じ結果・イベント履歴を生成します。
- 出口到着後は移動しません。誤配送があっても残りを継続し、全荷物の到着で終了します。
- 返り値には荷物ごとの経路・配送先・正誤、出発／移動／到着イベント、tick数と集計を含みます。分岐通過履歴はmoveイベントのfrom、direction、patternIndexから取得できます。
- Canvasはシミュレーション済みイベントを時間補間して再生し、フレームレートで配送を判定しません。

`src/validation.ts`で、ノード／荷物ID重複、接続元・接続先、Source数、出口、分岐L/R接続、1〜4枠パターン、配送先、循環、出口に到達できない経路を検証します。すべての枝を構造的に確認し、解法の組み合わせ探索は行いません。不正なステージは開始ボタンを無効にし、レポートへエラーを表示します。シミュレーション入口でも再検証します。
