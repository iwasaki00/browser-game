# 0.5.0-A — RESCUE：Chrome手動受入確認

作成日：2026-10-22。**以下は手動確認手順と期待結果です。GUIで確認済みの結果ではありません。**

自動操作ツールは起動時に終了しました。診断はWindowsの`CreateProcessWithLogonW failed: 2`です。今回は復旧作業を追跡せず、既存実装を維持しています。ソースコード・ステージ定義・Solver・検証レポートは変更していません。既存91件のテスト・型チェック・ビルドは前回成功した結果で、今回再実行していません。

## 1. ローカル起動と記録の分離

`032_すれ違い郵便局`フォルダでターミナルを開いて実行します。

```powershell
cd sort-and-send
npm run dev -- --host 127.0.0.1 --port 8035 --strictPort
```

通常のChromeで次を開きます。

- 順次解放・最高星の確認：`http://127.0.0.1:8035/`
- 任意のステージへのアクセス：`http://127.0.0.1:8035/?testMode=1`

Stage 01は最初から開けるため、今回の一連の確認には**クエリなしのURL**を使います。開発用の全解放モードでは最初からStage 02も開けるので、星1による解放確認には使いません。

通常の開発モードは`sort-and-send.dev.progress.v1`を使います。公開サイトや別ポートの保存とは別のオリジンで、本番キーを変更しません。全解放モードはページ内メモリだけを使い、再読み込みすると消えます。

8035が使用中なら8036などの未使用ポートへ変更し、URLも同じ番号へ変更します。同じホスト・ポートの通常モードで最後まで確認してください。既にこのオリジンに記録がある場合、解放確認は別の未使用ポートで行えば記録を消す必要がありません。

Production成果物を確認する場合は別ターミナルで次を実行します（再ビルド不要）。

```powershell
cd sort-and-send
npm run preview -- --host 127.0.0.1 --port 8036 --strictPort
```

`http://127.0.0.1:8036/`を開きます。Productionで`?testMode=1`を付けても全ステージ解放は有効になりません。開発版とは保存キーが異なるため、開発版の星記録は引き継ぎません。

## 2. 操作の基準

- Stage 01：荷物は01 RED ●、02 BLUE ▲、03 RED ●。分岐Aの左はRED EXIT、右はBLUE EXIT。
- パターンの表記はSTEP 01、STEP 02の順。`LR`なら1枚目L、2枚目R。
- 1tickは0.7秒です。RESCUEは押した時点の移動が終わる境界で停止します。最大約0.7秒待ってください。
- 「配送開始」の直後にRESCUEを押すと、通常は荷物01 RED／分岐A／tick 1／枠1を対象にします。対象が違う場合は操作が遅れた可能性があるため、その回を終えて再挑戦します。
- プレビューが開いたら時間制限はありません。**対象表示を確認してから**方向を選びます。
- RUN中は下へ少しスクロールした位置にRESCUEボタンがあります。PCでは「配送開始」とRESCUEが見える位置を先に調整しておくと操作しやすくなります。

## 3. 順番に行う確認

最初はStage 01のみ解放、最高星なしの状態を使います。下記の順番なら星1解放と最高星維持を同じ記録で確認できます。

### A：停止・表示・キャンセル（パターンLL）

1. Stage 01を開き、Aを`LL`にします（初期設定）。Stage 02がロックされていることを確認します。
2. 配送開始直後にRESCUEを押します。
3. モードがPAUSEDとなり、荷物番号・色・分岐・tick・通常方向・枠とL/R選択が表示されることを確認します。
4. 3秒ほど待ち、荷物が動かず、tickと対象表示が変わらないことを確認します。背面の分岐編集・ステージ変更・再挑戦を操作できないことも確認します。
5. 「キャンセルして再開」を押します。RUNへ戻り、RESCUEが使用済みになっていないことを確認します。可能なら同じRUNでもう一度開いてキャンセルし、未消費を確認します。
6. 配送終了を待ちます。

期待結果：FAILED、2/3、星0、3個ともRED EXIT。AはLLのまま。結果は「RESCUE：未使用」。Stage 02はロックのままです。

### B：星1CLEARで次ステージ解放（パターンLR・通常方向を確定）

1. 「再挑戦」を押し、AがLLのままであることを確認します。2枚目を押して`LR`にします。
2. 配送開始直後にRESCUEを押します。
3. **対象が荷物01 RED／A／tick 1／枠1／通常L**であることを確認します。
4. Lのまま「確定して再開」を押します。同じ方向でも使用権を消費する仕様です。
5. RUNに戻るとRESCUEが使用済みで操作できず、カードの設定がLRのままであることを確認します。
6. 結果とStage 02を確認し、荷物01の配送履歴を開きます。

期待結果：CLEAR、3/3、星1（★☆☆）。最高星1を表示し、Stage 02が選択可能になります。履歴は荷物01がAで「RESCUE／通常L→実際L」、他の2個にRESCUE表示はありません。各配送先はRED、BLUE、REDです。

### C：通常の星3を取得（パターンLR・RESCUEなし）

1. Stage 01で「再挑戦」を押します。LRが維持されていることを確認します。
2. RESCUEを押さずに配送します。

期待結果：CLEAR、3/3、星3（★★★）、RESCUE未使用。最高星3へ更新します。

### D：星1でも最高星3を維持（パターンLR）

Bと同じ操作を繰り返します。

期待結果：今回の評価は星1、ステージ番号下の最高記録は星3のまま。再挑戦したRUNではRESCUEが再び使えます。

### E：異なる方向への上書き・FAILED・星0（パターンLR）

1. 再挑戦し、Aを`LR`のまま配送します。
2. 配送開始直後にRESCUEを押します。
3. **対象が荷物01 RED／A／tick 1／枠1／通常L**であることを確認します。
4. Rを選び「確定して再開」を押します。
5. 使用済みで再使用できないことと、AがLRのままであることを確認します。
6. 結果の荷物01と02の配送履歴をそれぞれ開きます。

期待結果：FAILED、2/3、星0。荷物01だけBLUE EXITへ誤配送します。荷物02は通常どおりBLUE、荷物03は通常どおりREDです。荷物01のAで「RESCUE／通常L→実際R」と表示し、該当経路を金色で強調します。荷物02のAは通常Rで、RESCUE表示はありません。過去の最高星3は保持します。

### F：別ステージへ予約を持ち越さない

Eの終了後、Stage 02を開いてStage 01へ戻ります。設定が初期LLへ戻り、開始後はRESCUEを新しく使えることを確認します。以前の上書き履歴が新しい結果に混ざらないことを確認します。

### 任意：異なる方向への上書きで星1CLEAR（パターンLL）

1. Stage 01をLLにし、配送を開始します。
2. PC画面で表示が`TICK 2 / 4`になった直後にRESCUEを押します。
3. **荷物02 BLUE／A／tick 2／枠2／通常L**が対象になった場合に限りRを確定します。

期待結果：3個の方向がL、R、Lとなり、CLEAR 3/3・星1。荷物02だけ通常L→実際R、パターンはLLのままです。別の荷物が対象になった場合、この期待結果にはならないので、その回を終えて再挑戦します。狭い時間幅での操作が必要なため、必須項目の確認はBとEを優先します。

## 4. 375px幅の確認

ChromeでF12またはCtrl+Shift+Iを押し、デバイスツールバーをCtrl+Shift+Mで表示します。Responsiveを選び、幅375・高さ812に設定します。DevTools側の表示倍率は縮小しても構いませんが、ページ自体のズームは100%にします。

1. PC幅の確認後、同じタブ・同じオリジンでBとEを再実施します（Star 02の初回解放はPC確認済みなら繰り返す必要はありません）。
2. プレビュー内の長い対象文が折り返され、横スクロールがないことを確認します。
3. L/R選択、確定、キャンセルの全ボタンが見えるか、縦スクロールで到達して押せることを確認します。画面外で固定されて押せない場合は不合格です。
4. 3秒待って停止状態を確認し、キャンセル・再開と確定・再開を確認します。
5. 結果と荷物別履歴の上書き方向を確認します。
6. 確認後はデバイスツールバーを閉じ、通常のChrome表示に戻します。
