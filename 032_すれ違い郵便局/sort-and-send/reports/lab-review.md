# 0.5.0-C — LAB：実装・受入確認記録

確認日：2026-10-23。対象は研究室の追加と既存画面への統合です。ステージ定義、配送エンジン、Solver、コスト、採点、固定識別子、ヒント本文、既存検証レポートは変更していません。

## 解放・収集・再挑戦

全20ステージの保存済み最高星が1以上で解放します。RESCUEの星1を含みます。進行更新後に解放を判定するため、最後の未達面を通常CLEARしたRUNも登録対象です。過去の星から発見設定を生成しません。

RESCUEなしの通常CLEARだけを収集し、新規・重複・ロック中・RESCUE使用・FAILED・上限・不正設定・保存失敗・未知スキーマを区別します。分岐IDを一定順序に正規化し、未使用分岐も含む全分岐・全枠を比較します。キーは`JSON.stringify([stageId, stageFingerprint, sortedBranchTuples])`です。

研究室の再挑戦は保存データを再取得・再検証し、DESIGNに設定を適用します。RUN・カウンター・RESCUE・ヒントを初期状態に戻し、自動配送・自動収集は行いません。RUN／PAUSEDや別ダイアログ表示中は研究室を開けません。

## 保存契約

Productionキーは`sort-and-send.lab.v1`。既存の`sort-and-send.progress.v1`とは独立しています。通常DEVも専用キーを使用します。

```json
{ "schemaVersion": 1, "discoveries": [] }
```

各発見は`stageId`、`stageFingerprint`、`configuration`、`discoveryKey`、`cost`を持ちます。読み込み時に分岐集合、枠数、L/R、現在の識別子、再計算したキーとコスト、通常シミュレーションでの成功を照合します。表示には検証済みの発見だけを使用します。

- 識別子が古い記録は原文を保持し、現在の件数・再挑戦から除外します。
- schema 1配列中の不正記録は有効記録と分離し、通常追記でも破棄しません。既存の余分なルート項目も保持します。
- 未知schema・不正JSON・壊れたルート・読取不能時は書き込みと初期化を止めます。
- 書き込み直前にも保存文字列を比較し、読み取り後に変更されたスナップショットを上書きしません。複数キーの更新は原子的トランザクションではありません。
- 容量超過などの保存失敗は通知し、通常CLEAR・星更新の判定を取り消しません。
- 進行初期化のキャンセルは無変更。確定は研究室の削除成功後に進行を初期化し、音声・演出設定を保持します。研究室を安全に削除できなければ進行も変更しません。その後の進行保存だけが失敗した場合は「進行はページ内だけの初期化」と通知します。

成功総数は既存の検証済み集計を使用し、クライアントへ未発見の解答一覧は読み込みません。上限は各面`min(100, total)`です。現行は各1〜8件、全20面74件。総数と上限は別管理し、将来総数128件・上限100件の場合も100件で全発見にはしません。

## 実際のChrome操作

Windowsの通常ChromeでローカルVite previewと開発サーバーを開きました。解放後の操作は`?testMode=1&labTest=1`の一時メモリ内フィクスチャを使用しています。これは星1×20件だけを作り、発見は0件から開始します。実際の進行保存には触れません。

### 375px幅

Chrome viewportを375×812に設定し、一覧・詳細・再挑戦・長い一覧の閉じるボタンを操作しました。横はみ出しはありませんでした。測定値は`innerWidth=375`、文書`scrollWidth=360`（スクロールバーを除く）、ダイアログ`clientWidth=scrollWidth=326`、再挑戦ボタン252×44 CSS pxです。ダイアログ内をスクロールして閉じるボタンへ到達できます。終了時にviewport設定を解除しました。

## 手動での追試

アプリディレクトリで、通常版は以下を実行して表示されたURLを開きます。

```sh
npm run build
npm run preview -- --host 127.0.0.1 --port 8038 --strictPort
```

解放後の操作だけを確認したい場合は別ターミナルで以下を実行します。

```sh
npm run dev -- --host 127.0.0.1 --port 8039 --strictPort
```

1. `http://127.0.0.1:8039/?testMode=1&labTest=1`を開き、研究室が解放済み・発見0件であることを確認します。
2. Stage 01でAの2枠をL・Rにして通常配送します。CLEAR後の新規登録と研究室の1/1件を確認します。
3. 研究室のStage 01を開き、コスト2・A LRから再挑戦します。DESIGNで設定が適用され、自動配送されないことを確認します。
4. そのまま通常CLEARして重複扱いを確認します。
5. 再挑戦してRUN中にRESCUEを開き、最初のREDの通常LをLのまま確定します。星1CLEARでも登録対象外になることを確認します。
6. 375px幅でも一覧・詳細・再挑戦・閉じるを確認します。
7. 設定で進行初期化の確認文を読み、キャンセルで無変更、確定で0/20へ戻ることと音声・演出設定の保持を確認します。
8. `http://127.0.0.1:8038/?testMode=1&labTest=1`では開発用の全星付与が有効にならないことを確認します。

DEVフィクスチャはメモリだけのため、ページ再読み込みで星1×20・発見0件に戻ります。永続化の再読み込み・異常保存の保護は単体テストで確認しており、このGUIフィクスチャでは永続保存を確認した扱いにしていません。
